## 最新偏好：重定视觉表现，道路可以沿用

用户明确反馈：“现在地图看着太奇怪了，不一定要是深色配浅色这种，道路倒是可以沿用。”因此优先保留当前道路走向和地区连接，重新设计场景的画风、材质、配色、自然过渡、景观和空间层次。不要把重铺道路或整张地图改坐标当成默认答案。

当前“较深绿地面 + 大片浅黄道路”的强分区，以及平整单色底、色带式路面、少量贴上去的树/房子，都不是既定风格。地面不必深、道路不必浅，也不要求两者靠强烈明度反差区分。

现有20色地表、严格色阶、极低细节密度和硬边过渡只是上一版尝试，不是必须继续遵守的规范。允许更细腻的手绘像素/绘画式纹理、更多自然色层和有控制的过渡；以实际同屏清晰度、质感与主角兼容性判断，不用色数少来代替美术质量。

道路可以靠材质差异、踩踏磨损、草缘、落叶、碎石、接触影、林缘与地标引导来识别。避免把整张地图做成两种颜色的交通示意图，也避免为了“低对比”把环境做成空白平面。

## 开放重做的范围

当前地图和六组美术样板只是候选，不是必须继承的方案。可以重做场景构图、建筑群、景观、地面绘法与NPC/交互物的视觉关系。道路优先沿用；若空间确有问题，可提出局部调整或重规划，并说明为何单靠美术无法解决。

旧资料里的“道路、碰撞、坐标不动”是上一轮实施边界，已被本次授权取代。现有尺寸、逻辑格、相机倍率、道路宽度、平铺方案和色数上限是现状或上一版建议，不是新的设计必须遵守的硬指标。

目标是成熟商业RPG的场景体验：空间有结构、地点有身份、探索有节奏、人物与场景同屏统一。不要把空旷草地加一条路、道路两旁摆几栋房、均匀撒草或贴一些树当作重做完成。

## 可以改什么

- 城镇整体结构：可以改成长街、紧凑广场、门楼街区、多片相连小空间或其他更合适的结构，不拘泥当前南北直路和左右两列建筑。
- 野外结构：可以重新组织主路、岔路、回环、开阔区、林缘、景点和过渡，改变道路视觉宽度、疏密与探索节奏，不拘泥当前曲线形状。
- 建筑、NPC、道具与交互点的位置可以重排。碰撞、遮挡、相机、出生位置和旧存档位置适配应随最终方案由Codex实施；这些是交付任务，不是禁止重做的理由。
- 地图视觉表现与资产组织可以重定：瓦片、手绘整图加散件、分层场景或混合方式都可比较。不要为了复用当前素材而保留差的观感。
- “晴野行旅”可以保留、深化或由更合适的地图美术方案替代，但必须解释怎样与现有主角、NPC及“灯下行箧”UI形成一个游戏。不要把UI材质机械涂到全地图。

## 必须保留什么

- 游戏世界观、主角辨识度、NPC身份与既有功能；默认不重做主角。
- 功能合同中的城务入口、任务事件、关键交互物，以及它们的可达性。
- 地图间连接的目标地区、开放条件、任务依赖和建造进度语义；可移动出口在画面中的位置，但不能悄悄改变通关门槛或删除连接。
- 竖屏触控下的可读性与通行体验。NPC、路牌、任务目标不能为了构图而不可见、不可点或走不到。
- 不新增成长、战斗、货币、奖励或传送机制。需要机制变化的提案单列为可选，默认不实施。

现有工地不是成品楼体透明故障。可以重设计未落成的表现，例如封门、修缮区、材料堆和脚手架变体，不必继续使用当前裸露矩形地基；保留真实建造状态和入口条件。

先用一张短表比较最多3条可行路线，优先比较“沿用道路、彻底重做视觉表现”和“沿用主要道路、调整局部空间与景观”。只有结构本身确实阻碍质量时才加入“重做空间布局”。比较成熟观感提升、自然程度、竖屏可读性、资产需求和工程代价。然后你自己选一个最值得实施的方案，不把选择再丢给用户，不写三套完整方案。
