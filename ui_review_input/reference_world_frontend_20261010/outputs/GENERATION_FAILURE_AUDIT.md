# 本轮生图偏离参考的诊断

本轮结论：两批生成候选均不作为可接入素材。停止继续生成和接入；先修正方向与验证流程。本文件只记录诊断，不代表新方案已获用户验收。

## 目标与实际差异

用户提供的是二维俯视 RPG 地图参考：物体有手绘体积，但相机角度、人物与树木的尺度、像素色块组织在同一套地图语言里。它并不要求把树木画成平面剪纸，也不要求退回低色数或粗糙像素。

第二轮建筑图仍有过密的瓦片、木材和金属明暗，像摆放在台面上的立体模型。加载页仍有地平线、天空、远山和向远处收束的道路；标题页突出正面门楼、透视街道和逐块描绘的石材。登记页仍是厚重箱体、金属角件和光照渐变的静物构图。虽然可见像素边缘，画面语言仍未统一到用户参考。

这是视觉判断，不能据此断言图像生成器内部实际使用了 3D 建模。问题是成图呈现的立体预渲染感与目标不符。

## 已确认的原因

1. **我直接写入了错误的正向要求。** 第一批 civic 提示词包含原文 `clearly3Dsceneworksite notgreyUIrectangle`。本意是要求施工区作为地图物件而非灰色 UI 块，但实际指令明确要求了 3D 场景。这是我编写提示词的错误。
2. **多种绘画语言互相冲突。** 我同时写了俯视像素地图、high oblique、道路向门洞汇聚、volumetric、复杂材质和柔和光照。设计文件中的前端插画、透视与材质描述需要按用户参考重新解释，我没有完成这一步，反而强化了深透视和材料细节。
3. **参考约束不一致。** 第一批登记背景没有附用户参考，只靠文字描述“pixel art”。第二批又将失败图作为第一张输入，并要求“Keep layout/content unchanged”，保留了不合适的投影和构图。增加“no 3D”等否定词没有消除这些冲突。
4. **缺少先验收一张样板的环节。** 首轮一次生成七组内容；用户指出问题后，我又直接生成四组修正。没有先用一张地图视口验证风格，就把错误方向扩散到了多个资产。
5. **把输出缩放当成了潜在补救。** 逻辑尺寸与最近邻缩小只能调整显示密度，不能把写实材质、深透视或连续明暗变成参考图的像素绘画。应先验收原图风格，再处理尺寸、切图和导入。

上述原因中，提示词冲突、参考输入和批量验证次序有实际调用记录支持；各词如何影响生成模型是结合成图作出的推断。

## 纠正要求

- 地图样板只用用户原始森林图作为风格依据，不沿用失败图。
- 一次先验证一个可游玩的地图视口，角色、树、地面和道路在同一画面里检验尺度与相机角度。
- 正向描述锁定：二维俯视地图、与参考一致的树冠色块、统一像素密度、自然草地层次、安静的道路纹理、短的地面投影。不堆叠写实木纹、金属反光、深透视和电影光照要求。
- 先判断构图、视角、体积表达和像素组织；仅出现锯齿或像素颗粒不算通过。
- 地图样板通过后，再派生建筑与植被，并将加载、标题、登记三页转译为相同绘画语言。三页重做范围仍有效。
- 不用后期像素化或颜色量化掩盖风格偏差；样板未通过前，不批量生成或接入。
