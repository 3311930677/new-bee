# 地图接入评估与交付规格修订

> 最新修订：城镇出口为一个独立路牌，不制作门楼。地图范围按内容与留白计算，当前约1200×2112为工作草案；主路约136宽、支路较窄。城镇布局及旧门楼描述以 [TOWN_NEIGHBORHOOD_PLAN.md](TOWN_NEIGHBORHOOD_PLAN.md) 和最新 IMAGE_PROMPTS_ALL.md 为准。访客簿作为独立点位保留原功能ID。

> 城镇最新构图与生产范围由 [TOWN_NEIGHBORHOOD_PLAN.md](TOWN_NEIGHBORHOOD_PLAN.md) 覆盖：左右建筑、连续草坪主路、北门出城，1104×1920为待定样板范围。原960宽与广场绕行表不作为当前制作坐标；正式数据尚未改动。野外方案保持原范围。地表、建筑、树与NPC分开制作，生成前先核对当前预检记录。

本修订优先于旧方案中相机固定为 1.0、地图单倍交付与全屏图可直接铺满世界的解释。结论来自代码与文件实测、Godot 官方文档及隔离二维渲染测试。没有将候选图接入正式游戏，没有更改现有地图数据、角色、存档或游戏场景。

## 1. 能否直接接入

可以作为一张静态纹理显示，但不符合可游玩地图的交付要求。两张原图均为 841×1870，属于未校准的效果底稿。它们没有精确世界坐标、可走遮罩、独立树冠、建筑遮挡层、脚点、动态桥或拒马状态，不能直接替代已有地图。

正式场景保留纯 2D：Node2D、Sprite2D、Camera2D、CharacterBody2D 和独立碰撞。树与建筑的手绘体积允许存在；不会因此需要 3D 模型、三维相机或真实透视投影。

A1 可以作二维俯视风格候选。A10 的建筑、桌子和工地表现为较强的斜向投影，地面纹理比角色细；可保留物件设计，但须向现有角色的下正面、上方能见屋顶的投影统一。单一静态图中的透视不能靠引擎调整相机角度修正。

## 2. 实测与缩放链条

项目视口基准为 480×800，canvas_items + keep_width；长屏验证采用 480×1067。世界坐标目前按 48 单位逻辑格记录。项目默认最近邻过滤。Camera2D.zoom 大于 1 会放大画面，世界可见宽度等于视口宽度除以 zoom。

| 相机倍率 | 480×800 的世界可见范围 | 480×1067 的世界可见范围 | 71.5 世界单位高主角的屏幕高度 |
|---|---|---|---|
| 1.0 | 480×800 | 480×1067 | 71.5 |
| 1.15 | 417.4×695.7 | 417.4×927.8 | 82.2 |
| 1.25 | 384×640 | 384×853.6 | 89.4 |

用户指出 1.15→1.0 使固定大小物件缩小约 13%是正确的；可见世界面积同时增加约 32.25%。这不代表增加了素材细节。

主角也改了比例，因此角色须单独计算。原图有效可见高度为 110 源像素（128×128 首帧 alpha 边界 y11–121）。旧城镇为 110×0.66×1.15=83.5 屏幕单位，旧野外为 110×0.54×1.15=68.3；当前两图是 110×0.65×1.0=71.5。也就是说当前主角在城镇缩小约 14.4%，在野外反而长高约 4.7%。

完整链条：

源像素 → 图片在世界里的显示比例 → Camera2D.zoom → 设备窗口相对逻辑视口的比例。

2 倍交付文件不是让物件变大；它应以 0.5 的基础映射回原来的逻辑尺寸。相机是另一个独立倍率。默认最近邻不保证分数缩放没有像素宽度不均或运动闪烁。

## 3. 样板不是全图

测试对比将同一张候选分别映射为 960 宽整图和 480×1067 的局部样板。前一种在同屏里约将物件加大一倍，道路占屏过多，大树和地标容易被裁掉。后一种更接近现有主角与环境的比例，但还需正式拆层与比例校准。

因此 A1–A12 定义为局部景观候选，A13/A14 才是全图布局概念。不能把 A1 拉成整张 960×2112 的枫林古道，也不能把 A10 拉成整张城镇。A1 当前包含桥的剪影只为构图，不自动改变真实桥坐标。

城镇地图 960×1920 为 1:2，候选图约为 9:20；直接强行拉伸会造成宽高方向不一致的约 11%形变。枫林尺寸与候选宽高比近似，但仍不能因此忽略对象尺度、位置和 gameplay 的差别。

暂保留世界范围：城镇 960×1920，野外 960×2112。这些控制探索长度与路线，不应用来代替物件大小调整。世界范围也不需要与前端画幅相同。

## 4. 统一交付规则（明确倍率和生成请求）

采用“2 倍工作母版 + 明确逻辑范围 + 经整理的游戏输出”，而不是所有文件直接按源像素当世界坐标。母版倍率与像素色块密度分别验收；高分辨率照片式细节缩小后仍不算像素风。

| 内容 | 逻辑尺寸或世界范围 | 请求/制作母版 | 游戏输出与对应关系 |
|---|---|---|---|
| A 局部景观候选 | 480×1067 校准框 | 请求 960×2134；若只支持相邻规格，保留多余边缘后登记裁切 | 只做构图参考，不直接上线 |
| 加载/标题/登记 | 480×1067 | 960×2134 | 2 倍纹理按逻辑尺寸显示；480×800 中央安全裁切另验收 |
| 城镇全地表 | 960×1920 世界范围 | 拼合工作母版 1920×3840 | 整理为 960×1920，再切 8 块 480×480 |
| 野外全地表 | 960×2112 世界范围 | 拼合工作母版 1920×4224 | 整理为 960×2112，再切 8 块 480×528 |
| 城镇地表制作块 | 核心 480×480，四边各 32 世界单位延展 | 1088×1088（含延展） | 校准、拼合、修缝后再切核心 |
| 野外地表制作块 | 核心 480×528，四边各 32 世界单位延展 | 1088×1184（含延展） | 校准、拼合、修缝后再切核心 |
| 独立物件 | 审定的世界宽高 W×H | 单件 2W×2H，另留品红空边 | 去底、统一像素后 W×H；锚点用世界坐标记录 |

这里的“请求尺寸”不等于工具保证输出尺寸。内置工具没有显式 size/seed 参数；每次必须读取实际宽高。规格不符标为原始候选；不允许默默拉伸到目标值再称合格。像素风不能用任意比例缩放补足尺寸，须按实际有效像素网格重新整理。

全图超过单次能力时不请求超长整图：按上述制作块生成/描改，每块附同一通过的样板、邻块与从布局表导出的道路指导图。64 世界单位的相邻重叠带用于对齐与修缝；随机独立生图不保证接缝。先在完整母版上修好道路连贯、颜色和岸线，再切核心块。运行纹理的邻块采样边缘需要额外保护，不能把生成重叠带误当运行坐标。

若不采用母版工作流，也可直接按 1 倍整理输出；核心要求是明确“一个源像素对应多少世界单位”，无需为统一而机械地多占四倍显存。2 倍母版不默认全部装入手机运行内存。

## 5. 相机与对象尺寸的修订选择

取消“固定 1.0 取代 1.15”的定案。样板校准先以 1.15 作为候选基准，与 1.0/1.25 同屏比较；本轮未修改游戏当前的 1.0。主角暂用实际 71.5 世界单位作尺，基准 1.15 时约显示 82.2 屏幕单位；72 指世界高度，不再误写成各倍率下不变的屏幕高度。

建议基础对象尺寸（待实际同屏确认）：成年人世界高度约 72，普通大树约 166–202，门洞高度约 88，主路约 120–160 世界单位。参考图是局部视口，不能把一条占局部 30%宽的路机械扩成整个 960 世界宽度的 30%。

1.15 兼顾当前观感与可见范围；1.25 更近，但交互地标、树冠和 HUD 边缘容易拥挤。若最终优先严格的整数像素显示，可用 1.0 并重新整理物件世界尺寸；这属于另一个完整比例方案，不是把相机改小就能自动变精致。未经同屏验收不全量迁移坐标。

## 6. 直接铺图会遇到的问题

- 树冠与人物：一张底图中的树只能在角色下方；玩家走到树后仍盖在树上。拆出树冠与树干，按落地点排序，遮住主角时按既定规则减透明。
- 建筑与门：屋顶不能等同建筑碰撞全图轮廓；需地面占地、门口触发区、可遮挡前景。角色在门口的大小和位置必须实测。
- 桥/拒马：开关状态不能烘焙进不可变地表；桥面保持当前通行语义，阻挡条件沿用实际配置，不根据画出来的缺口改变玩法。
- 烘焙阴影：地表不能再带散件的完整影子，否则拆层后产生双影、物件移动后的残影。静态地表保留地表光色，独立物件接触影按统一方法处理。
- 可达性：花草的视觉密度不等于碰撞；草与路可通行范围须有遮罩，桥两端、出生、出口和 NPC 必须连通。
- 地标越界：候选图中被裁掉的议事厅屋顶不构成完整建筑资产。画幅边缘可以有框景，但不能把游戏唯一入口裁掉。
- 纯 2D 角度：统一屋顶可见比例、垂直边、横向轴和脚点；不同物件不能各自采用不同斜向角度。不能靠旋转整张纹理模拟一致投影。
- 动态像素表现：最近邻 + 分数相机倍率可能产生不等宽像素；需在运动中检查，不仅验收静态截图。
