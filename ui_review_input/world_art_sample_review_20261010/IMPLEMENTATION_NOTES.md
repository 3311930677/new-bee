## 制作与导入

源美术使用内置ImageGen，保留全部原件；工程副本在 `assets/world/sunny_travel_20261010/source/`。初稿和修正版分开保存。地表疏密、树冠留白和建筑比例做过一次针对性修正。

`generation_manifest.json`、`revision_prompts.json`、`hall_revision_prompt.json`记录实际提示词与原文件。按工具要求输出真实透明背景，代替规范中的品红底，避免额外抠底污染。

`tools/ImportSunnyTravelArt.tscn`使用Godot原生最近邻导入、共享调色板、二值alpha及帧注册。为排除生成式四帧之间的面部/衣料抖动，用规范关键帧构造受控的胸头或布料局部动效，不把整张人物上下平移。下半身和守卫矛杆保持一致。

`tools/BuildSunnyAssetMetadata.py`只分析透明组件边界，供原生导入定位完整对象；没有用Python编辑图片。`tools/BakeSunnyGround.tscn`将实际路线生成的地面保存为工程资源，避免首次进地图时现场制作大纹理。路线签名和范围不匹配时不使用旧烘焙结果。

重新制作时依次执行：透明区域分析 → 原生导入 → Godot资源导入 → 地表烘焙 → Godot资源导入 → 样板捕获。原素材与Cloud定稿不覆盖。

## 验证与边界

- 本轮原生窗口检查：`SUNNY_SAMPLE_OK checks=227 failures=0`。涵盖NPC脚底/下半身/局部动效、基础瓦片边缘、静态碰撞对照、地图配置、主角缩放、中心线、模拟按键移动、执事自动交谈和真实点击离开对话。
- 17个导入资产通过色数与二值alpha检查；执事/守卫各48色，地表族20色，建筑40色；两张正式地面不超过20色。色数检查针对源像素，不把叠加UI、文字与阴影后的截图色数当作调色板色数。
- 12组受影响回归的最终日志通过：资源、城务、地图、主世界、世界会话、主线、任务、返回、性能、霜关美术、港务成长与路牌。旧主世界测试原本要求旧TextureRect整图，已改为检查实际地表覆盖完整范围、并处于实体下层；战斗、存档、出口和进度检查保留。
- 性能回归未放宽阈值，本机加载预热约4秒，主要页面仍在原预算内。这不是Android性能验收。
- Windows引擎退出仍有资源/RID诊断，按已有issue #43规则单列；没有声称零告警。
