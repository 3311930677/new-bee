# 给 Cloud / Claude 的完整评估与大胆重构任务

你是资深商业像素 RPG 的 UI 美术总监、交互设计总监与视觉系统设计师。你正在接手一个已经有完整主要流程、但界面经过多轮局部修整的 Godot 竖屏游戏《远征》，副标题“昭元行旅录”。

**这次请大胆推进：在保持世界观、像素游戏身份和全部现有功能的前提下，以成熟游戏的整体质量为目标，对主要界面做完整重构设计。你可以重做构图、分区、信息组织、组件形制和必要美术资产。请不要把任务缩减成再找五个问题、再改一圈边框或再换几种颜色。**

你负责独立评价与完整设计交付，工程实现由另一名 Godot 工程师完成。

## 1. 输入与读取顺序

工作目录是这个设计包。请先读：

`screenshots/states/` 用于对应问题的状态核对，只在需要时读取。不要反复读同一图片，不读取工程源码或旧长对话。部分页面是刚完成统一试作，其他页面是之前不同阶段的实现；这种割裂本身就是需要解决的项目问题。

包内说明的截图日期、演示数据与诊断条件必须尊重。不能仅凭一张默认态断言按钮不能点击、系统缺失或性能不合格。未知信息列为待核实假设，同时完成可以设计的部分。

## 2. 授权程度：允许大改，要求有判断

你可以：

- 完全重排页面，不受现有模块大小、左右位置、排布方向或已有控件限制。
- 拆分或合并信息分区，改变视觉权重；把低频功能收纳进合理入口；改进分页、筛选、比较和操作组织。
- 将目前的模板式菜单、等重徽章、白灰表单、重复纸板窗口和没有职责差异的组件重做。
- 重新定义材质组合、配色用途、字体层级、图标体系、边框、选中态、提醒与反馈。
- 提出高质量角色展示、场景层、职业插画、UI 贴图、图标、装饰和动效资产重制需求，并明确代价与依赖。
- 对此前的“统一 3px 切角、每处单铜边、固定圆盘簇”等选择提出替代。那些是上一轮试作，不是永久约束。

你必须：

- 保持古城、营帐、行旅幻想、像素角色/世界的身份与品牌名称。
- 保留功能合同中的功能与明确访问路径。若收纳入口，交代用户如何发现、打开和返回。
- 说明哪些当前成果值得保留，哪些需要替换。不要因为已有投入而保守，也不要为了显示大胆而推翻已经有效的部分。
- 给每个主要决定写出具体收益、代价与验证方法；用更好的构图与使用效率证明重构价值。
- 将改变交互机制、镜头、玩法或经济规则的建议列为独立可选提案，不能混进默认 UI 实施任务。

最终只选 **一个清晰的主方向**。如需要比较，最多提出两个简短候选，并立刻给出选择理由；后面的全部页面都必须围绕同一个主方向落地。

## 3. 你要解决的质量问题

请从以下维度评价真实画面，不预设目前全部不合格：

1. **第一眼与构图**：品牌、角色、场景或战斗态势谁是主角？玩家首先看见什么、接着去哪里？重心、留白与透视是否成立？
2. **信息与行动层级**：主操作是否明确？资源、任务、状态、次级入口是否各有优先级？是否存在重复、过密、过空或同等重要的问题？
3. **游戏感与题材一致性**：材质和组件是否像属于这个世界的器物？是否仍有网页后台、系统表单、通用模板菜单或素材拼贴的观感？
4. **精细度**：图标的轮廓、大小与重量，边饰的节奏，字体的字重/行高/对齐，选中态和反馈，是否达到成套作品的水平？
5. **角色与玩法表达**：营帐是否让角色有存在感？养成是否表达成长收益？装备是否让比较和投入清楚？战斗是否让行动时机、技能和目标可读？
6. **跨页完整性**：启动、登记、营帐、地图、养成、装备、背包、出征与战斗是否属于同一游戏？页面职责有差异时，如何保持一致又不机械复制？
7. **手机使用**：短屏、长屏、安全区、手指触控、长文字、明暗场、遮挡、滚动/分页/收合与返回是否能真实成立？
8. **资产与工程落地**：哪些问题靠布局和原生控件解决，哪些确实必须有新美术？每个依赖是否明确、可复用、可分批交付？

成熟游戏的判断必须落到这些可见与可实施的标准上。若提到某款成熟游戏，明确学习的是构图、信息或组件原则；没有读过其截图时标为类比，不声称已经检索或对照。不能复制他人的资产。

## 4. 覆盖范围与页面要求

主要范围：启动主菜单、营帐主页、城镇 HUD、野外 HUD、养成总览、装备、背包、战斗主视图、地区行路图、出征准备。

配套范围：登记、创建角色、加载、图鉴、设置、游戏介绍、战斗技能页。

请对 **全部 17 个提交视图** 给出最终设计。城镇与野外、战斗主视图与技能页可以共用系统，但各自的职责、布局差异与状态必须写清楚。不要只详写启动页，其他页面用“参考同一风格”带过。

未提供的天赋/宠物/坐骑/称号等内部子页面，用共有组件和扩展规则覆盖，不臆造完整玩法；养成总览的现有入口仍需完整保留。

跨页导航需形成一张简洁路径图，标明页面入口、返回、浮层关闭与低频功能的收纳位置。不要让玩家因为视觉收纳失去功能。

## 5. 交付一：`outputs/UI_REDIRECTION_MASTER.md`

包含以下内容：

### A. 真实画面诊断

- 先给出整体判断：现在最拖累整套游戏质量的结构性问题是什么，以及哪些已有成果有效。
- 列出最重要的 **12–20 个问题**，按影响排序；每条含页面/截图文件名、具体位置、可见证据、影响、处理方式和优先级。
- 区分全局系统问题、页面构图问题、需要资产的问题与待实机验证的问题。不要将同一个 Logo 或边框问题拆成多条凑数。
- 说明仅修小处为何不能解决这些结构问题，完整重构要改变哪些关键关系。

### B. 唯一主美术方向

- 用一句可执行的定义命名方向，给出气质、世界观联系、视觉母题与适用边界。
- 提供 HEX 调色表：基础色、文字色、结构色、强调色、语义状态色；明确常态/重要/危险/可领取/选中等用途与强调预算。
- 字体职责表：品牌、页标题、正文、数字、按钮、说明、角标的字号、行高、字重、颜色、字框与回退规则。
- 材质职责表：背景、主承载面、次承载面、操作、标签、地图、战斗指令各用什么材质，在哪些页面使用，如何保持轮廓与照明一致。
- 图标标准：造型、轮廓、色阶、源图/显示尺寸、透明留白、光向、采样与状态表达。
- 装饰标准：哪些区域可以承担标志性装饰，哪些区域必须安静；不靠到处加金边或循环发光获得精致度。
- 世界像素与精细 UI/清晰中文之间的连接原则。主角、背景与界面分辨率差异要有设计依据。

### C. 组件与行为体系

为共享组件分配稳定 ID，至少覆盖：主/次/轻量动作、栏目导航、页签、身份/资源、状态条、任务摘要、物品格/列表/详情、装备比较与投入区、地图框与标记、战斗指令/技能行、名牌、数量角标、提醒、提示反馈、弹窗与危险确认。

每种组件写清：用途、视觉结构、尺寸规则、内外边距、文字/图标区域、默认/按下/选中/禁用/键盘焦点/开关/可领取态，以及哪种状态需新图、哪种可通过原生颜色/绘制/动效实现。手机信息不能依赖悬停。

定义统一的网格、间距、圆角或切角、轮廓重量、分隔方式、阴影、叠放层级、转场与反馈节奏。允许按页面职责分族，但族之间要共享基础规则。

## 6. 交付二：`outputs/MAIN_UI_REBUILD_BLUEPRINT.md`

为全部 17 个视图建立独立章节，每章包含：

1. **页面职责与改造结论**：最重要的信息、视觉焦点、第一行动；当前保留/替换/收纳的内容及理由。
2. **最终构图与阅读顺序**：文本线框或简洁布局示意，并解释主轴、留白、层次及角色/背景的位置。
3. **480×800 区域表**：区域 ID、x/y/w/h、相对占比、锚点、内外边距、组件 ID、资产 ID、层级、点击范围。尺寸自洽，热区不重叠；装饰叠放与实际交互区分开。
4. **480×1067 与安全区**：固定区域、弹性区域、背景延展或裁切、角色/Logo 比例与脚底基线、底部操作位置；说明顶部 44/底部 34/左右 8 占用时如何保持可用。
5. **功能映射表**：每项原功能的新位置、新入口或收纳路径、返回方式，证明没有漏掉任何功能。
6. **内容与边界状态**：按该页处理长名字、长地名、任务两行、大数值、零数量、未解锁、空列表、满包、加载中、选择/禁用、费用不足、成功/失败等实际适用状态。未核实的标为假设，不虚构概率或数值。
7. **交互与反馈**：当前最重要的状态变化怎样表现、谁触发、持续多久、能否中断、是否接收输入。不得让所有模块常驻闪烁或发光。
8. **依赖与实施任务**：按共享系统→素材→页面→状态→验证排序；每条任务写目标、对应组件/资产、完成标准、风险或依赖。不写代码，不编造工程节点路径。

额外要求：

- 营帐：角色展示和继续旅程形成清楚主轴；资源与低频运营入口不过载；条件解锁入口出现后布局仍成立。
- HUD：给出常驻遮挡预算、中央净空、摇杆与操作簇的位置、任务展开上限、情境提示和名牌避让；不要为了放 UI 更改镜头或碰撞。
- 养成：六条成长线要表达职责和收益，不做六个同等重量的漂亮徽章。
- 装备/背包：物品辨认、筛选浏览、选择、比较、投入成本、操作结果与确认都必须清楚；不把关键信息挤成小字。
- 战斗：人物/伙伴/敌人、血量/状态、当前行动、指令与技能各有层级，反馈不能盖住可用行动；速度/自动/撤退权重区别明确。
- 地区图/出征：探索路径与选择配置要有游戏主题表达；已解锁、当前、条件受限的状态不只靠颜色。
- 登记/建角/设置：清晰输入和安全操作保留，避免为世界观装饰牺牲表单与确认。
- 加载/介绍：进度真实、阅读有节奏、图片与文字服务内容，不机械铺满纸页。

最后提供 **完整重构路线**：

- 第 1 批：共享视觉系统、最有代表性的一个主页面与最关键资产，建立质量基准。
- 第 2 批：营帐、HUD、养成与装备/背包的核心循环。
- 第 3 批：战斗、出征、地区图与配套流程完成统一。

这是实施顺序，不是缩减设计范围。三批所需页面本轮必须全部设计好。给出跨页完成依赖、每批真实截图清单、禁止带到下一批的质量缺陷，以及临时资产允许使用的期限/退出条件。
