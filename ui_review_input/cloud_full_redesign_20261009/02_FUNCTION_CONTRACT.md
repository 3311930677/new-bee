# 功能合同与页面路径

布局、分组与入口位置均可改变；功能、数值语义、访问路径和返回能力必须保留。未提供的子页面不需要逐一猜测内容，但必须定义可扩展的共同规则。

| 视图 | 必須保留 | 核心设计职责 |
|---|---|---|
| 启动主菜单 | 《远征》/昭元行旅录；开始、介绍、设置、退出；原开始后续流程 | 品牌与世界观、唯一主要行动、配套入口层级 |
| 营帐主页 | 头像更换、姓名/等级/经验、四币、角色展示、任务、活动、竞技/召唤/兑换、世界/背包/养成/图鉴、设置、继续旅程、条件解锁的归路小聚 | 角色与下一步行动的主轴；重要与低频入口分层 |
| 城镇 HUD | 等级、生命、历练、金币、地名、主/支/委托、地图、小地图、摇杆、药剂数量/使用、伙伴、疾行、营帐、已解锁骑乘、NPC/玩家/伙伴名字、情境互动 | 清楚读图与操作；保护中央游玩视野 |
| 野外 HUD | 同一 HUD 语言；目标指引、实际可用任务、出口/营帐或撤离语义、场景互动与提醒 | 亮暗场可读，危险与目标层级，入口不过载 |
| 养成总览 | 当前角色/职业/等级、属性或成长摘要；装备、天赋、技能书、宠物、坐骑、称号六条养成入口；返回 | 说明成长方向与下一步价值，避免六个同等装饰徽章堆砌 |
| 装备 | 当前职业武器、护甲/饰品槽位；选择/详情/属性；强化、宝石、精炼与词条操作；费用、材料、结果、不可用状态；返回 | 看懂当前装备、投入与收益、比较与操作反馈 |
| 背包 | 装备/材料/宝石/待领取页签；容量、列表/分页或滚动、选择、详情、现有装备/管理动作、领取与确认、返回 | 同时保住浏览效率、物品辨识、比较与处理路径 |
| 战斗主视图 | 玩家/敌人/伙伴位置与状态；当前指令、行动或技能信息；普通攻击、技能、药剂、伙伴相关动作、速度、自动/托管、撤退条件与确认；战斗反馈 | 态势、目标、行动时机与可点按钮优先级 |
| 地区行路图 | 地点、实际连线、可达/未解锁/条件状态、进入或前往路径、返回 | 地域探索感与可读路径；与历练路线区分 |
| 出征准备 | 秘境、人物、宠物三步/页签；世界或秘境选择、进入条件、当前配置、确认开始、返回 | 看懂去哪、用谁、带谁以及能否开始 |
| 登记 | 当前账号/密码等表单、已有头像/自定义头像功能、主要提交操作、已有错误反馈与返回 | 世界观中的清晰表单；准确输入与稳定反馈 |
| 创建角色 | 昵称输入/随机名字、已有性别/职业选择、角色预览与介绍、确认/返回 | 角色身份与玩法特点；有主角而非填满表单 |
| 加载 | 品牌或当前内容、真实进度/加载反馈、必要说明；保持原后续跳转 | 等待时的世界观与可信进度；不虚构进度 |
| 图鉴 | 当前图鉴分类、条目、已知/未发现状态、选择/详情与已有领取行为（若对应状态存在）、返回 | 发现感、收藏进度、角色/怪物辨识 |
| 设置 | 当前分类、档案/存档相关功能、操作/声音等现有选项、返回及危险动作确认 | 稳定清晰，功能和确认优先于装饰 |
| 游戏介绍 | 已有世界/人物/旅途内容和分页导航、关闭/返回 | 清晰讲述世界观；阅读与图像的节奏 |
| 战斗技能页 | 可用技能、费用/状态/条件、选择、目标或行动关联、关闭/返回 | 与战斗主视图共用层级；技能开关和禁用明确 |

## 跨页必须保留的规则

- 所有入口给出明确最终去向，收纳低频功能也必须能发现。
- 提醒由真实状态触发：可交付、可领取、材料/资源足够、解锁等。不要所有栏目常亮红点。
- 四币与金币均来自实际钱包；可以缩写，但必须给出查看完整值的路径。
- 长名字、长地图名、任务两行、超大数值、缺图和零数量需要有规则。
- 图标与文字不能成为不可交互的烘焙画面；名称、数据、计数、进度和状态保留原生可更新内容。
- 主世界回营帐与历练撤离行为不同；原有确认、暂停、返回和异常存档处理不能省略。
- 当前城镇/NPC/物件保留自动靠近互动。若新设计建议改成手动确认，必须列为改变交互机制的独立提案，不作为默认工程任务。
- 世界内角色、地图、镜头、移动、碰撞和战斗计算不因布局需要而随意更改。可提出视觉资产替换，注明技术依赖。

截图只覆盖代表性状态。具体触发阈值、隐藏子页和细节未提供时，写“待工程核实”，不补造数值或功能。
