# 风格边界与实现约束

## 保持的身份

中国古城与行旅幻想世界，像素角色、地图、建筑、伙伴与战斗；黄昏、夜营和暖灯火；旧木、旧铜、纸页、布与旅途器物的语境。品牌名称和人物身份保持。

你可调整 UI 色调、材质组合、轮廓、图标、装饰分量与页面结构，建立新的主方向。纸页窗口与深色 HUD 可以按职责采用不同材质，但必须有一套共同的字体、轮廓重量、状态与装饰逻辑。

不强制沿用上一轮的“每个容器都是 3px 切角和单铜边”。可推翻这类形制选择；给出新规则、适用边界和收益。不可把所有页面做成同一张板，也不可只堆金边、宝石、羽翼或强光来表达成熟感。

世界内像素风保持。若主页需要更高精度的像素角色展示、职业插画或动画，列出新增资产/帧序列需求，不把现有小图无限放大当作完成，也不直接更换成不相容的照片或写实角色。

## 尺寸与输入

- 项目配置：Godot 4.7，逻辑基准 **480×800（3:5）**；`canvas_items` + `keep_width`，竖屏。另有 **480×1067** 长屏证据。
- 所有坐标、字号和热区先以逻辑像素表示，给出相对比例与锚点；不能默认按 1080×1920 设计后缩小。
- 主要操作热区至少 44×44，紧邻热区不得重叠；可见图形可以小于热区。考虑右手/左手、摇杆与操作区域的冲突。
- 安全区从运行时可用矩形取得；说明顶部 44、底部 34、左右 8 的模拟占用处理。背景可越过安全区，交互不能越界。
- 长屏通过背景延展、弹性留白与分组锚定适配，角色、徽记和边饰保持比例。不对整页统一缩放来解决问题。
- HUD 必须给出游玩视野的遮挡预算；战斗必须给出角色、敌人、反馈与指令区之间的空间关系。

## 字体与资产

- 现有 MaShanZheng、NotoSerifCJKsc-SemiBold、NotoSansSC Regular/Bold 等中文字体。可使用新字体方案，但需完整中文覆盖、字号验证、授权/来源要求和回退；不要假定不存在的字库已经安装。
- 小字号正文不用密集毛笔字。需要大标题、页面标题、正文、数值、说明、角标各自的字号、行高、字重、颜色和长文本规则。原尺寸阅读是底线。
- 文字独立线性过滤；像素世界素材以最近邻为主；精细 UI 图标和器物按显示尺寸规划采样。不能一律像素化或一律模糊平滑。
- 背景、角色、Logo、按钮面、边框、图标、状态、阴影与文本需要可拆层。动态中文和数值不得烘焙进新图。
- 按钮/边框若使用九宫格，必须给出源图尺寸、边距和可拉伸/不可拉伸区；角色、徽章与字标不得非等比拉伸。
- 允许重新制作大量必要素材，但需要共享组件优先、依赖和成本分级。代码绘制适合简单形状；真正承担构图与质感的资产要明确列出。

## 不确定性与工作边界

截图与功能合同优先，当前坐标不是固定限制。缺少隐含状态可提假设，标出需要工程或实机验证的内容。

设计阶段只读此包，不读取工程、源码、日志、存档或整个素材库，不运行 Godot、不做测试、不调用 Godot MCP、不启动子代理、不生成图片、不改工程。素材生成提示词作为文本交付即可。

没有本轮实际 API 调用费用上限的数据；不推测 Wokey/Cloud 计费，不把“少花钱”当作削弱方案细节的理由。控制上下文的方法是只读相关截图一次、交付结构化文件、避免旧长对话和无关工具结果。
