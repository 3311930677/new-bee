## 同一份尺寸规范

根目录的 `ui_kit_spec.json` 是原规范的逐字节副本，未改变任何美术尺寸、游戏尺寸、切线或布局框。生成提示词的每件尺寸和固定角块范围直接从该规范读取；后续还原仍读这份规范，不以模型画出的外框尺寸反推规范。1美术像素=2屏幕像素。

每张初次生成都附了指定的三张参考图：对应无文字布局图、`style_ref_title_bg.png`、`style_ref_character_x4.png`。修正调用额外附上待修原图。`references/` 保存全部布局图、标注核对图和两张风格参考副本。

`generation_prompts.json` 保存7张初始实际提示词，`revision_prompts.json` 保存角饰、蜡封、条填充、货币座等修正提示词。带 `_v1`、`_v2` 后缀的文件是保留的早期版本，不是建议使用的版本。

## 视觉检查与处理决定

- 检查了数量、无文字、无画入按钮图标、无角色、无投影/外发光及可拉伸中段。对主按钮和次级按钮的大角饰做了缩小修正，对任务卡删掉了垂入中段的缎带，对货币左端圆座做了缩小，对条填充去掉了额外外框。
- 为遵守中段无装饰和轮廓一致，选中页签使用内部边框亮度表达，省略文档细项中的底部中央缺口。主按钮角饰简化为小型角扣与内嵌宝石，避免纵向拉伸中段出现卷纹。
- 7张PNG完整性与1536×1024尺寸通过检查；按品红色族分离前景后识别出3、6、2、3、7、5、5个独立大组件，总数31。识别到的实际源图包围框记录在 `asset_manifest.json`，它们仅帮助找图，不替代规范的 `guide_box`。

## 源图的实际限制

生成结果是用于后续网格还原的美术源图，尚不是Godot可直接接入的九宫格贴图。模型未严格遵守每个方块的尺寸、4/5/6倍整数像素网格、逐像素相同的状态轮廓或二值化边缘。应依照原规范还原并让同组状态/稀有度共用一个轮廓模板，九宫格拉伸测试在还原后进行。

品红背景视觉上干净，但实测RGB有轻微色差，不是每个像素都精确的 `#FF00FF`；原PNG保留了这种源图特征。后续需先按品红色族做容差抠底，再量化颜色和二值化透明，不宜只删除完全等于 `(255,0,255)` 的像素。导航圆座中透出的品红属于应抠除的空洞，不是素材本身的配色。

本轮未修改或提交 `Title.gd`、`PixelKit.gd`，未调整页面布局，也未运行游戏回归测试；只交付生图素材和记录。接入阶段仍需验证角块切线、轮廓一致性及各页真实截图。
