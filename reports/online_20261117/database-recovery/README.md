# 受限数据库身份与真实备份恢复

本批完成 L0 的数据库运行权限和本机逻辑恢复链。**Go 40/40、实际退出码 0；真实 HTTPS 双 Godot 客户端 9/9。** 原始记录见[验收索引](verification.json)、[Go 完成事件](go-integration.jsonl)、[Go 实际进程结果](go-result.json)和[真实双端报告](world/report.json)。

- 网关使用独立 runtime 身份，不持有数据库管理/迁移/备份凭据；以只读迁移检查和受限权限模式三次实际启动。误传离线凭据、拥有者身份和未来迁移均由实际网关拒绝；旧迁移程序和已有恢复目标也实际拒绝。
- migrator 拥有应用 schema，backup 只读；runtime 无建表/建库、角色管理、所有权、角色成员关系或账本改写/清空权限。Go 真实 SQL 覆盖 18 次越界尝试、成员关系防护，以及类型/大对象单独存在时不得误判空库。SQL 跟踪确认建角色前已生成 SCRAM 校验值，不把明文密码发进语句。
- 原生 `pg_dump` 归档与 17 张表的计数/摘要来自同一导出快照。Go 对照在快照建立后并发提交 110→117，实际恢复仍一致为 110；归档损坏在建库前拒绝，恢复行校验失败时仅隔离工具新建的库，源资产不变。恢复后的账本触发器、唯一约束、外键和余额约束均以实际 SQL 检查。
- 两个真实客户端先同城移动并各自胜利。发奖触发器故障时零半笔奖励，重启/原请求重试成功后，在两场未确认结算时以只读身份备份，再恢复到新库。**17 张表匹配，撤销 2 个会话、失效 2 个租约**；备份之后的源审计行没有进入旧快照。
- 原客户端观察旧访问/刷新令牌被拒绝，再普通登录原角色、重放原结算请求并取得相同结果 ID，最终每人金币 110、各一笔结果/奖励账本/claim/确认，零有效会话。玩家数据和在线源码运行前后未变，客户端/权威日志无错误。

[备份清单](world/backup-manifest.json)和[恢复报告](world/restore-report.json)保存实际 UTC 起止时间、归档摘要和全表校验。此处仅收脱敏报告、日志和[同屏](world/world-a.png)/[战斗](world/battle-a.png)/[结算](world/result-a.png)截图；数据库 dump、TLS 私钥、连接、角色密码、客户端凭据和屏障文件均未归档。完整单机回归独立为[79/79、实际退出码 0](../database-regression/README.md)，没有改变性能预算。
