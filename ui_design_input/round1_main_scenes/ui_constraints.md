# 技术与素材约束

## 已核实事实

- 项目：《远征》，Godot 4.x；配置声明 4.7，既有记录使用 4.7.2。
- 竖屏逻辑基准为 **480×800（3:5）**，不是默认 1080×1920。拉伸模式 `canvas_items`，比例策略 `keep_width`，竖屏；项目已有 480×1067 长屏截图及安全区处理。
- UI 很多在运行时由脚本建立，`.tscn` 文件本身不是完整布局证据。设计阶段不需要读取代码或节点树。
- 当前背景和角色为像素幻想/行旅题材，营帐为青蓝夜色、暖灯火、古城与帐篷；地图为像素地面、建筑、NPC 和可移动人物。
- 字体资源现有 MaShanZheng、NotoSerifCJKsc-SemiBold、NotoSansSC Regular/Bold、ZCOOLXiaoWei、ZCOOLQingKeHuangYou。毛笔字适合大标题；正文和数字有清晰字体可用。
- 当前像素角色与地图主要采用最近邻过滤；正文已独立使用线性过滤。高清器物图标已有缩小采样方案。不能将整个 UI 一律最近邻，或一律平滑。
- 原生文字、计数、进度条、红点、点击热区与状态需继续独立于美术贴图。当前已有少量烘焙文字的装饰资源，新增方案应逐项说明替换或拆层。

## 设计必须满足的约束

- 尺寸一律先以 480×800 逻辑像素表达；同时给出相对占比、锚点及长屏变化规则。不要机械拉长按钮、角色或装饰边框。
- 重要热区至少按 44×44 逻辑像素规划，这是本轮交互底线，不是对实体手机测试的结论。可见图案可小于热区。
- 安全区使用运行时得到的可用矩形，避免把顶边/底边写死在屏幕边缘。分别说明背景延展、固定控件和弹性区域。
- 正文应在原尺寸截图可读。给出字号、行高、字重、颜色、字框高度与长文本策略，不能只说“高级字体”。小字号不用密集毛笔字或厚描边。
- 不改变人物移动、镜头、碰撞、地图尺寸或玩法参数来配合美术。HUD 排布可重做；背景、角色比例的改动必须列出代价与依赖。
- 不将可交互区域画进整屏图，不把游戏做成网页仪表盘，不增加缺乏玩法依据的商城、体力、排行、付费入口。
- 不要求工程师只凭概念图猜布局。必须给出区域矩形、间距、层级、状态和资源拆分。

## 新素材规格要求

每项必须包含：唯一 ID、用途、优先级、最小可用方案、显示尺寸、源图尺寸、透明背景要求、可拉伸区/九宫格边距、文字安全区、采样方式建议、状态变体与依赖。

像素角色以整数倍展示为优先方向；若要求高精度角色立绘，需明确这是新增资产，而不是放大现有低分辨率角色即可实现。中文文案、玩家名字和数值不得烘焙进新图。背景与构件分层交付，不能拿完整合成图当可用 UI 资产。

预算未知：用户希望少量 Opus 调用完成设计，普通编程交给 Codex。把素材分为必需/增强/后续，优先给出可复用的少量组件。不推测 Wokey 单次价格，不宣称提示词可强制费用上限。

## 交付准确性

仅凭截图无法判定点击逻辑、性能或所有隐藏状态。发现证据不足时写清假设，在不改变功能合同的情况下提出设计；不要要求扫描工程补齐。历史截图日期与局限见 README。
