### 当前走路精灵图制作规范

**画布**：512×512，4 列 × 4 行，每格 128×128，RGBA 透明底；脚底基线统一为 y=120，人物四周至少留 4px 透明安全区。

**步态解剖（4 帧循环，帧号 0-3）**：
- 帧 0：左脚向前接触地面，右脚在后
- 帧 1：经过位，双腿收拢，作为停止时的中性姿势
- 帧 2：右脚向前接触，与帧 0 互补
- 帧 3：反向经过位，随后无缝回到帧 0
- 躯干、头和武器尽量锁定，只允许腿脚及少量披风、衣摆的次级运动

**生成管线**：以角色 idle 为身份参考、旧 walk 只作方向外观参考；每个方向单独生成横向四帧条带。清除棋盘格/黑底后，四帧使用同一个联合裁剪框与固定锚点，人物级统一缩放，地面基线 y=120，再生成 SpriteFrames、编号检查图、128px 循环 GIF 和游戏实际 64px 循环 GIF。

**验收标准**：第 0/2 帧为相反落脚位，第 1/3 帧分别抬起不同的脚；每帧至少有一只支撑脚接近同一地面线；人物、武器、披风和脚尖不得切边；四方向身份与持械一致。必须同时查看 128px 逐帧表和 64px 实际尺寸循环，最后通过 Godot 资源加载、切块范围、实际位移、斜向归一化和停步测试。

## 后续生成公共约束（所有重生成提示词须遵守）

1. **角色设定锁定**：同一角色的 idle / icon / walk_4dir / 立绘必须共用同一段外观描述（发色、发型、头饰、服装主色、武器样式），仅改动作与帧布局；优先以 walk_4dir 为准反推其余。
2. **风格统一**：像素风为主基调（16-bit JRPG 质感），背景/deco 类提示词一律追加 "pixel art style, consistent with 16-bit JRPG"，禁止水彩/晕染混搭。
3. **tile 可平铺**：地形 tile 提示词必须含 "seamless tileable texture, edges wrap perfectly"，生成后先 3×3 平铺实测再入库。
4. **画布留白**：透明素材四周至少留 2px 空白，禁止主体贴边；生成后检查四角与四边 alpha。
5. **宠物特征显式声明**：尾巴数量、眼睛数量等关键特征在提示词中明确写出（如 "single tail"），避免模型自行发挥。

## 全量接线回归（2026-09-17，300+ 素材接入后的自测）

审查范围：`G.res_tex()` 索引的 59 项游戏内实际引用素材（8 主题战斗背景 + 5 流派图标 + 4 地图交互物件 + 宠物 + 主题怪物/首领），并逐场景截图复核 12 张界面。

**结论：素材本身无缺陷（59/59 全部解析成功）。本轮发现的问题全部在“代码取用素材的方式”上，均已修复：**

- [x] **【已修复】素材索引只认 `source/` 母稿，从不认 `ready/` 成品**（`G._build_res_index`）。
  影响：每个 UI 图标/横幅都加载 970~2170px 的原始大图——显存浪费巨大，且 `ready/` 里已裁切到设计尺寸的成品完全没被用上（与素材清单“ready 可直接使用”的口径矛盾）。
  修复：改为**先索引 `ready/`（递归各子目录），再用 `source/` 补位**；新增 `_scan_png_dir()` 复用扫描逻辑。

- [x] **【已修复】`TextureRect` 的 `expand_mode` 赋值顺序错误**（5 处：`GachaPanel._tex_rect`、`TraitPicker` 流派图标、`CodexPanel` 头像/边框、`BattleScene` 战斗背景）。
  `Control.size` 只会被“顶大到不小于最小尺寸”，不会自动缩回。原代码先设 `size` 再设 `expand_mode`，导致最小尺寸瞬间被钳到贴图原尺寸，`size` 随后被顶成原图大小。
  最直观的症状：召唤横幅 `ui_banner_gacha` 被撑成 **2172×724** 铺满整个面板，把「保底/出率/炼化规则」等文案全部压住不可读（见修复前后对比）。
  修复：一律把 `expand_mode` 移到 `size` 之前。

- [x] **【已修复】`GachaPanel._gold_btn2` 两行按钮文字重叠**。
  `PanelContainer` 会把每个直接子控件都铺满内容区，原实现再 `add_child` 一个副标 `Label`，导致标题与副标完全重合（「十 连」盖在「800 魂石 / 1 券」上）。
  修复：改用 `VBoxContainer` 竖排标题与副标；同步修正「再抽一次」按钮取子节点的方式。

- [ ] `bg_battle_snowfield` 命名与其余 7 张 `bg_battle_<主题>` 不一致（主题 id 是 `snow`，素材名多了 `field`）。
