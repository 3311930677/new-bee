## 0. 全局逻辑与对应关系

### 0.1 端到端玩法逻辑链（一张图理清全游戏）

```
【启动 · 单主线入口（v1.5）】
  启动 → 有存档? ── 是 ──→ 【主世界】远征主城（唯一常驻入口）
                └─ 否 ──→ 登录 → 创角 → 主世界

【局外循环 · 主世界（养成主城，§6.2/§6.3）】
  主世界远征主城(GameHome)
    ├─ 顶栏四币：金 / 远征币 / 灵魂石 / 荣誉（cur_* ×4）
    ├─ 面板：人物卡 + LV/经验条（当前 LV、exp/需求、世界进度 N/8、当前世界）
    ├─ 出征(§2.6/§2.7) → 选秘境(已解锁世界) → 选人物(4人,roles.json)
    │                   → 选出战宠+替补(pets.json，未解锁宠不可选) → 进局
    ├─ 世界图志(§6.2)：8 世界列表，三态 已通关 / 可挑战 / 未解锁(附解锁条件)
    ├─ 宠物图鉴(§3)：8 宠两列，已收集 / 未收集(附解锁条件)，收集态实时刷新
    └─ 养成 6 线(§6)：等级天赋/装备/宠物/技能书/坐骑/称号 → 战力提升

【局内循环 · 一局远征（5~10分钟）】
  路线图骨架(nodes.json: 起点→3层×3选1→BOSS)
    → 进入节点 = 落地为探索大地图区域(maps.json: tile+散件+怪物刷新+出口传送阵)
    → 大地图自由移动(WASD/方向键/摇杆/点击寻路) → 怪物警戒追击 → 接触开战
    → [战斗](§2 站位制): 自动普攻+5技能手动+换宠+托管
    → 胜利回地图(怪消失/掉落) → 三选一词条(traits.json) → 找传送阵 → 下一节点
    → (HP跨节点延续/能量buff清空/词条保留 §2.6)；任何时候可「撤离」退出(§2.7)
    → BOSS节点 → 局结算: 经验 + 材料产出(金币/远征币/灵魂石/材料/荣誉)

【接口 · 三条经济闭环】
  1 战斗闭环：局内词条构筑(随局重置) → 局外数值养成(永久)
  2 推图闭环：打怪得经验/材料 → 升级 + 强化 → 战力 → 通关当前世界首领
             → 解锁下一世界 + 解封该世界对应宠物 → 更高层（§6.2 成链推进）
  3 抽奖/PVP 闭环：远征产出货币(灵魂石/金币) → 抽奖 → 宠物/装备 → 战力；
                  对战 → 荣誉 → 称号/限定材料（荣誉不加深数值差距）
        已通关世界 → 扫荡(70%收益) → 快速积累
```

### 0.2 开发顺序总纲（v1.3 定稿：单机先行，PVP 渐进）

```
阶段0 工程奠基 → 阶段1 战斗竖切 → 阶段2 远征循环(大地图) → 阶段3 养成+抽奖
→ 阶段4 单机深化(深渊/无尽/词条轮换)  ←—— 单机完整闭环，可独立上线测试
→ 阶段5 PVP渐进: 5A 账号+确定性改造+中继 → 5B 1v1 → 5C 2v2 → 5D 3v3 → 5E 赛季
→ 阶段6 社交 → 阶段7 打磨发布
```

单机闭环先行的理由：①PVE 本地结算无网络依赖，验证核心玩法最快；②确定性改造（5A）复用阶段 1 的战斗内核（§2.1 时序本就按可复现种子设计）；③ PVP 1v1 只需"1 个人物+1 宠"上阵，2v2/3v3 复用同一战斗内核仅扩展布阵显示——**战斗内核一次写对，四个模式全吃**。

### 0.3 状态机（启动路由 + 单局，玩家视角）

**启动路由（v1.5 单主线入口）**：
```
BOOT → G.has_profile()? ── 否 ──→ TITLE(标题) → LOGIN(登录) → CREATE(创角) → HOME
                        └── 是 ──→ HOME(主世界远征主城)   ← 有存档跳过登录/创角，直达主城
```
> `[已实现]` `has_profile()` = `selected_role` 与 `player_name` 均非空即视为老玩家，由 `Main.gd` 在启动时判定并 `go_game_home`（延迟一帧切换，避开 autoload 加载期）。顶栏右上「重新创建角色」可主动回到创角流程。

**单局状态机**：
```
HOME(主世界) → DEPLOY(选世界/选人/选宠) → ROUTE(路线图选节点)
  → EXPLORE(大地图移动/交互) ⇄ BATTLE(遇敌开战)
       ↑↓  胜:回EXPLORE / 败:→SETTLE
  → BOSS_BATTLE → SETTLE(经验+材料结算) → HOME
任意 BATTLE 失败 → SETTLE（无惩罚，材料照给）
任意 EXPLORE → 点「撤离」/按 ESC 二次确认 → SETTLE(exited) → HOME   ← v1.5 新增出口
```

## 1. 人物机制（4 人定稿）

### 1.1 框架

- **人物固定 4 名**，无人物卡池（抽奖不抽人，见 §5）：
  | id | 名字 | 职业 | 武器 | 定位 | 素材目录 |
  |---|---|---|---|---|---|
  | zs | 破军 | 战士 | 大剑 | 近战物理，能抗能打 | `image/role/zs/` |
  | ck | 穿杨 | 枪骑 | 长枪 | 中远程物理，灵动输出 | `image/role/ck/` |
  | fs | 霜语 | 法师 | 法杖 | 远程群伤+控制 | `image/role/fs/` |
  | fz | 晨星 | 牧师 | 圣锤 | 治疗辅助，可独立刷怪 | `image/role/fz/` |

- **出战规则**：PVE 远征局内 = 1 人物 + 1 出战宠物 + 1 替补宠物（见 §3.4 换宠）；PVP = 按模式 1/2/3 人上阵（宠物随人物参战）。**人物之间不切换**——选人即本局身份，跨局可选不同人物；等级/天赋/装备/技能书全局共用（武器分系例外，见 §6）。
- **属性 8 项**：HP / ATK / DEF / SPD（普攻间隔系数，roles.json 的 `speed`）/ CRIT / 能量(上限100) / 技能 CD / 控制抗性。无命中闪避、无物法分离。
- **普攻基准间隔 = 2.0s ÷ SPD**（SPD 为除数系数）→ 能量回充 = 20 × SPD / 秒。霜语 0.9 ≈ 9/s，穿杨 1.2 = 12/s——**能量经济分人物显著不同，阶段 1.8 必须分人物模拟**（霜语费用高+回充慢双重惩罚是否成立）。

### 1.2 成长公式（等级 1~60）

```
升到 lv+1 经验 = lv×100 + 2×5^(0.1×lv)
HP   = 100 + 40×(lv−1)
ATK  = 20  + 4×(lv−1)
DEF  = 10  + 2×(lv−1)
CRIT = 5% + 0.1%×lv
```

**装备外观 3 阶**（纯表现）：ATK 达 50 / 120 / 250 自动升阶，仅武器+甲两部件换装（见素材清单 A3）。

### 1.3 站位与攻击规则（策略核心，v1.1 定稿修正）

- 战场 20 站位 = 5 列 × 4 排，敌我各半场 5×2，靠中线一排为各自**前排**。
- **普攻目标规则**（消除 v6"远程可打后排"与夺魄"无视前排"的矛盾，定稿如下）：
  - **近战**（破军、晨星）：只能命中对方**前排**存活单位；敌方前排全灭时**战场推进**，可攻击任意存活单位（防僵局）
  - **远程**（穿杨、霜语、远程宠物）：可打**任意排**，默认目标 = 敌方最低血（被嘲讽时强制转火）
  - **指定排是技能特权，不是普攻特权**：夺魄=指定后排且无视 50% DEF（原"无视前排"附加值与远程普攻规则重复，已改）；倾泻=随机目标（含后排）；霜语 AOE=全体
- 位移词条/技能可改变站位（击退/换列）。
- 显示分层：PVE 只高亮有单位区域（紧凑）；PVP 1v1 紧凑 / 3v3 全场展开。格子逻辑两模式统一。

## 2. 战斗逻辑

### 2.0 战斗全流程状态机（遇敌 → 结算，逻辑主干）

```
ENTER(遇敌触发/接触判定)
  → 布阵快照: 敌方编成(§2.5)按站位表落位; 我方=人物+出战宠(按人物id固定列)
  → INTRO(1s): 背景bg_battle_{主题}淡入, 单位入场
  → LOOP(固定tick 1/30s, §2.1时序):
       BuffSystem → 施法队列(前摇) → TraitSystem → 普攻计时 → AI/玩家指令 → 死亡判定
       玩家输入(5技能/换宠/托管) → 指令校验(能量/CD/存活) → 入施法队列
       换宠: 替补入场(获免死1次) + 出战宠退场(本局不可再上, CD 60s)
  → 胜利条件: 敌方全灭 → VICTORY
  → 失败条件: 我方全灭(人物+宠) → DEFEAT
  → SETTLE: 战斗结果 → 掉落(itm_*/cur_*) → 回大地图(§2.7) 或 局结算(§2.6)
```

**指令优先级**（同一 tick 多输入）：换宠 > 技能 > 托管开关（换宠是即时快照操作，技能需排队前摇）。前摇 0.3~0.5s 的设计目标：①打击感（起手→命中两段表现）②PVP 联网延迟掩埋（§7）。

**战斗场景构成**（素材全部到位的完整战斗画面）：
- 背景：`bg_battle_{主题}` ×8（遇敌主题决定）
- 单位：人物（§1.6 姿势帧）+ 宠物（§3.4）+ 怪物（§4.4）
- HUD：`ui_panel_battle` 技能条底 + `sk_*` 技能图标 ×20 + `buff_*` 状态角标
- 表现：`fx_{技能id}` 命中特效 + `sfx_*` 状态特效 + 飘字（程序 Label，走 G.gd 字体）

### 2.1 一帧的时序（确定性要求，PVE/PVP 共用）

```
tick(固定 1/30s 步进):
  1. BuffSystem.tick()        # 持续 buff 计时/触发（流血跳字等）
  2. 施法队列推进             # 前摇 0.3~0.5s 倒计时，到点结算伤害（表现层可延迟播）
  3. TraitSystem 钩子          # on_tick
  4. 普攻计时器按 SPD 触发     # 普攻 +20 能量
  5. MonsterAI / 玩家输入指令入队
  6. 死亡/胜负判定
```

随机数全部走可复现种子（`seed` 局内固定），PVE 与 PVP 逻辑同源——这是阶段 5A 确定性改造的前置。**战斗随机与局外抽奖随机两套源严格隔离**（见 §11-3）。

### 2.2 伤害公式（DamageCalc.gd，纯函数可单测）

```
伤害 = ATK² / (8 × DEF + ATK)    # 暴击 ×1.5；治疗类 = HP%×MaxHP + 系数×ATK；下限 1
```

TTK 目标（1.8 数值模拟校验，v1.4 场级口径修订）：普通场 8~20s / 精英场 10~30s / BOSS 场 45~120s（lv10~12 匹配第一层远征的实测锚点；lv1 开局基线 20~80s 属成长激励期）。原"精英 40~70s"口径废弃——单场 >40s 对竖屏连打节奏（验收：连打 5 局不腻）过长。模拟曲线不合预期时调 DEF 系数/怪物 HP，不拍脑袋。

### 2.3 状态效果 17 种（BuffSystem）

**持续 15**：流血、中毒、定身、混乱（随机目标 50% 伤害）、减速、破甲、嘲讽、恐惧、潜伏（受击减半）、反震、吸血、护盾（吸收层）、无敌、免死（锁 1 血）、复活。
**即时 2**：斩杀（低于阈值处决）、驱散（移除指定状态）——走技能结算管线不进 buff 生命周期。

每个 buff 字段：`创建时机/触发时机/层数上限/控制抗性豁免`。**控制抗性**：单属性降低被概率施放定身/混乱/恐惧/嘲讽的成功率。

### 2.4 词条钩子（TraitSystem）

**词条总数 44 = 常规 40 + 双刃 4（v1.1 口径修正）**：数值系 12 + 机制系 16 + 流派联动系 12 = 常规 40；双刃独立一档 4 条（燃血/薄甲/狂潮/死线）。六流派（流血/暴击/反伤/控制/能量/召唤），钩子：`on_hit / on_tick / on_kill / on_behit / on_skill`。同流派 ≥3 条触发流派效果（如反伤 3 件 → 反伤翻倍+回血）。

**流派归属（v1.4 补定）**：联动系每流派仅 2 条，不足以凑 3 件触发 → 数值/机制系中语义强相关词条同时归属流派（type 不变，仅 school 字段）：流血 = 撕裂者+放血者+重创；暴击 = 致命韵律+弱点洞悉+精准+裂创；反伤 = 坚壁反震+以伤换伤+荆棘·小；控制 = 霜寒延长+碎冰+寒触+重击+威吓；能量 = 能量导管+超载+聚能+充盈；召唤 = 宠物强化+共鸣+生生不息（持久战叙事）。每流派可凑 3 件，三选一定向Build可达。

**三选一构成（v1.1 精确化）**：槽1 = 数值或机制系随机；槽2 = 流派联动系（85%）或双刃（15%）；槽3 = 全池随机。双刃可选不选（复杂度不作难度）。

### 2.9 PC 键位适配（v1.5 新增）

**背景**：`project.godot` 里**没有 `[input]` 段**——所有操作动作都在运行时用代码注册，避免手改工程文件、也方便热调。

**实现**（[已实现] [G.gd](file:///d:/godot/new%20bee/远征/src/autoload/G.gd) `ACTIONS` + `_ensure_input_map()`）：

| 动作名 | 绑定键 | 说明 |
|---|---|---|
| `move_left` | `A` / `←` | 左移 |
| `move_right` | `D` / `→` | 右移 |
| `move_up` | `W` / `↑` | 上移 |
| `move_down` | `S` / `↓` | 下移 |
| `gm_console` | `F10` / `` ` `` | 唤起 GM 开发者控制台（§14） |
| `ui_cancel` | `ESC`（引擎内置） | 关闭/返回；探索中触发「撤离」二次确认（§2.7） |

**为什么用 `physical_keycode`**：绑定写的是**物理键码**（`InputEventKey.physical_keycode`），不是字符键码——这样 WASD 与输入法状态、键盘布局（QWERTY/AZERTY 等）无关，中文输入法激活时也不会失灵。这是"适配 Windows 端 WASD"的关键点。

**接法**：
```gdscript
const ACTIONS := {
    "move_left":  [KEY_A, KEY_LEFT],
    "move_right": [KEY_D, KEY_RIGHT],
    "move_up":    [KEY_W, KEY_UP],
    "move_down":  [KEY_S, KEY_DOWN],
    "gm_console": [KEY_F10, KEY_QUOTELEFT],
}
func _ensure_input_map() -> void:
    for action in ACTIONS:
        if not InputMap.has_action(action):
            InputMap.add_action(action)
        for kc in ACTIONS[action]:
            var ev := InputEventKey.new()
            ev.physical_keycode = kc
            InputMap.action_add_event(action, ev)
```
地图移动侧统一读 `Input.get_vector("move_left","move_right","move_up","move_down")`（自带归一化，斜向不加速）；触屏摇杆仍可作为同动作的并行输入源。

**注意**：`GmConsole` 用 `_input`（而非 `_unhandled_input`）接收 `gm_console` / `ui_cancel` 并 `set_input_as_handled()`，保证 GM 面板的开关优先级高于场景层；场景层的 `ui_cancel` 处理先判 `G.ui_blocked`，两者不打架。

### 6.2 世界解锁链（v1.5 新增——8 世界成链逐个开）

**主线骨架**：8 个主题按 `maps.json` 的 `theme_order` 排成一条**单链**，玩家**开局只解锁第 1 界**，通关当前界的 BOSS 才开下一界——这就是"养成系列"的推进轴。

```
theme_order = [forest, snow, volcano, tomb, desert, glacier, abyss, castle]
                ①       ②       ③       ④       ⑤       ⑥       ⑦      ⑧
开局 worlds_unlocked = 1  →  通关第 N 界 BOSS → worlds_unlocked = N+1（+ 解封该界宠物）
```

- **通关判定落点**：局末 BOSS 战胜利 → `RouteScene` 结算 → 调 `G.on_world_cleared(theme_id)`
- **推进规则**（[已实现] [G.gd](file:///d:/godot/new%20bee/远征/src/autoload/G.gd) `on_world_cleared`）：标记 `prog.world_cleared[theme_id] = true`；若 `theme_id` 在 `theme_order` 中且下一界未解锁，则 `prog.worlds_unlocked = idx + 2`，**一次只推进一界**（跳级 / 重复通关不会越界）；返回新解锁的世界名（无新解锁则返回空串）
- **宠物同步解封**：同一次调用内 `unlock_pets_for_world(theme_id)` 把该界对应宠物写进 `prog.pets`（映射见 §3.1）
- **存档字段**：`prog = { level, exp, worlds_unlocked, world_cleared{}, pets[] }`，随 `G.save_game()` 落 `user://save.json`（v2）
- **[已实现]** 主世界「世界图志」面板三态展示：**已通关** / **可挑战**（`worlds_unlocked` 内未通关）/ **未解锁**（灰显 + 显示解锁条件"通关「上一界」首领"）；「出征」对未解锁世界**硬门禁**（按钮 `locked`），由 `VerifyGameHome.gd` 的 G/H 段覆盖

**为什么是"链"而不是"全开"**：让每个世界都是明确的目标与奖励（宠物 + 材料 + 经验），避免玩家乱跳导致战力断层，也把"打怪升级 → 打下一界"变成唯一正反馈路径。

## 7. PVP 实时对战（完整设计，v1.3 扩充）

### 7.1 模式矩阵

| 模式 | 上阵 | 属性规则 | 词条/宝石 | 匹配 | 结算 |
|---|---|---|---|---|---|
| 排位 1v1 | 1 人+1 宠/方 | **白板**（基准属性表，与等级无关） | 不生效 | ELO ±100 段内 | ELO ±25/−20，赛季段位 |
| 排位 2v2 | 2 人+各 1 宠/方 | 白板 | 不生效 | 队伍均分 ELO | 同上（队伍共享） |
| 排位 3v3 | 3 人+各 1 宠/方 | 白板 | 不生效 | 同上 | 同上 |
| 休闲 1v1~3v3 | 同上 | **战力带入**（等级/装备/宠物/技能书全生效） | 不生效 | 无段位约束，快速匹配 | 荣誉少量、无 ELO |

**白板化细则（排位）**：天赋/装备数值/宠物数值/技能书 k 加成全部失效，仅保留外观差异（皮肤/装备 3 阶外观/坐骑）→ 排位 = **人物选择 + 宠物选择 + 阵容站位 + 技能操作**，纯技巧对局。
**休闲补偿**：属性差超 20% 时低方补 10% 全属性；120s 超时按剩余血量 %（**溢出治疗不计入**，防治疗拖延流）。

### 7.2 对战流程状态机（匹配 → 结算）

```
LOBBY(PVP大厅,ui_panel_pvp_lobby)
  → 选模式(1v1/2v2/3v3 + 排位/休闲) → MATCHING(匹配中,ui_panel_pvp_match)
      2v2/3v3: 先组队(邀请/自动补位,ui_panel_pvp_team) 再全队入匹配
  → MATCHED: 服务端建房间,下发 seed(战斗种子)+双方阵容快照
  → DEPLOY(阵型): 30s 内拖动站位(列选择;宠物位固定随人物) → 锁定
  → BATTLE: 锁步帧同步对战(§7.3), 战斗内核=§2 同源(PVE/PVP 一套逻辑)
  → SETTLE: 服务端权威判胜负 → ELO/荣誉结算 → 战绩页 → LOBBY
  掉线: 30s 内可重连; 超时判负(排位扣分减半,休闲不扣)
```

### 7.3 锁步帧同步（确定性，PVE 战斗内核直接复用）

**原理**：双方各自本地跑同一份确定性战斗模拟，每帧只交换**操作指令**（几十字节），不交换任何游戏状态——带宽极小且天然防作弊。

```
逻辑帧(固定 15fps 步进, 与渲染帧解耦):
  1. 双方客户端把本帧输入(技能i/换宠/托管)编码为指令 {tick, unit, action}
  2. 上传 pvp_relay(自建轻量房间中继, wss)
  3. relay 收齐双方本帧指令 → 广播"确认帧"给双方
  4. 客户端收到确认帧才推进 tick: 指令入队 → §2.1 同一战斗时序
渲染帧(60fps): 插值平滑表现; 指令本地乐观显示(前摇掩盖确认延迟)
```

**确定性三铁律**（PVE 阶段 1 就按此写，5A 改造成本归零）：
1. 所有随机走局内种子（房间 seed，双方一致）
2. 禁浮点比较/字典遍历序（伤害公式全整数运算或固定精度）
3. tick 固定步长，渲染与逻辑解耦

**掉线重连**：客户端重连后向 relay 拉取房间快照 seed + 已确认指令日志，本地重放至当前帧——确定性保证重放结果与对端一致。

### 7.4 对战内规则差异（vs PVE，仅 3 处）

| 差异点 | PVE | PVP |
|---|---|---|
| 指令来源 | MonsterAI（§2.5） | 对端玩家指令（relay 转发） |
| 站位显示 | 紧凑高亮 | 1v1 紧凑 / 2v2、3v3 全场 20 站位展开 |
| 超时 | 无 | 120s 按剩余血量%（溢出治疗不计） |

布阵规则（§1.3）前后排/近战远程限制**完全同源**——PVE 锻炼的站位理解直接迁移 PVP，这是设计意图。

### 7.5 ELO 与段位赛季

- ELO：胜 +25 / 负 −20；组队按队伍均分匹配；±100 分段内搜索，超 30s 放宽 ±200
- 段位 5 档：青铜→白银→黄金→铂金→钻石（rank_* ×5 徽章）；4 周赛季
- 赛季结算：按段位发荣誉+限定称号；超期未打降一档（服务端权威）
- 赛季榜（ui_panel_season）：本地榜 + 好友榜（阶段 6 社交后）

### 7.6 PVP 素材对应（提示词总库 §12）

|---|---|---|---|
| 段位徽章 | rank_{bronze,silver,gold,platinum,diamond} ×5 | 64×64 | 资料页/赛季榜/结算页 |
| PVP 大厅底板 | ui_panel_pvp_lobby | 256×256 九宫格 | 模式选择页 |
| 匹配面板底板 | ui_panel_pvp_match | 256×256 九宫格 | 匹配倒计时/双方信息 |
| 组队房间底板 | ui_panel_pvp_team | 256×256 九宫格 | 3 队员头像位 |
| 赛季榜底板 | ui_panel_season | 480×800 | 榜单整页 |

### 7.7 PVP 开发渐进（阶段 5 内部排序，5A→5E）

```
5A 地基: 账号服务(注册/登录/令牌) + 确定性改造收口(种子/整数化/固定步进)+单测
   + pvp_relay v0(wss 房间中继/掉线判负) + FrameSync + 联调工具(双开模拟器)
   验收: 双设备同 seed 同指令日志 → 战斗逐帧一致(哈希比对)
5B 1v1 竖切: 匹配→阵型→对战→ELO→战绩 闭环(只用已有战斗内核, 显示紧凑模式)
   验收: 双真机 10 局稳定; 前摇延迟掩埋手感可接受; 掉线判负正确
5C 2v2: 组队(邀请/自动补位) + 全场站位显示 + 队伍共享 ELO
5D 3v3: 六人同房间(压力测试: relay 并发/指令风暴) + 全场显示优化
5E 赛季: 段位/赛季榜/结算奖励/降级; 排位白板化实测(晨星治疗 vs 血量%结算)
   验收: 3v3 六人 10 局无掉线; 积分双端一致; 排位归一化生效
```

## 14. GM 开发者控制台（v1.5 新增，调试专用，**不入正式发行**）

**定位**：给开发/调试用的后门，能一键把账号打到"满级 + 全解锁 + 资源管够"，省去反复刷图。**必须在正式发行前用构建开关剥离或禁用**（默认密码硬编码，见下）。

**打开方式**（[已实现]）：

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 按 `F10` 或 `` ` `` | 唤起开发者控制台（`gm_console` 动作，§2.9）；再按一次关闭 |

- **互斥冻结**：控制台打开时置 `G.ui_blocked = true`，探索层 / 主城据此冻结移动与点击（关掉再恢复），避免面板下误操作

**功能表**（[已实现] [G.gd](file:///d:/godot/new%20bee/远征/src/autoload/G.gd) `gm_*`）：

| 按钮 | 调用 | 效果 |

- **数据驱动**：`level_cap()` 读 `growth.json`（60）、`world_count()`/`theme_order()` 读 `maps.json`、宠物读 `pets.json`——GM 一把梭始终与数据表一致，改表即改满配结果
- **[已实现] 回归覆盖**：`VerifyGameHome.gd` I 段验证口令校验、`gm_grant_all` / `gm_max_level` / `gm_unlock_all_worlds` / `gm_unlock_all_pets` / `gm_add_currency` / `gm_reset_save` 的落值，以及 `pet_unlock_text` 的展示文案
