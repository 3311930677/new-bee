# 四角色四方向行走精灵图与 Godot 切图

## 交付规格

本批角色沿用项目的破军、穿杨、霜语、晨星形象，采用 Q 版像素风行走，而非写实人体动捕。

| 人物 | 最终 PNG（项目相对路径） | 可直接赋给 AnimatedSprite2D 的 SpriteFrames |
| --- | --- | --- |
| 破军 | image/role/zs/pojun_walk_4dir.png | image/role/zs/pojun_walk_frames.tres |
| 穿杨 | image/role/ck/chuanyang_walk_4dir.png | image/role/ck/chuanyang_walk_frames.tres |
| 霜语 | image/role/fs/shuangyu_walk_4dir.png | image/role/fs/shuangyu_walk_frames.tres |
| 晨星 | image/role/fz/chenxing_walk_4dir.png | image/role/fz/chenxing_walk_frames.tres |

每张 512×512、RGBA 真透明、4 列×4 行、每格 128×128；每方向 4 帧，共 16 帧，四人共 64 帧。最终 PNG 不带序号、文字、网格线或外边距，可以等分切块。

| 从上往下的行 | 行索引 | 动画名 | 朝向 | 帧顺序 |
| --- | --- | --- | --- | --- |
| 第一行 | 0 | walk_down | 下／正面 | 从左往右 0～3 |
| 第二行 | 1 | walk_left | 左／左侧面 | 从左往右 0～3 |
| 第三行 | 2 | walk_right | 右／右侧面 | 从左往右 0～3 |
| 第四行 | 3 | walk_up | 上／背面 | 从左往右 0～3 |

默认 8 FPS、循环；一轮 0.5 秒。四帧依次为左脚接触、经过位、右脚接触、反向经过位。不要在结尾再追加第 0 帧，否则会形成重复停顿。AtlasTexture.region 为 Rect2(列×128, 行×128, 128, 128)，filter_clip=true。

## 制作流程与容易出错的地方

1. 先锁定人物、装备和服装，再分别生成正面、左右侧面、背面，并要求脚部参与走路，避免只有披风晃动。破军按用户补充参考图更新为年轻无胡须、棕红刺发、黑金盔甲、红披风、手持宽刃大剑。
2. 用内置 imagegen 按角色 idle 身份参考，为每个角色的每个方向分别生成横向四帧条带，共 16 条；提示词保存在 `image/role/walk_4dir_review/prompts_v5.md`，母图保留在各人物的 `source/*_walk_*_strip_v5.png`。
3. 检查持武器手和身份：破军四方向双手低位持宽刃剑；穿杨为深蓝黑高马尾、青披风、长枪；霜语为银发、深蓝服装、白毛领、深色靴子与法杖；晨星为金发、白修女帽、蓝白金长袍与晨星锤。
4. 去除生成图烘焙的棋盘格背景，保留白发、白袍及轮廓。仅清除不属于人物的极小孤立背景残点。
5. 每条母图按横向四格裁切，同一方向四帧使用联合透明包围盒，不对单帧重新居中；这样武器、披风和长发变化不会拖动骨盆。装入标准格时防止切掉脚尖、剑尖、枪尖、锤头和披风。
6. 每个人全部 16 帧使用同一个缩放比例，同一方向使用固定放置锚点。统一地面基线 y=120，格内至少保留 4px 透明安全区。
7. 生成 Godot 4 SpriteFrames 资源、逐帧编号检查图、循环 GIF，并运行真实引擎的资源与移动测试。

可重复执行：在项目根目录运行 `python tools/pack_walk_strips_v5.py`。技术检查记录在 `image/role/walk_4dir_review/qa_v5/technical_checks.json`。

## Godot 中的使用

最快方式：给 AnimatedSprite2D 的 Sprite Frames 属性直接加载上表对应的 .tres。

手动切图：新建 SpriteFrames → 添加对应 walk 动画 → Add frames from Sprite Sheet → 选择最终 PNG → Horizontal=4、Vertical=4 → 只选择对应方向的一整行 → 按左到右添加 → Speed=8、Loop 开启。参见 [Godot 官方精灵动画教程](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)。

使用 Nearest 纹理过滤，不开启 mipmaps；PNG 保留透明，使用无损导入。不要把带文字的 QA 检查图当成游戏素材。

角色节点位置表示地面脚底点。预览实现采用 AnimatedSprite2D.centered=false、offset=Vector2(-64,-120)，碰撞区域仅放在脚底附近，而不是把头部、披风和武器都塞进碰撞框。AtlasTexture 的裁剪设置参见 [官方 AtlasTexture 文档](https://docs.godotengine.org/en/stable/classes/class_atlastexture.html)。

移动必须改变 CharacterBody2D 的位置，不能只播放原地动画。velocity 使用像素／秒，调用 move_and_slide()，不再乘 delta；使用 Input.get_vector 归一化斜向输入。预览按实际位移速度调节动画 speed_scale，停止或顶住边界时停止播走路。参见 [CharacterBody2D 官方文档](https://docs.godotengine.org/en/stable/classes/class_characterbody2d.html)。

## 可直接运行的移动预览

打开 src/preview/WalkSpritePreview.tscn，按 F6 运行。点击人物按钮或按数字 1～4 选择角色，方向键移动；另三个人物保持静止。

预览独立于现有创建角色和主页场景。正式地图使用 `player_speed=88`，动画步频按实际速度缩放；每轮约移动 44px，与 48px 地图格接近。

## 核对结果与边界

64 帧逐张查看了带编号的检查图，并以 64px 游戏实际显示尺寸复查循环，核对落脚位、抬脚位、固定锚点、完整脚部、装备位置、透明边界与身份一致性；详细表见 `image/role/walk_4dir_review/qa_v5/frame_review.md`。`technical_checks.json` 记录联合裁剪框、固定锚点、最终包围盒、图像哈希与脚区重合率。

Godot 4.7.2 测试输出：`WALK_ASSETS_OK: 64 atlas frames; four roles x four movement directions; stop and diagonal normalization verified.`

通过资源加载、精确 Atlas 区域、四人×四方向实际位移、停止播放和斜向速度测试；独立预览场景也通过启动检查。测试环境对用户目录日志／证书访问存在限制，但本次资源和移动断言均执行完成、退出码为 0。

这些是可切块、可驱动实际移动的 Q 版行走素材。v5 不再一次生成整张方向网格，而是逐方向约束真实的左右脚接触与抬脚经过位，并用共享锚点消除逐帧重心漂移。AI 帧之间仍有少量发梢、衣纹和装备细纹变化；此批不包含攻击、跑步或受击动画。
