# 四角色四方向行走精灵图与 Godot 切图

## 交付规格

本批角色沿用项目的破军、穿杨、霜语、晨星形象，采用 Q 版像素风行走，而非写实人体动捕。

| 人物 | 最终 PNG（项目相对路径） | 可直接赋给 AnimatedSprite2D 的 SpriteFrames |
| --- | --- | --- |
| 破军 | image/role/zs/pojun_walk_4dir.png | image/role/zs/pojun_walk_frames.tres |
| 穿杨 | image/role/ck/chuanyang_walk_4dir.png | image/role/ck/chuanyang_walk_frames.tres |
| 霜语 | image/role/fs/shuangyu_walk_4dir.png | image/role/fs/shuangyu_walk_frames.tres |
| 晨星 | image/role/fz/chenxing_walk_4dir.png | image/role/fz/chenxing_walk_frames.tres |

每张 1024×512、RGBA 真透明、8 列×4 行、每格 128×128；每方向 8 帧，共 32 帧，四人共 128 帧。最终 PNG 不带序号、文字、网格线或外边距，可以等分切块。

| 从上往下的行 | 行索引 | 动画名 | 朝向 | 帧顺序 |
| --- | --- | --- | --- | --- |
| 第一行 | 0 | walk_down | 下／正面 | 从左往右 0～7 |
| 第二行 | 1 | walk_left | 左／左侧面 | 从左往右 0～7 |
| 第三行 | 2 | walk_right | 右／右侧面 | 从左往右 0～7 |
| 第四行 | 3 | walk_up | 上／背面 | 从左往右 0～7 |

默认 10 FPS、循环；一轮 0.8 秒。不要在结尾再追加第 0 帧，否则会形成重复停顿。AtlasTexture.region 为 Rect2(列×128, 行×128, 128, 128)，filter_clip=true。

## 制作流程与容易出错的地方

1. 先锁定人物、装备和服装，再分别生成正面、左右侧面、背面，并要求脚部参与走路，避免只有披风晃动。破军按用户补充参考图更新为年轻无胡须、棕红刺发、黑金盔甲、红披风、手持宽刃大剑。
2. 用内置 imagegen 生成与定向修订。首批提示词保存在 image/role/walk_4dir_review/prompts.json，破军参考图修订提示词保存在 pojun_reference_v3_prompt.md；原始图和修订图均保留在各人物的 source 目录。
3. 检查持武器手：正面屏幕左侧与背面屏幕右侧对应人物自身右手，不能四个方向都简单保持同一屏幕侧。霜语选修订版正面、原版侧面及背面，纠正持杖手不一致的问题。破军宽刃剑在四方向均保持双手低位持握，没有背剑或攻击光效。
4. 去除生成图烘焙的棋盘格背景，保留白发、白袍及轮廓。仅清除不属于人物的极小孤立背景残点。
5. 原始生成图不能盲目等分：穿杨的一个脚尖靠近名义行边界；新版破军右向行的一处剑尖与下一帧披风在水平投影上重叠。优先沿真实透明间隙提取；投影重叠的行按连通人物轮廓归属提取，再装入标准格，防止切掉脚尖、剑尖、枪尖和披风。
6. 每个人全部 32 帧使用同一个缩放比例，不逐帧拉伸、不分别撑满格子。统一脚底基线 y=120，水平方向按完整剪影居中；格内留透明安全区。
7. 生成 Godot 4 SpriteFrames 资源、逐帧编号检查图、循环 GIF，并运行真实引擎的资源与移动测试。

可重复执行：在项目根目录运行 python tools/pack_walk_sheets.py。源图选择记录为 image/role/walk_4dir_review/selected_sources.json。

## Godot 中的使用

最快方式：给 AnimatedSprite2D 的 Sprite Frames 属性直接加载上表对应的 .tres。

手动切图：新建 SpriteFrames → 添加对应 walk 动画 → Add frames from Sprite Sheet → 选择最终 PNG → Horizontal=8、Vertical=4 → 只选择对应方向的一整行 → 按左到右添加 → Speed=10、Loop 开启。参见 [Godot 官方精灵动画教程](https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html)。

使用 Nearest 纹理过滤，不开启 mipmaps；PNG 保留透明，使用无损导入。不要把带文字的 QA 检查图当成游戏素材。

角色节点位置表示地面脚底点。预览实现采用 AnimatedSprite2D.centered=false、offset=Vector2(-64,-120)，碰撞区域仅放在脚底附近，而不是把头部、披风和武器都塞进碰撞框。AtlasTexture 的裁剪设置参见 [官方 AtlasTexture 文档](https://docs.godotengine.org/en/stable/classes/class_atlastexture.html)。

移动必须改变 CharacterBody2D 的位置，不能只播放原地动画。velocity 使用像素／秒，调用 move_and_slide()，不再乘 delta；使用 Input.get_vector 归一化斜向输入。预览按实际位移速度调节动画 speed_scale，停止或顶住边界时停止播走路。参见 [CharacterBody2D 官方文档](https://docs.godotengine.org/en/stable/classes/class_characterbody2d.html)。

## 可直接运行的移动预览

打开 src/preview/WalkSpritePreview.tscn，按 F6 运行。点击人物按钮或按数字 1～4 选择角色，方向键移动；另三个人物保持静止。

预览独立于现有创建角色和主页场景，没有替换旧 idle 图片，也没有改变主场景。默认基础速度 60 像素／秒，应用现有角色速度倍率；正式接入地图时，可按格子大小与视觉步幅再调速度。

## 核对结果与边界

128 帧逐张查看了带编号的检查图，核对朝向、完整脚部、装备位置、透明边界与相邻姿态；详细表见 image/role/walk_4dir_review/qa/frame_review.md。technical_checks.json 记录每帧原始裁剪区域、最终包围盒和图像哈希。

Godot 4.7.2 测试输出：WALK_ASSETS_OK: 128 atlas frames; four roles x four movement directions; stop and diagonal normalization verified.

通过资源加载、精确 Atlas 区域、四人×四方向实际位移、停止播放和斜向速度测试；独立预览场景也通过启动检查。测试环境对用户目录日志／证书访问存在限制，但本次资源和移动断言均执行完成、退出码为 0。

这些是可切块、可驱动实际移动的 Q 版行走素材。AI 帧之间仍有少量发梢、衣纹和装备细纹变化；逐帧检查和引擎测试不等同于严格的骨骼步态／脚底锁定校准，不应宣称完全零滑步。此批不包含攻击、跑步或受击动画。
