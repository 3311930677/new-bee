## 二、每轮做了什么

### 轮次 19 · 先把「测试可信」这件事做出来

- 重写 `tools/run_regression.ps1` 的判定口径：退出码 + 本用例自己的完成行 + 错误模式 + 墙钟超时 + 真实存档未改，五重判定；未知筛选 / 零项 / 用例数不符 / 引擎版本不符一律非零退出。
- 新增 `tools/selftest_regression.ps1`：用伪引擎 `.cmd` 做 11 项故障注入（先 OK 后 SCRIPT ERROR、OK 但退出码 1、无完成标记、卡死超时……）。
- `verify_data` / `verify_walk_assets` 从 `assert + quit(0)` 改为显式失败计数。
- **顺带修掉两个真实缺陷**：`G._veil_viewport_size()` 在节点未入树时刷 7 条引擎错误；`SettingsPanel.do_import` / `G._load_save` 解析非法 JSON 时刷引擎红字（新增 `G.json_parse_silent`）。
- 新内容：**演武连胜之证**（胜 +1 / 败清零 / 平局与撤退不清零 / 满 3 连胜发荣誉 / 段位分加成），数值进 `data/arena.json`。

### 轮次 20 · 抽卡保底与商店校验

- **#19**：十连整批补发高品质后**未清零保底计数**——补发之后计数还挂着 10，下一次连抽会再白送一张高品质。抽出确定性内核 `roll_batch_with(n, rng)` 与 `_decide_rarity` 钩子，补发后清零。
- **#20**：`shop_items()` 改为校验后货架（未登记 / 缺价 / 0 / 负 / 字符串 / 非整数 / 空 id / 重复 id 全部下架），`shop_price` 不再 `max(1,…)` 兜底，`shop_buy` 独立再校验，`ShopPanel._make_row` 不兜底。
- 新内容：**图鉴收集里程**（2/4/6/8 只四档，奖励魂晶/荣誉/经验/道具），数值进 `data/codex.json`。
- **故障注入**：注释掉清零行 → `VerifyGacha` 报「实为 10」，确认用例抓得住。

### 轮次 21 · 存档完整性与成长口径

- **#39**：新增 `src/save/SaveData.gd`——版本闸门 + 逐版迁移（v1→v2→v3）+ 幂等归一化 + 语义校验 + 备份（保留 3 份）+ 原子写盘。导入严格拒绝；启动遇未来版本先备份原档再兼容读取（不再"用默认档顶掉玩家进度"）。新增 6 个存档 fixture 与 `VerifySave` 用例。
- **#24**：未来时间水位按显式容差（6 小时）识别，导入拒绝、启动备份提示，边界（±0 与 +1s）有专门用例。
- **#29**：暴击改回 `base.crit + per_level×(lv-1)`（穿杨因此 **+2%**，其余 -0.001，前后对照见日志）；经验公式改读 `growth.json` 的 `exp.type` + 参数，**不执行表里的字符串**。
- 新内容：**出征补给**（加带药剂，金币只在出征时结算，返回不扣钱）。

### 轮次 22 · 可见缺陷（界面布局与刷新）

## 三、修复清单（按影响）

**会真的坑到玩家：**

1. 十连补发高品质后保底不清零 → 保底被重复兑现（#19）
2. 导入存档没有版本闸门/校验/备份/原子替换 → 一个坏档或未来版本档就能冲掉玩家进度（#39、#24）
3. 装载进度条永远满格（#1）
4. 装备表有 15 种宝石，界面只列前 6 种（#4）
5. 称号组内第 5 条起被裁掉且无法滚动（#2）
6. 详情弹层没有 owner，面板关掉后弹层成为孤儿；ESC 穿透关掉底层面板（#6）
7. 演武傀儡缺素材，战斗里退化成红色程序圆体（#41，轮次 19 接线 + 缺图断言）
8. 穿杨的暴击被写死公式吃掉 2%（#29）
9. 扫荡先扣券再算收益 → 表配坏时白掉一张券（#37 附带）
10. 怪物顶着障碍无限抖、撤退也救不了（#23）

**看起来没事但会静默出错：**

11. 回归脚本会误报全绿（#42）——这是本轮投入最大的一项，后面所有修复都依赖它可信
12. 非法商品价格兜底成 1（#20）
13. 节点未入树取树刷引擎错误 / 非法 JSON 刷引擎错误
14. 委托卡文字绕过卡片内边距并互相压字（#13）
15. BOSS 层号与扫荡构成写死（#37）
