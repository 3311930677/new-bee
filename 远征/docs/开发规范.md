## 1. 每次开发会话 SOP（强制工作流）

### 1.1 会话开始（开发前）

```
1. git pull --rebase origin main          # 拉取最新代码（rebase 保持线性历史）
2. git status                             # 确认工作区干净（有脏文件先处理再开工）
3. 读本文档 §2~§6 + 当次任务对应的设计文档章节
```

### 1.2 开发中

- 小步提交：每完成一个可验证单元（一个系统/一个界面/一批素材）即 commit 一次，不攒大包
- 遵守 §3 Git 规范、§4 代码规范、§5 素材规范
- 改设计口径（数值/规则/id）必须同步改文档——**文档即真相源，代码是文档的实现**

### 1.3 会话结束（开发后）

```
1. 自验证（§6 验证清单全过）
2. git add <具体文件路径>                 # 禁止 git add -A / git add .（防误提交生成物与密钥）
3. git commit -m "<type>(<scope>): <中文描述>"
4. git push origin main                   # 上传 GitHub
5. git status                             # 确认 clean + ahead 0
```

## 2. Git 规范

- **主分支**：`main`，单人开发直推；大功能（PVP/联机）可开 `feat/*` 分支，完成后 rebase 回 main
- **提交信息**：Conventional Commits + 中文描述，例如：
  - `feat(battle): 新增 DamageCalc 伤害公式与三组单测断言`
  - `fix(gacha): 保底计数跨池串号，改按池独立累计`
  - `assets(role): 补穿杨待机/移动/攻击三组帧序列`
  - `docs(spec): 玩法文档 v1.3 对齐提示词总库`
- **禁止**：
  - force push main；跳过 hooks；`--no-verify`
  - 提交 `.godot/`、`*.tmp`、导出产物（apk/exe）、密钥/账号类文件
  - 提交前不跑验证清单就 push
- **`.gitignore` 维护**（仓库根需补一份，远征/ 子目录已有）：发现新垃圾文件类型时**当次**追加进 ignore，不留到下次
- **冲突处理**：pull --rebase 冲突时，逐文件确认设计口径以 docs 最新版为准，解决后 `git rebase --continue`
- **大文件**：音频/视频/大图（>5MB）先评估；素材 PNG 按提示词规格生成（最大 512×512）正常入库

## 3. Godot 4.7 工程规范

### 3.1 引擎与渲染（不可变，已定稿）

| 项 | 值 |
|---|---|
| 引擎版本 | Godot 4.7.x（project.godot `config/features=4.7`） |
| 渲染器 | Compatibility / GLES3（`gl_compatibility`，桌面与移动一致） |
| 画面 | 480×800 竖屏，stretch=`canvas_items`，默认纹理过滤=nearest（像素完美） |
| 物理引擎 | Jolt Physics（工程默认，纯 2D 项目仅物理区用到时注意） |
| 主场景 | `res://src/main/Main.tscn` |
| Autoload | `G`（`src/autoload/G.gd`，主题/字体/共享状态/UI 工厂） |

### 3.2 目录结构（固定，新文件按此归位）

```
远征/
├─ project.godot / icon.svg
├─ src/
│  ├─ autoload/    # G.gd 及后续全局单例（DataManager 等）
│  ├─ main/        # Main.tscn 场景根
│  ├─ ui/          # 界面场景（Login/CreateRole/GameHome/Title...，.gd+.tscn 同名成对）
│  └─ battle/ ...  # 后续按系统建子包（combat/map/gacha/...）
├─ data/           # JSON 数据表（roles/skills/traits/... 共 14+ 张，DataManager 统一加载）
├─ image/          # 运行时引用的素材（按提示词 id 命名分目录：role/monster/ui/...）
├─ assets/         # 原始/源素材（source 母图、字体；不直接被场景引用）
├─ tools/          # 素材处理脚本（normalize_sprite_sheet.py 等）
├─ docs/           # 设计文档（本规范+玩法+提示词+素材清单）
└─ tests/          # GDScript 单测（DamageCalc/TTK 模拟等，后续建立）
```

### 3.3 GDScript 2.0 代码规范（核心，写代码前过一遍）

**命名**：
- 函数/变量/信号/参数：`snake_case`
- 常量：`SCREAMING_SNAKE_CASE`；类名/节点类：`PascalCase`
- 私有成员前缀 `_`；信号回调 `_on_<对象>_<信号>`（用 `@onready` + `connect`，Godot 4 不用 `_on_` 自动连接）
- 布尔变量/函数用 `is_`/`has_`/`can_` 前缀

**类型（静态类型强制）**：
- 所有函数签名标返回类型：`func _ready() -> void:`；无返回必须 `-> void`
- 变量优先 `:=` 推断；容器/参数显式标注：`var roles: Array = []`、`hp: int`
- 临时循环变量可省略类型，其余一律有类型
- JSON 解析结果先 `is` 判型再取用（参考 G.gd `_load_roles()` 的 `parsed is Array` 写法）

**语法与习惯**：
- `@onready var x := $Path`（禁止 `_ready` 里 get_node）
- 字符串优先 `String` 拼接 `%` 或 `format()`；数值转显示统一 `str()`/`snappedf()`
- 错误处理：**加载失败/表缺失用 `push_error`，降级可用 `push_warning`**；`print()` 只允许出现在临时调试，提交前删净
- 随机数：战斗内必须走种子 RNG（`RandomNumberGenerator.seed`，PVP 确定性铁律）；局外（抽奖）独立 RNG 实例并存档状态——**两套随机源严禁互串**
- 定时用 `await get_tree().create_timer(x).timeout` 或 Timer 节点；帧循环逻辑统一 `_process(delta)`/`_physics_process(delta)`，战斗 tick 固定步长独立实现（§玩法 2.1）

**UI 铁律**：
- 一切 UI 控件走 `G.gd` 工厂（`gold_label`/`menu_button`/字号阶梯 13/16/18/22/30/56），**禁止随手调参/自建配色**
- 文字一律程序渲染（Label），**严禁把文字烧进图片素材**
- 主题色只用 G.gd 常量（BG_DEEP/PARCHMENT/GOLD...），新颜色先进 G.gd 注册再引用

**场景/资源**：
- `.tscn` 优先编辑器生成；手改仅限 uid/引用路径修复，改完必须打开编辑器验证
- 贴图引用统一 `res://image/...`；`assets/source` 母图不被运行时引用
- 新 autoload：先在 project.godot 注册并确认加载顺序（G 最先）

### 3.4 数据表规范

- 一切数值/配置进 `data/*.json`，**代码里不写魔法数值**（数值调平只动表）
- 表加载统一走 `DataManager`（待建）：启动时全表校验，缺表/字段错 `push_error` 并降级空表
- id 命名与提示词总库严格一致（`zs_lieshan`/`pet_frostwolf`/`gem_atk_3`...），**新增 id 先入总库再写代码**
- JSON 格式：UTF-8 无 BOM，2 空格缩进，禁止尾逗号

## 4. 素材工作流（生成 → 抠图 → 切分 → 入库）

### 4.1 流程总览

```
提示词总库复制提示词 → AI 生图（Seedream/SDXL）
→ 背景去除（remove.bg 等，见 4.2）
→ 边缘清理（tools/clean_sprite_edges.py，见 4.3）
→ 尺寸/透明校验（4.4）
→ sprite sheet 切帧（tools/normalize_sprite_sheet.py）
→ 按提示词 id 命名入库 res://image/<类别>/ → Godot 导入(.import 自动)
→ git add 入库
```

### 4.2 抠图工具（按素材类型选）

| 工具 | 地址 | 适用 | 注意 |
|---|---|---|---|
| **remove.bg** | `https://www.remove.bg/zh` | 大图：人物母图 512、NPC 立绘、坐骑、卡面 | 免费 1 张/次需预览质量；AI 抠边可能软/破硬边轮廓 |
| remove.bg API / 桌面版 | 同上（付费批量） | 批量 30+ 张时 | 项目量大再买，前期手动够用 |
| **rembg（本地 CLI）** | `pip install rembg` → `rembg i in.png out.png` | 批量去背，离线 | 同为 AI 抠图，像素图慎用 |
| GIMP/Photoshop 阈值抠图 | — | **像素小图/icon（≤128px）首选** | 阈值选色→alpha，保住硬边轮廓不糊 |
| Aseprite/像素软件手动抠 | — | 24~32 色像素图兜底 | 最保真，量小用 |

**关键约定**：像素风素材（tile/icon/精灵帧）的深棕硬边轮廓是风格锚点——**remove.bg 类 AI 抠图会平滑边缘破坏像素感，小图一律阈值/手动抠**；remove.bg 只用于 512 级大图（母图/立绘/整幅卡面），且抠完检查轮廓是否被软化。

### 4.3 边缘清理（tools/clean_sprite_edges.py，AI 抠图后必跑）

AI 抠图/棋盘格去除后常见三类残留，该脚本一次处理：

1. **半透明毛边**（0<alpha<255）→ 硬二值化（≥128 保留，其余清空），像素风必须硬边
2. **封闭棋盘格残留**（被角色包围、边界 flood fill 够不着的灰格）→ 迭代洪泛 + 孤立中性色腐蚀
3. **浅灰白边光晕**（贴透明边的不透光浅灰像素）→ 用内部邻居颜色重绘（decontamination），白色内容（如霜语白发）因邻居同色不受影响

用法：`python tools/clean_sprite_edges.py <png>...`（原地处理）。验收：分析指标 semi=0、残留灰格≈0，且在**深色背景**上目检无光晕。

### 4.4 入库校验（每张必查）

- [ ] 透明背景（PNG-32，边缘无白/黑杂边）
- [ ] 尺寸与提示词规格一致（48/64/96/192/256/512 档）
- [ ] 帧序列：帧数=提示词声明、等宽、横向排布
- [ ] 文件名 = 提示词 id + `.png`（如 `sk_zs_lieshan.png`、`gem_atk_3.png`）
- [ ] 目录按 §3.2 归位（`image/role/zs/`、`image/ui/`、`image/monster/`...）
- [ ] Godot 打开后 .import 生成且纹理过滤=nearest（默认已设）
