# 《远征》开发方案 v6（Godot 4.7.2 + 4人物 + 实时PVP 版，定稿）

> **For agentic workers:** 本方案按里程碑拆分为可勾选任务（`- [ ]`），每个任务含目标/文件/验收标准，可逐条执行、逐条验证。

**Goal:** 竖屏中古 Roguelite「远征」（路线图 + 深度词条构筑 + 半自动策略战斗），配 6 线养成、实时PVP（1v1/2v2/3v3）与轻社交，**可玩性与复杂度向原版《战场女神》看齐**，难度保持低挫败。

**Architecture:** Godot 4.7.2。PVE 战斗全本地结算；PVP 战斗确定性模拟 + 自建轻量房间服务帧中继；账号/云存档/社交走自建服务端接口。数据全部 JSON 表驱动。

**Tech Stack:** Godot 4.7.2 GDScript 2.0（Compatibility 渲染器/GLES3，竖屏 480×800，viewport `canvas_items` + integer 缩放实现像素完美）/ JSON 数据表 / 本地存档 / WebSocket(wss) / 自建对战服务（PVP 房间中继，独立轻量进程）。kunlun 遗留解析脚本（GDScript 3.x 写法）需一次性适配 GDScript 2.0。

**设计总纲：复杂度敞开加，挫败感继续克制。** 失败无惩罚、负面词条仅 15% 且可选、装备强化失败不掉级、局外永久成长。

## 1. 设计定稿

### 1.1 核心循环

```
局内(远征,一局5-10分钟): 选节点→战斗→三选一词条→…→BOSS→结算
局外(世界):            6线养成→变强→挑战更高层 + 社交
竞技(PVP):            1v1/2v2/3v3 实时对战→积分/段位→赛季榜与奖励
接口: 远征产出养成材料；局外战力决定可挑战层数；已通关层可扫荡(70%收益)
```

低挫败机制：赢输都有材料 / 局外永久成长 / 双刃词条可选不选 / 连续失败 3 次保底礼包。

### 1.2 战斗系统（半自动深化，定稿）

**形态**：自动普攻 + **5 技能手动** + 一键全自动托管。"技能是加速器"原则升级为"用多少脑赢多漂亮"：不操作能通关，好操作通关更快、更华丽（连击/处决加分）。

**属性（8 项）**：HP、ATK、DEF、SPD（普攻间隔）、CRIT（暴击率）、能量、技能 CD、控制抗性（降低被控概率）。无命中/闪避、无物法分离（状态效果全部走控制抗性结算）。

**布阵（策略核心）**：战场 20 站位（5 列×4 排，敌我各半场 5×2，靠中线一排为各自前排）。**近战只能命中对方前排**（远程可打后排）——站位的策略意义完全复刻原版回合制。位移词条/技能可改变站位。**显示分层**：PVE 单人局战场 UI 紧凑呈现（只高亮有单位区域，格子逻辑不变）；PVP 按模式扩展显示（1v1 紧凑 / 3v3 全场）。

**人物（4 名，定稿）**：破军（近战物理，能抗能打）、穿杨（中远程物理输出）、霜语（远程群伤+控制）、晨星（治疗辅助，可独立打架刷怪）。内部 id：破军=zs、穿杨=ck、霜语=fs、晨星=fz（对齐 kunlun 特效目录）。作战时可出战 1 名 + 宠物 1 只；PVP 中人物即出战单位（1v1/2v2/3v3 按人数上阵，宠物随人物参战）。

**技能规格**：每人物 **5 技能**（20 个，4 人物×5；k=攻击倍率/cd=秒/cost=能量；晨星治疗类按 HP%+ATK 系数结算；技能 id 规则 `{人物id}_{拼音}`）：

| 人物 | # | 技能 | k | cd | cost | 附加 |
|---|---|---|---|---|---|---|
| 破军 | 1 | 裂山 | 1.5 | 5 | 20 | 单体 |
| 破军 | 2 | 破阵 | 1.2 | 9 | 25 | 目标 DEF −20%×5s |
| 破军 | 3 | 回风斩 | 0.8 | 12 | 40 | 前排全体 |

| 穿杨 | 2 | 贯甲 | 1.0 | 8 | 25 | 目标 DEF −15%×5s |
| 穿杨 | 3 | 夺魄 | 2.0 | 12 | 40 | 后排单体（无视前排） |
| 穿杨 | 4 | 遁影 | 0 | 10 | 20 | 自身"潜伏"3s（受击减半） |

| 晨星 | 5 | 破晓 | 0 | 18 | 60 | 全体无敌 1.5s + 回复 8%MaxHP |

**技能连携**：特定顺序触发额外效果（例：破军 破阵→断罪 k 额外 +1.0；霜语 霜环→天陨 对减速目标 +30%；晨星 祝祷→破晓 治疗量 +30%）。连携表进 `combos.json`。

**状态效果（15 持续 buff + 2 即时效果，从原版 55 种摘核心）**：
- **持续 buff（15）**：流血、中毒、定身、混乱（随机目标 50% 伤害）、减速、破甲、嘲讽、恐惧、潜伏（受击减半）、反震、吸血、护盾（伤害吸收层）、无敌、免死（锁 1 血）、复活——有"创建时机/触发时机/层数上限/控制抗性"字段，走 BuffSystem 生命周期，结构沿用原版 buff 设计。
- **即时效果（2）**：斩杀（目标低于阈值直接处决）、驱散（即刻移除指定状态）——走技能结算管线，不进 buff 生命周期。

**战斗内操作**：5 技能条 + 换宠按钮（宠物 60s CD、附赠一次死亡保护）+ 托管开关。

**能量**：普攻 +20，上限 100 → 约每 4~6 秒一个决策点。
**前摇**：0.3~0.5s（掩盖未来联网延迟 + 打击感）。
**战斗时长**：普通 15~40s，精英 40~70s，BOSS 60~120s。

**伤害公式**（沿用寻秦饱和函数）：
```
伤害 = ATK² / (8 × DEF + ATK)    # 暴击 ×1.5；下限 1
```
**成长公式**（等级上限 60）：
```
升到 lv+1 经验 = lv×100 + 2×5^(0.1×lv)    # lv 1~60
HP = 100 + 40×(lv−1)   ATK = 20 + 4×(lv−1)   DEF = 10 + 2×(lv−1)   CRIT = 5% + 0.1%×lv
```
> 注：ATK 增速为 DEF 两倍，同级对战 TTK 会随等级变长——开工前先跑 1/10/30/50 级 TTK 模拟（见阶段 1.8），若曲线不合预期再调 DEF 系数或公式，不拍脑袋。

### 1.3 词条系统（40 条 + 六流派，深度核心）

**稀有度四档**：白(16)/蓝(12)/紫(8)/金(4)，紫金为机制型。

**六流派 + 标签**：流血 / 暴击 / 反伤 / 控制 / 能量 / 召唤。**同流派 ≥3 条触发"流派效果"**（例：反伤流 3 件 → 反伤伤害翻倍 + 反伤时回血）。

**双刃词条 15%**（可选不选，作复杂度不作难度）：
| 词条 | 收益 | 代价 |
|---|---|---|
| 燃血 | ATK +40% | 每秒掉血 1% |
| 薄甲 | 伤害 +30% | DEF −20% |
| 狂潮 | 技能 CD −30% | 技能消耗 +50% |
| 死线 | HP<20% 时无敌 3s | 战斗结束 HP 固定上限 60% |

**代表词条（全 40 条分布）**：
- 数值系（12）：锋锐/铁壁/疾风/狂怒/巨力/轻身/坚壁/锐眼/血牛/魔涌/神速/不灭
- 机制系（16）：流血/中毒/荆棘/吸血/蓄势/护盾/时停/回响/斩杀/处决重置/蓄能/奥术涌动/破甲深化/恐惧光环/连携强化/召唤物强化
- 流派联动系（12）：各流派 2 条（淬毒/血怒/收割/感电/震爆/铁幕/控场/冰心/通量/超载/唤灵/支配）

**获取规则**：三选一 = 1 数值或机制 + 1 流派联动或双刃 + 1 随机；战斗内词条面板可看；篝火可删 1 条。

### 1.4 路线图与内容模式

- 一局：起点 → 3 层（各 3 选 1）→ BOSS。
- 节点权重：普通 40 / 精英 15 / 事件 15 / 宝箱 12 / 商店 8 / 篝火 10；保底：第 2 层 ≥1 精英，每局 ≥1 事件、≥1 商店。
- 精英：怪物挂 1 随机词条，必掉 1 词条；精英词条池独立（怪物侧）。
- 难度：第 N 层怪物全属性 ×(1+0.12N)。
- **深渊模式**：25 层，BOSS 带随机词缀组合（2 条），通关进排行榜。
- **无尽模式**：无限层，冲榜用。
- **每周轮换**：词条池每周轮换 50%。
- 扫荡：已通关层一键扫荡，70% 收益。

### 1.5 局外养成（6 线，定稿）

1. **等级 + 天赋树**：每 5 级 1 点，三系（暴击/生存/技能），各 10 节点——build 方向主来源。
2. **装备**：强化（每级 +10%，成功率 `0.9^级`，失败不掉级）+ **精炼**（随机词条洗练，4 条可洗，锁定需消耗）+ 宝石镶嵌（3 色 × 5 级）+ **外观随 ATK 自动升阶 ≥3 档**（纯表现，不加属性）。
3. **宠物**：完整线——资质/成长率/突破/进化/吞噬/技能学习/参战（1 只）。
4. **技能书**：20 技能统一入池（4 人物×5），各人物解锁/升级本系 5 技能（远征币），每级 k +5% 上限 10 级，重置返还部分消耗；宠物技能学习走宠物线。
5. **坐骑**：6 类（素材现成），升阶 + 属性 + 战斗内移速/出场特效。
6. **称号/成就**：探索/战斗/收集三类成就，称号属性微加成。

**货币 4 种**：金币（通用）/ 远征币（技能书/精炼）/ 灵魂石（宠物线）/ 荣誉（称号）。**砍掉**：经脉/星魂/帮派/交易/种菜/藏宝图/师徒/擂台/法宝/护符/神符。

### 1.6 实时PVP（1v1/2v2/3v3，定稿）

**模式**：1v1 单排；2v2/3v3 支持组队（房间邀请好友，缺位由匹配补齐）。每场 120s，超时按剩余血量 % 结算；一方全员倒下即负。

**平衡（双模式，定稿）**：
- **排位赛——完全公平**：人物/技能带入，**装备/宠物数值全部归一化**（按基准属性表拉平，仅保留外观差异），局内词条与宝石不生效。段位/赛季只统计排位。
- **休闲赛——战力带入**：装备/宠物数值生效，局内词条与宝石仍不生效；开局属性差超 20% 时向低方补偿 10%。
- 排位积分与战力数值彻底解耦，杜绝"氪/肝数值压排位"。

**同步方案（锁步帧同步）**：
- 战斗逻辑本地确定性模拟（复用 PVE 的 DamageCalc/BuffSystem/SkillSystem，随机数全部走可复现种子，固定步进）
- 客户端以 15 帧/s 上传操作输入，服务端按帧序广播；本地预测 + 帧回滚兜底
- 服务端职责：匹配池、房间生命周期、帧中继、掉线判定（>5s 判负/托管）、积分结算接口

**积分与赛季**：ELO（胜 +25 败 −20，±100 分段匹配）；段位：青铜/白银/黄金/铂金/钻石；每 4 周一赛季，赛季榜 + 荣誉/远征币奖励。

**UI**：PVP 大厅（三模式入口 + 组队房间）→ 匹配 → 战前阵型（各自半场 5×2 布位，人物+宠物站位自选）→ 战斗（5 技能 + 宠物，禁用托管）→ 结算（积分/段位变化）。

### 1.7 社交（阶段 5）

账号登录 / 云存档 / 世界聊天 / 好友 / 排行榜（远征层数+无尽+PVP 三榜）/ 异步组队（借队友镜像 AI）。走自建服务端接口。

### 1.8 运营活动（预留入口，框架先行）

**定位**：首期不做完整活动体系，只留"活动中心"入口 + 配置驱动框架；后续运营活动（签到、限时副本、兑换、节日活动、PVP 活动赛等）全部通过线上配置增量发布，全程无需更新客户端包体。

**首版范围**：
- 主界面常驻"活动"入口：红点提示 → 活动列表 → 单活动页，三级结构
- 活动配置线上化：服务端下发活动列表（id/类型/起止时间/标题/图/奖励项），客户端按类型渲染，未知类型安全降级隐藏
- 内置 2 个占位模板验证发布链路：登录签到、限时兑换（远征币/荣誉）
- 活动进度/领奖状态存本地存档（`act_progress`），并随账号云存档一致

**发布链路**：GM 后台改配置 → 客户端拉取 → 活动上线/下线/调期，不碰代码不发包。

### 1.9 NPC（轻量剧情脸，节点挂载）

**定位**：不做可走动世界；NPC 只作节点/入口的"剧情脸"——半身立绘 + 对话气泡，给纯菜单交互加氛围，成本极低。

**名单（10~12 个，首批 3 个）**：
| NPC | 挂载点 | 首批 |
|---|---|---|
| 旅行商人 | 商店节点 | ✅ |
| 铁匠 | 篝火节点（删词条/重铸的化身） | ✅ |
| 信使 | 主界面公告/活动中心红点化身 | ✅ |
| 神秘旅者 | 事件节点通用脸 | |
| 被困村民/流浪骑士/占卜师/深渊教徒 | 事件节点专属 | |
| 深渊看门人 | 深渊模式入口 | |
| 竞技场主持 | PVP 大厅 | |

**规格**：每人 1 张半身立绘（对话弹出）+ 1 头像；个别关键 NPC 加待机 2~4 帧。不做分支剧情树（事件节点本身已有选项逻辑），台词池随机轮换。

**数据**：`npcs.json`（id/名字/立绘/台词池/挂载点），加 NPC = 加一条配置 + 一张图。

## 2. 技术架构

### 2.1 工程结构（新建独立工程）

```

  assets\                # ui / fx / role / monster / mount / icon
  data\                  # skills.json traits.json monsters.json nodes.json combos.json
                          # growth.json talents.json pets.json mounts.json achievements.json npcs.json
  src\
    autoload\            # G.gd DataManager.gd SaveManager.gd AudioManager.gd
    battle\              # BattleScene Combatant SkillSystem TraitSystem DamageCalc MonsterAI BuffSystem
    mapgen\              # RouteGenerator NodeResolver

    meta\                # Growth Talents Equip Pet Mount Achievement

```

### 2.2 核心模块职责

| 模块 | 职责 |
|---|---|
| `DamageCalc.gd` | 纯函数：伤害/暴击/破甲/抗性修正，可单测 |
| `BuffSystem.gd` | 15 种持续状态的生命周期（创建/触发时机/层数/抗性）+ 2 种即时效果（斩杀/驱散）管线——结构移植自原版 buff 设计 |
| `TraitSystem.gd` | 40 词条注册表 + 流派计数 + 钩子（on_hit/on_tick/on_kill/on_behit/on_skill） |
| `SkillSystem.gd` | 技能 CD/能量/前摇/连携检测（combos.json） |
| `Combatant.gd` | 战斗实体状态机 + 站位规则（前后排/近战打前排） |
| `MonsterAI.gd` | 目标选择（最低血/同排/后排）+ 技能循环 + 精英词条 |
| `RouteGenerator.gd` | 权重/保底生成路线图，纯数据可单测 |
| `TalentSystem.gd` / 养成各模块 | 6 线养成逻辑与 UI |
| `pvp/FrameSync.gd` | 锁步帧同步：输入帧收集/帧推进/追帧/hash 校验（确定性战斗复用 PVE 逻辑） |
| `pvp/MatchClient.gd` | 匹配请求、房间创建/加入、断线重连与超时判定 |
| `act/ActCenter.gd` | 活动框架：拉取配置、列表/详情渲染、按类型分发到模板、领奖状态跟踪 |
| `server/pvp_relay` | 独立进程：WebSocket 房间中继 + 匹配池 + 积分/榜单接口（Node 单文件部署） |
| `server/api` | 账号/云存档/活动配置下发/REST 接口 + GM 后台（活动发布入口） |

### 4.4 制作管线（母图锚点法）

1. **盘点建索引**：xaqd_png 206 张 + file.dat 清单 → `美术索引.csv`（只记录参考，不复制进工程）

## 5. 风险与对策（深度版 Top 6）

| 风险 | 对策 |
|---|---|
| 平衡爆炸（40 词条 × 6 流派 × 20 技能） | 数值全 JSON 化；AI 做 combo 校验与表格生成；流派效果只做"3 件套"一层 |
| 半自动 + 深度策略互相干扰（既要操作又要思考） | 托管兜底；"操作换效率"而非"操作换生存"；阶段 1 实机调 |
| 复杂度 ×1.5 的开发量 | 里程碑渐进不并行；每阶段验收过才进下一阶段 |
| PVP 帧不同步 / 作弊 | 战斗全确定化 + 帧 hash 抽查；属性快照云端校验；掉线判负 |
| 自建 PVP 服务端工作量被低估 | 服务端只做无状态中继（不承载战斗逻辑）；Node 单文件部署；先 1v1 竖切验证 |
