### 顺带修掉的两个真实缺陷（因为判定变严才浮出来）

1. **`G._veil_viewport_size()` 在节点未入树时刷 7 条引擎错误。** 父级还没 `add_child` 就调 `parent.get_tree()`，Godot 4.7 直接报 `ERROR: Parameter "data.tree" is null. at: get_tree (scene/main/node.h:559)`，并打出完整 GDScript 回溯（`TraitPicker.setup` → `MapScene._after_battle_rewards`）。已改为先 `is_inside_tree()` 再取树，拿不到就退回 480×800 基准。
2. **非法存档码会刷引擎红字。** `SettingsPanel.do_import` / `G._load_save` 用 `JSON.parse_string`，解析失败时引擎自己 push 一条 `Parse JSON failed`。玩家粘贴一段乱码就会看到报错。新增 `G.json_parse_silent()`（`JSON.new().parse()`，失败返回 `null`），这两处改走静默解析，由业务层给人类可读提示。

## 轮次 20 · B 批其一：抽卡保底与商店校验（#19、#20）

**主问题 #19：十连整批补发高品质后不清保底计数。** `GachaPanel._roll_batch` 里逐张保底会清零，但十连那条「整批至少一张史诗及以上」的补发分支替换末张后**没有清零**。后果是：十连白送一张紫/金之后，保底计数仍挂在 10（甚至更高），下一次连抽会**再白送一张**高品质——保底被重复兑现。

| 文件 | 改动 |

## 轮次 21 · B 批其二：存档完整性 + 成长口径（#39、#24、#29）

**主问题 #39：存档版本与迁移没有边界。** 原实现把迁移散落在 `G._load_save` 的字段赋值之间（`items.gacha_pity → prog.gacha.pity`），导入路径 `SettingsPanel.do_import` 只检查"是不是 JSON 对象"就把整份文本盖到存档文件上：没有版本闸门、没有结构校验、没有备份、没有原子替换。导入一个更高版本的档会静默丢字段；导入一个被写坏的档会直接把玩家存档冲掉。

### 改动

| 文件 | 改动 |
|---|---|
| `src/save/SaveData.gd`（新增，`class_name SaveData`） | 单一事实来源：`CURRENT_VERSION = 3`、`version_of`、`is_future`、**逐版迁移**（v1→v2 补顶层容器；v2→v3 搬 `gacha_pity`）+ 幂等**归一化**（对所有版本都跑，清掉残留在 v3 档里的历史字段）、**语义校验**（容器类型/钱包非负/道具非负/等级范围/`last_ts` 未来水位）、`load_payload`（启动路径，宽容但要报告 mode）、`import_payload`（导入路径，严格拒绝）、`backup_file`（带时间戳、保留 3 份）、`write_text_atomic`（临时文件 + 回读校验 + rename） |
| `src/autoload/G.gd` | `SAVE_VERSION` 改为 `SaveData.CURRENT_VERSION` 的别名（两处不再各写一个数字）；`_load_save` 走 `SaveData.load_payload`，新增 `last_load_report` / `save_backup_path`；**遇到未来版本的档先备份原档再按兼容方式读**（不再"只用默认值顶着"，那等于静默覆盖玩家进度）；删掉原来散在读档中间的保底迁移 |

### 顺带修掉的两处判定问题

1. **回归脚本的大小写误判**：PowerShell 的 `-match` 默认**不区分大小写**，错误模式 `_FAIL` 命中了 `SaveData._mig_fail` 这个函数名，把一次正常的 `push_warning` 回溯判成了失败。已全部改为 `-cmatch`（引擎错误字符串大小写固定，精确匹配更安全）。
2. **备份额度**：`write_text_atomic` 原先用"字节数 == 字符数"校验回读内容，存档里有中文（昵称/性别）时必然不等；改为直接比对回读字符串。

### 本轮新增可体验内容：出征「补给」

药剂本来是固定 2 瓶，玩家没有任何"为这趟远征花钱"的决策。现在出征筹备面板左下多了一枚「补给 +1」：

- 基础 2 瓶（`potions_base`），最多加带到 4 瓶（`potions_max`）；加带单价递增（第 1 瓶 180 金，之后每瓶 +120），全部写在 `data/nodes.json` 的 `run` 段。
- **金币只在点「出征」时一次性结算**：加带阶段不扣钱，按「返回」/取消更不扣钱——避免"买了药剂却没用上"的白花钱陷阱。
- 余额不足或超出上限时整单拒绝并给出中文原因，`_hint` 行直接显示。
- 出征配置里的 `potions` 随加带数量走，地图 HUD 的「药剂 ×N」立刻反映。

### #6 详情弹层的模态所有权

原实现（`G.show_info_popup`）：CanvasLayer 直接挂根节点、没有 owner、ESC 无人处理、也不参与 `ui_blocked`。由此产生两类真实故障：

1. 开着详情弹层按 ESC，ESC 穿到底下的面板把它关掉，弹层自己留在屏幕上；
2. 弹层的父面板被关掉后，弹层成为挂在根上的孤儿——点不掉、也没人能收。

改法：

- **模态栈**：`G._modals`（每项 `{id, layer, owner}`），栈非空即阻塞。
- **唯一释放路径** `close_info_popup(layer)` / `close_info_popup_by_id(id)`：遮罩点击、「知道了」、ESC、owner 退出四条路全走它，可重复调用。
- **ESC 只关栈顶**：`G._unhandled_input` 里处理 `ui_cancel` 并 `set_input_as_handled()`。G 是 autoload，输入传播上先于场景节点，所以底下的面板不会再收到这次 ESC。
- **owner 退出自动释放**：连接 `owner.tree_exiting`。闭包捕获的是**整数 id 而不是弹层对象**——捕获对象在对象释放后回调会打印 `Lambda capture at index 0 was freed. Passed "null" instead.`（第一版就踩了，被回归脚本抓出来）。
- **阻塞改成"并集"而不是布尔覆盖**：`ui_blocked` 变成属性（`get: 内部锁 or 模态栈非空`），30 处读法一字未改，`G.ui_blocked = true/false` 的写法也照旧——但关掉弹层不会再把转场/GM 的锁一起放掉。
- 顺手加了 `_prune_modals()`：栈里若有被别处释放的弹层，读数与关栈顶之前先清一遍，避免失效条目永久占着栈顶。

## 轮次 25 · E 批：怪物卡住与地图重绘（#23、#15）+ 称号内容扩充

### #23 怪物不再无限卡住

`_MapMonster` 用 `move_and_slide` 走位，被散件挡住时**速度仍然有值、位置却不动**，于是怪会一直顶着树原地抖；`retreat_home()` 又只改目标点，撞的还是同一个障碍，等于没救。

改法（全部基于**实际位移**，不靠速度/距离猜测）：

- 每帧比较"期望位移 `speed*delta`"与"实际位移"，实际位移低于期望的 35% 就累计卡住时长；有进展立刻清零（走得慢不会被误判成卡住）。
- 连续卡住 0.6s → 触发一次绕行：追击时沿"玩家方向"的侧向挪开（侧移点不往玩家接触圈里挤），游荡时随机换方向，绕行 0.5s。
- 连续绕行 3 次仍无进展 → 放弃当前目标：追击状态退回游荡、目标点回巢位。
- **不做穿墙传送**：位置永远由 `move_and_slide` 决定，只换目标点，不会出现"怪瞬移到玩家旁边"。
- `retreat_home()` 一并清掉绕行与卡住计数——否则它会带着上一段的侧移目标继续往障碍里顶，撤退就是空话。

### #15 小地图不再每帧重绘

`_update_nav()` 每帧调用并 `queue_redraw()`，而一次 `_draw` 要遍历怪物 / 拾取物 / 兴趣点 / 传送阵多个集合。改为：

- 位置类变化**节流到 ~10Hz**（`MINIMAP_INTERVAL = 0.1s`）；
- 事件类变化（拾取、击杀、用掉兴趣点、打开大地图）走 `_mark_nav_dirty()`，**下一帧立刻刷新**——节流不能让"点了却半天不变"。
- 罗盘（目标名 + 步数）仍每帧更新，它只是改几个 Label 文本，不是重绘。

⚠ **未做设备实测**：#15/#16 的验收口径是"同一设备、相同种子对照帧耗时 P50/P95"，夜里没有真机，也没有可重复的帧耗时基线。实现与防回退口径已落地，但**帧耗时的改善未经验证**，需要白天在目标设备上对照一次。
