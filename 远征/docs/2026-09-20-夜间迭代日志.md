## 轮次 19 · A 批：先把「测试可信」这件事做出来（#42、#38）

**主问题 #42：回归脚本会误报全绿。** 旧脚本三处硬伤：不检查进程退出码；把任意 `OK` 子串当通过；筛选到不存在的用例时 `0 items` 也打印 `ALL GREEN`。已实测复现。

### 改动

| 文件 | 改动 |
|---|---|
| `tools/run_regression.ps1` | 重写判定口径：①进程退出码必须 0；②必须出现该用例**自己的**完成行 `^<TOKEN>_OK`（不再子串猜）；③输出不得含 `SCRIPT ERROR`/`Parse Error`/`Compile Error`/`USER ERROR`/`Assertion failed`/`ERROR:`/`FAIL:`/`MISS:`/`_FAIL`；④墙钟超时（`--quit-after` 只是帧上限，卡死仍会退出 0）；⑤真实存档未被改写 |

### 顺带修掉的两个真实缺陷（因为判定变严才浮出来）

1. **`G._veil_viewport_size()` 在节点未入树时刷 7 条引擎错误。** 父级还没 `add_child` 就调 `parent.get_tree()`，Godot 4.7 直接报 `ERROR: Parameter "data.tree" is null. at: get_tree (scene/main/node.h:559)`，并打出完整 GDScript 回溯（`TraitPicker.setup` → `MapScene._after_battle_rewards`）。已改为先 `is_inside_tree()` 再取树，拿不到就退回 480×800 基准。
2. **非法存档码会刷引擎红字。** `SettingsPanel.do_import` / `G._load_save` 用 `JSON.parse_string`，解析失败时引擎自己 push 一条 `Parse JSON failed`。玩家粘贴一段乱码就会看到报错。新增 `G.json_parse_silent()`（`JSON.new().parse()`，失败返回 `null`），这两处改走静默解析，由业务层给人类可读提示。

## 轮次 20 · B 批其一：抽卡保底与商店校验（#19、#20）

**主问题 #19：十连整批补发高品质后不清保底计数。** `GachaPanel._roll_batch` 里逐张保底会清零，但十连那条「整批至少一张史诗及以上」的补发分支替换末张后**没有清零**。后果是：十连白送一张紫/金之后，保底计数仍挂在 10（甚至更高），下一次连抽会**再白送一张**高品质——保底被重复兑现。

### 改动

| 文件 | 改动 |
|---|---|
| `src/ui/GachaPanel.gd` | 抽出 `roll_batch_with(n, rng)` 作为**确定性内核**（随机源由调用方注入）；`_roll_batch` 只负责建随机源。整批补发成功后 `pity = 0` |
| 同上 | 新增 `_decide_rarity(rng, rates, pity, pity_max)` 钩子，把「该出什么稀有度」这一处决策单独暴露出来，测试可子类覆写 |
| `src/autoload/G.gd` | `shop_items()` 改为**校验后货架**：id 非空且已登记、价格为正整数（字符串/布尔/缺字段/0/负/非整数一律非法）、重复 id 只留第一条；非法的 `push_warning` 并**下架**，不再兜底成 1。新增 `SHOP_PATH`（var，测试可指向临时表）与 `shop_reload()` |
| 同上 | `shop_price()` 不再 `max(1, ...)`，未登记/已下架一律返回 0；`shop_buy()` 独立再校验一次（面板可以被绕过，购买接口是唯一入口） |
| `src/ui/ShopPanel.gd` | `_make_row` 去掉 `max(1, ...)` 兜底，价格非法直接不上屏 |
| `tools/VerifyGacha.gd` | 新增 14 节：脚本化子类 `ScriptedGacha` 覆写 `_decide_rarity`，**确定性**跑完四条保底路径——(a) 第 60 抽判定看到的 pity 必须是 60；(b) 自然出紫清零；(c) **全下品十连整批补发后计数必须清零**；(d) 批次里已有高品质时不得二次替换、末张不被替换、计数按逐张口径继续累计；(e) 计数挂在 `prog.gacha` 而非道具背包，超阈值计数按达阈值处理 |
| `tools/VerifyPanels.gd` | 新增 7.1 节：把「表被写坏」注进临时货架表——重复 id / 缺价 / 零价 / 负价 / 字符串价 / 非整数价 / 未登记 id / 空 id，断言全部下架且购买接口独立拒绝、钱包与背包零变化；随后合法条目仍恰好扣一次发一次 |

### 本轮新增可体验内容：图鉴「收集里程」

图鉴此前只有一行「已收集 N / 8」的计数，**收集本身没有任何回报**——多抽到的宠物除了炼金转金币就没有别的意义。现在：

- 新增数据表 `data/codex.json`：四档里程（2 / 4 / 6 / 8 只），奖励覆盖魂晶、荣誉、经验与道具（宠物粮、强化石、资质果、进化晶石）。
- 图鉴面板新增一行「收集里程」进度文案（三态：有可领的 / 下一档还差几只 / 全部领完）与一枚「领取」按钮（无奖励可领时压灰且不接点击）。
- 领取走 `G.codex_claim()`：存在 / 未领过 / 收集数达标，三者缺一即拒绝且**不做任何部分发放**；领完写入 `prog.codex_claimed` 并落盘（读档后不会重复领）。
- 全部数值落在表里，代码不写死。
