## 轮次 1｜进界面慢 + 按钮点不动（性能与输入手感的硬 bug）

**用户原始反馈**：「现在进入游戏界面很慢是为什么，然后返回按钮和一部分按钮经常失灵，检查按钮」

### 1.1 诊断（先量，再改）

写了一次性探针（`tools/_ProbeUI.gd`，用完即删）分别量「首次 / 二次」进入各屏的耗时，结论全在数字里：

| 观测项 | 数值 | 说明 |
|---|---|---|
| 素材索引全量扫描（336 项） | 4 ms | 不是瓶颈 |
| 加载页预热 275 张 ready 贴图 | 381 ms | 一次性，可接受 |
| 单件大图 `background/home.png`(1.5MB) | 23 ms | 不是瓶颈 |
| 单件 `bgm_home.ogg`(1.4MB) | 4 ms | 不是瓶颈 |
| **GameHome 首次进场景** | **533 ms** | ← 问题在这 |
| GameHome 第二次进场景 | 31 ms | 差值 500ms 全是一次性开销 |
| CityScene 首次 / 二次 | 212 / 113 ms | 同上 |
| 打开世界图志 / 图鉴 / 召唤 / 兑换 / 设置 / 养成（首次） | 121 / 87 / 79 / 25 / 13 / 31 ms | 每个面板首次都要付一次 |

**决定性实验**：把面板脚本逐个 `load()` 计时，再进场景 —— `GrowthPanel.gd` 148ms、`GameHome.tscn` 231ms、`RouteScene.tscn` 236ms（连带 MapScene/BattleScene）、`GachaPanel.gd` 52ms、`WorldPanel.gd` 41ms…**全部编译完后再进 GameHome 只要 56ms**。
结论：慢的不是贴图、不是音频、不是字体——是 **GDScript 的首次编译**，而且它被平摊到「玩家点进每个界面的那一帧」上，所以感知成「进界面很慢」。

**按钮为什么失灵**：金剑鼠标指针贴图 34×37，刃尖在左上 `(0,1)`，而热点写成了 `(4,33)`（那一点在贴图的透明空白处）。热点定义是「贴图的哪一点压在鼠标坐标上」，于是**整把剑被画到鼠标上方 32px**——玩家拿剑尖去点按钮，真实落点在剑尖下方 32px，38px 高的按钮正好被点空。这不是控件被挡。

顺带用命中测试（复刻 Godot 的 `gui_find_control_at_pos`）逐点验证，另有真死区：主城「出征」按钮左上角被摇杆的 124×124 命中区咬掉 7×26px、右下角被提示条咬掉 71×20px（合计约 78×26 的角部死区）。

### 1.2 本轮改动

| # | 类别 | 改动 | 文件 |
|---|---|---|---|
| 主 | 输入 | 指针热点 `(4,33)` → `(1,1)`（压在剑尖上），并写清为什么 | `src/autoload/G.gd` |
| 副 1 | 加载 | **加载页接管一次性编译**：新增 `PRELOAD_CODE`（主界面/主城/路线图 3 个场景 + 6 个面板脚本 + 创角/标题/登录）与 `PRELOAD_AUDIO`（6 首 BGM），连同贴图分帧预热；进度条按「贴图 + 脚本」总数推进 | `src/ui/LoadScreen.gd` |
| 副 2 | 输入 | 主城装饰层不再抢点击：城名横幅、等级签、操作提示条、摇杆左移 12px | `src/city/CityScene.gd` |
| 副 3 | 缓存 | `G.res_tex()` 加名称级贴图缓存（面板反复开关少几十次 `load()` 往返） | `src/autoload/G.gd` |
| 副 4 | 性能 | 主城暗角渐变 480×800 逐像素生成 → 120×200 + 线性过滤 | `src/city/CityScene.gd` |
| 副 5 | 工程 | 新增性能/按钮回归工具 `tools/VerifyPerf.gd/.tscn`（带预算断言 + 五点命中测试）；加载页加测试接口 `auto_advance` | `tools/`、`src/ui/LoadScreen.gd` |

### 1.4 验证

- 13 项 headless 回归全绿：`VerifyAssets / VerifyBattleScene / VerifyCity / VerifyGameHome / VerifyMapScene / VerifyRouteScene / VerifyGacha / VerifyPanels / VerifyGrowth / VerifyPerf` + `verify_data / verify_battle / verify_route / verify_trait / verify_walk_assets`。
- 截图复查：`city / city_built / home` 三张人工过目——NPC 全身立绘、暗角平滑无带状、提示条不再压住主按钮。
- 回归守卫：`VerifyPerf` 把预算写死成断言（主界面 200ms、主城 250ms、浮层 130ms、二次打开 70ms），今后谁再把一次性开销放回「点进界面那一帧」就会红。

### 1.5 未解决 / 风险

- 世界图志首次打开仍要 ~119ms（8 张 SlideCard 一次性建完）；正解是 PageDeck 按需建卡（用到才建），排进后续轮次。
- 主城 113ms 里大头是 480 格 `TileMapLayer.set_cell` 与 8 个 NPC 节点，属结构成本，暂不优化。
- **音效目前是空的**：`assets/audio/ui_click.wav` 在本次会话的工作区里是「已删除」状态（未提交），所以 `Audio.sfx("ui_click")` 静默无输出，按钮无点击声。按用户此前意图不擅自恢复，改为后续轮次统一做一套克制的 UI 音效（CC0 或程序合成）。

### 1.6 下轮计划（轮次 2）

轮次 2 主问题：**核心玩法的「剧情背景」缺失**——现在从创角直接进主城，世界/秘境/首领都只有一行说明，玩家不知道自己为什么出征。
计划：加一段**可跳过的开场叙事**（世界背景 + 主角身份 + 首个目标），数据表驱动（`data/lore.json`），风格走羊皮纸书卷（宋体竖排感 + 逐行淡入），并在主界面加「当前主线目标」一行，让目标感贯穿。
