## 轮次 1｜进界面慢 + 按钮点不动（性能与输入手感的硬 bug）

**用户原始反馈**：「现在进入游戏界面很慢是为什么，然后返回按钮和一部分按钮经常失灵，检查按钮」

### 1.1 诊断（先量，再改）

写了一次性探针（`tools/_ProbeUI.gd`，用完即删）分别量「首次 / 二次」进入各屏的耗时，结论全在数字里：

| 观测项 | 数值 | 说明 |
|---|---|---|
| 素材索引全量扫描（336 项） | 4 ms | 不是瓶颈 |
| 加载页预热 275 张 ready 贴图 | 381 ms | 一次性，可接受 |
| 单件大图 `background/home.png`(1.5MB) | 23 ms | 不是瓶颈 |
| 单件 `bgm_home.ogg`(1.4MB) | 4 ms | 不是瓶颈 |
| **GameHome 首次进场景** | **533 ms** | ← 问题在这 |
| GameHome 第二次进场景 | 31 ms | 差值 500ms 全是一次性开销 |
| CityScene 首次 / 二次 | 212 / 113 ms | 同上 |
| 打开世界图志 / 图鉴 / 召唤 / 兑换 / 设置 / 养成（首次） | 121 / 87 / 79 / 25 / 13 / 31 ms | 每个面板首次都要付一次 |

**决定性实验**：把面板脚本逐个 `load()` 计时，再进场景 —— `GrowthPanel.gd` 148ms、`GameHome.tscn` 231ms、`RouteScene.tscn` 236ms（连带 MapScene/BattleScene）、`GachaPanel.gd` 52ms、`WorldPanel.gd` 41ms…**全部编译完后再进 GameHome 只要 56ms**。
结论：慢的不是贴图、不是音频、不是字体——是 **GDScript 的首次编译**，而且它被平摊到「玩家点进每个界面的那一帧」上，所以感知成「进界面很慢」。

**按钮为什么失灵**：金剑鼠标指针贴图 34×37，刃尖在左上 `(0,1)`，而热点写成了 `(4,33)`（那一点在贴图的透明空白处）。热点定义是「贴图的哪一点压在鼠标坐标上」，于是**整把剑被画到鼠标上方 32px**——玩家拿剑尖去点按钮，真实落点在剑尖下方 32px，38px 高的按钮正好被点空。这不是控件被挡。

顺带用命中测试（复刻 Godot 的 `gui_find_control_at_pos`）逐点验证，另有真死区：主城「出征」按钮左上角被摇杆的 124×124 命中区咬掉 7×26px、右下角被提示条咬掉 71×20px（合计约 78×26 的角部死区）。

### 1.2 本轮改动

| # | 类别 | 改动 | 文件 |
|---|---|---|---|
| 主 | 输入 | 指针热点 `(4,33)` → `(1,1)`（压在剑尖上），并写清为什么 | `src/autoload/G.gd` |
| 副 1 | 加载 | **加载页接管一次性编译**：新增 `PRELOAD_CODE`（主界面/主城/路线图 3 个场景 + 6 个面板脚本 + 创角/标题/登录）与 `PRELOAD_AUDIO`（6 首 BGM），连同贴图分帧预热；进度条按「贴图 + 脚本」总数推进 | `src/ui/LoadScreen.gd` |

## 轮次 2｜世界志与序章：把"你为什么出征"讲清楚

**现状缺口**（按影响大/成本低排序后选的主问题）：
1. **主问题｜剧情背景几乎为零**：创角完成后直接落进主城，玩家不知道「昭元界是什么」「碑为什么会碎」「第一站该去哪」。八片大陆只有名字和一句状态，首领除了名字什么都没有。
2. 副｜主线目标不可见：只有世界图志里的「已解锁 3/8」这类统计，没有"我现在该干什么"。
3. 副｜旧存档没有引导衔接：新加的叙事如果无脑弹，会打断老玩家。
4. 副｜文案散在代码里：`GameHome`/`WorldPanel` 里已有中文长句，再加剧情会越来越难改。
5. 副｜没有剧情回归手段：文案与配置脱节（比如首领改名）不会被任何测试发现。

### 2.1 本轮改动

| # | 类别 | 改动 | 文件 |
|---|---|---|---|

**叙事梗概（写进 lore.json，游戏内可读）**：昭元界八座镇界碑锁着地脉下的「渊」；天倾纪十一年林海那座碑先哑了——**不是被打破的，是从里面推开的**。你是守碑人最后一脉，师门散尽只剩半卷《远征图志》。八境各有碑灵化成的首领（森林之主是把自己种进树心的守碑人、雪原女巫是第一个听见碑里声音的人……），而终局的篡位者之王曾是守碑人首座——他算过一笔账：八碑归位，昭元要死一半人才能活。

## 轮次 3｜打击感：让"打上去"有重量（核心玩法）

**现状缺口**：战斗已有落血、暴击飘字「暴 N」、连携提示、受击闪白，但——
1. **主问题｜命中没有"重量"**：任何一下打上去画面都一样，重击和刮痧在体感上没区别。
2. 副｜**敌方施法完全看不见**：`cast_start` 只在"施法者是玩家角色"时提示，敌方（含首领大招）静默出手，玩家只能看到自己突然掉血。
3. 副｜飘字只有一档：暴击/普通/持续伤害除了颜色，大小与动感一样，看不出轻重。
4. 副｜**残血没有任何警示**：血条细到 44px，血量掉到红线也不知道，等反应过来已经结算了。
5. 副｜结算只有"胜利 + 奖励"，不知道自己这局打得怎么样。
6. 副｜（顺带修）**结算那一帧若正抖屏，战场会一直歪着**——没有收招逻辑。

### 3.1 本轮改动（全部在表现层，sim 规则一行未动）

| # | 类别 | 改动 |
|---|---|---|
| 主 | 打击感 | **顿帧**：暴击/重击（单次伤害 ≥ 目标 12% 生命）时把 sim 步进压到 0.18 倍、70ms 内回弹；只动步进倍率，玩家的 ×1/×2 不受影响 |
| 主 | 打击感 | **震屏**：背景 + 战场挂进 `_shake_root`，按轻/重/暴击分三档抖动（2.0 / 7.0 / 4.5 振幅），HUD 与飘字不跟着晃；结算时 `_stop_shake()` 强制归位 |
| 副 1 | 可读性 | **敌方施法提示**：非角色施法显示「敌方 · 技能名」，首领技显示「首领技 · 技能名」并先晃一下当预警 |
| 副 2 | 可读性 | **伤害飘字分层**：暴击最大最亮（FS_LG+4，「暴 N」）、重击次之（橙红）、普通居中、持续伤害最小最淡；都带 0.7→目标值的弹出 |
| 副 3 | 可读性 | **低血警示**：角色血量 <25% 时屏幕边缘红晕脉动（120×200 径向渐变 + 线性过滤）+ 首次补一句「危急 · 血量过低，补药或撤退」 |
| 副 4 | 战报 | 结算面板加一行：用时 / 最高单击 / 我方输出 / 我方承伤（表现层统计） |
| 副 5 | 修复 | 结算帧收招（顿帧归零 + 震屏归位） |

### 3.2 验证

- `VerifyBattleScene` 扩了 8 条断言：顿帧触发/归零、震屏位移/归位、敌方施法提示文案、战报最高单击与承伤、**低血层挂点必须在根节点而不能混进飘字层**（飘字层有"结算后应清空"的断言）。
- 用例里把 `speed` 置 0 冻住 sim：只验表现层，避免真实伤害持续插进来让断言飘。第一次跑正是因此暴露了"结算后顿帧/震屏不收敛"的真 bug（已修）。
- 全量回归：`VerifyBattleScene / VerifyMapScene / VerifyRouteScene / verify_battle / verify_route / VerifyLore / VerifyGameHome / VerifyPerf` 全绿。
- 截图复查：`battle_low`（新增用例，hp_override 压到 10% 看红晕）、`battle` 两张通过；红晕上限从 0.70 收到 0.52（够警觉但不糊屏）。

### 3.3 下轮计划（轮次 4）

轮次 4 主问题：**主城只是个布景**——NPC 只会说一句随机台词、建筑只给一次性活动，玩家没有"每天回来有事做"的理由。
计划：NPC 委托（日刷新，接取 → 打怪/带物 → 回城交付领奖），把"主城 → 出征 → 主城"的循环真正接上，并让 NPC 台词跟委托状态联动（接了/完成/交付出不同的口吻）。
