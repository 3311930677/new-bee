## 启动决定与现状

2026-11-16 用户明确要求“全量推进《远征》联机版实施方案”。按此开始联机工程和封闭测试环境；原方案的单机 S7、公开交易及公开运营门槛仍单独核验，不把开发启动解释为这些门槛已通过。

- 启动前代码：本地账号、存档、傀儡/镜影演武；无在线后端。
- 工作区已有未提交的 UI、地图、战斗、测试与素材改动。本次增量保留，不重置，不整体提交。
- 2026-11-08 记录为 78 项回归通过，属于历史证据。本次需重新运行；本地引擎缺主程序，从仓库已有压缩包恢复 4.7.2 后重测。
- 路线沿用 Go + PostgreSQL；共享战斗继续由无界面 Godot 执行。缓存和消息总线等多实例需要时再引入。
- 在线角色、钱包、背包和任务在服务端独立保存；本地角色只提供职业/昵称/外观预览，不能提交资产。

## 实施批次

1. L0-A：PostgreSQL 迁移、真实账号/短期令牌与刷新撤销、在线角色/导入白名单、幂等与账本；HTTP API 和客户端入口。
2. L0-B：房间分配/独占租约、Godot 权威地图/战斗进程、签名结果/持久化奖励、双客户端自动化和截图。
3. L1–L2：复用同一协议逐项实现公共世界、社交、合作机制；达到门槛再进入经济与帮派。
4. L3–L6：完整交易与运营基础上接多人竞技，按原文件保留所有规则、异常矩阵和发布证据。

### L0-B 权威进程原型

- `server/room` 是独立、无 autoload 的 Godot 工程模板。构建时复制实际 `src/combat`、伙伴/地区规则与数据表，记录源码摘要，执行导入及 `--check-only`；不会读取单机账号/存档或提供 GM。
- 私有 RPC 仅监听回环地址，以 HMAC-SHA256、时间窗、随机 nonce 和版本守卫认证。Go 的实际通信客户端已经连接真实 Godot 进程，不只通过模拟对端测试。
- 房间按自己的单调时钟推进共享 BattleSim；命令按序去重，拒绝序号冲突、越序和未拥有技能；种子+输入日志能重放到相同最终状态摘要。

- 三端内容版本现覆盖 `data/` 下全部 JSON，包含成长、组合技、伙伴和地区规则；当前一致摘要 `d305f350db87fa61cf085b1aba714112d567873224aefba5aa2ffb113f105a52`。只校验少量核心表的初版已替换。
