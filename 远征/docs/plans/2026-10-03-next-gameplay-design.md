## 一、先以当前版本为基线

现行数据和最近的交付记录显示：主线 36/36、支线 24/36、主世界地图 18、首领 8/8；四职业主线终点均可到 Lv60。已有 4 职业、49 种怪物、40 个装备模板、9 只宠物、6 类坐骑。第四幕“归路门厅→三声共鸣廊→碑心”已是三房机关链，结局后的六条“归路托付”已接入三城 NPC、地图目标和持久世界变化。以上是**已有内容**，不能再照早期问题清单把第四幕后半、结局或整套宠物进化当成未做。依据：[主线数据](../../data/story_quests.json)、[支线数据](../../data/side_quests.json)、[主世界地图](../../data/main_world_maps.json)、[第四幕后半交付](2026-10-02-fourth-act-back-delivery.md)、[归路托付交付](2026-10-02-return-jobs-delivery.md)。

现有可操作系统包括：攻击/技能/道具/撤退与我方在左、怪物在右的接近命中；八主题三层历练与词条构筑；演武；三处钓鱼及烹饪；宠物喂养、突破、资质重置、进化；坐骑购买、升阶、骑乘；五市场现货、工作与两条船运；每日委托表已有 **13 条**，但主要是 `clear/slay/deliver`。后续应增加**玩法之间的联系和可见后果**，而不是把这些功能从零再做一遍。

真正需要补的是：剩余 12 条支线；碑窟首通后挑战与独立房间素材、水闸独立素材、矿脉完整机关空间；有地图行动的委托循环及跨日保存；三种守碑誓约、地区关系；历练跨进程续局；坐骑地形作用与后五骑的地图表现；怪物/地理/来源图鉴；完整音画、安卓与人工游玩验收。旧清单把前三幕副本和第四幕副本混为一谈，也把已有 13 条每日任务误记成“零委托”，排期必须以当前数据复核。

叙事边界：`data/lore.json` 的八碑、渊和王城首座仍是长线谜题；s36“归路仍在”是**归路碑篇章的结案和第一次远征的终点**。通关内容可以留下下一页图志的疑问，不擅自把八碑总谜改成已解决，也不追加必做的 s37。八个“历练主题”是玩法投影，尚未定义与八座真实界碑的一一对应，设计和 UI 不作等号。封渊留路/留声守望、港口供货路、霜关轮岗等已存选择必须继续有回应，两路都能完成后续内容。

还有两处设定应先统一：`lore.json` 对城破距今的年数有冲突；序章称阿豆是信使，现行城镇配置称其为兽栏伙计。以下新对白不写死年数，不擅自认定其身份转变缘由。新实装前由剧情表统一这两点。

## 二、希望玩家实际体验到的节奏

主世界一次短旅程约 10–15 分钟：在城里听到具体麻烦 → 出城观察、护送或处理机关 → 有一个战斗或非战斗的选择 → 当场看到地形/人物回应 → 回城领奖并补图志。30–45 分钟的一次长旅程可再接一座三房副本或一轮历练。这里是**策划节奏目标**，不是已实测通关时长。

所有新增玩法遵守四条规则：

1. 主线和普通装备可独立通关；钓鱼、交易、抽取、誓约、委托、历练都不成为强制钥匙。
2. 信息先于选择：路线风险、合约保证金、誓约效果、机关线索和首领预兆在确认前可读。失误可退回或补救，不靠不可见概率卡剧情。
3. 选择留下可见变化：灯亮、潮道开、矿车改线、人物改口、册页补全；奖励等值的叙事分支不偷偷改变伤害或结局可达性。
4. 所有领取、消耗和状态推进走唯一事务 ID；背包满、撤退、重进、重复事件和写盘失败都保持幂等或完整回滚。旧档没有参与新玩法时保留原进度。

## 三、先补三座旧副本：同为三房，机关各不相同

## 五、让已有日常委托真正发生在主世界

`data/quests.json` 已有 13 条每日任务，但大多是八主题历练讨伐或交库存物品；当前日期翻日时会清空进行中的委托。目标是把**“委托模板”**定义为可落在地图上的行动，不是机械再补 12 个同类击杀任务。保留既有条目的可领取历史，新增三城各四种的主世界模板，第一批先做每城一种，再扩到表中十二种。

| 城镇 | 四类可重复世界事务，每次只刷两条候选 | 可复用的现有入口 |
|---|---|---|
| 昭元 | 路标勘定（查三处路痕）；巡界夜岗（守一个可见刷点）；桥板修补（带普通材料到桥）；岩龟寻路（跟随脚印而非杀怪） | 闻叔告示栏、老赵、石头、枫林古道、断碑坡 |
| 沉渊港 | 潮线观测（三处水线）；缆绳加固（选受力点）；盐账对盘（核实价格信息）；短程押运（两条路线择一） | 沈澜港务、老鹭栈道、陆七货签、旧盐道、潮痕滩 |
| 霜关驿 | 炉息巡查（找堵塞）；矿车让道（道岔选择）；雪线踏勘（辨足迹）；轮岗补给（送到一个岗火） | 宁砚、岑雪、陶铎、矿道、栈道 |

每项以 `posting_id = template_id + board_day + slot` 存档和结算，同一次公布只领一次。每天可以更新**未领取**的候选；已接委托保持到玩家主动交付或放弃，现实时间过零点绝不清掉进度。主线不要求做委托，玩家离线数日不会损失永久奖励。接取后地图显示目标、预计耗时与普通报酬；现场完成时有短反馈，回城结算一次。对旧存档中的 `active` 委托做迁移映射，不重置进度；原有 13 条任务仍可作为巡界厅“历练委托”继续玩。

首轮建议把“路标勘定、潮线观测、炉息巡查”三条做可用样板。验证跨真实日期模拟、退出重进、放弃重接、重复事件、奖励失败回滚；控制收益为同期野外战斗/支线的补充，而非最快升级路径。

## 六、四组能把旧系统串起来的新玩法

### 6.1 守碑誓约：给每次出行一个明确做法

玩家完成 s12 后在昭元巡界厅或安全碑座选一项当前誓约；出行前可以换，战斗中不能临时切到最有利一项。三项不是善恶或阵营站队，不改变主线台词正误。

| 誓约 | 地图任务 | 战斗/探索的轻量差异 | 主要报酬 |
|---|---|---|---|
| 庇护 | 护送、救援、保住补给点 | 小幅提升保护/恢复，略减伤害 | 图志的幸存者记录、守护纹样 |
| 征伐 | 清除危险敌群或破解首领前哨 | 小幅提高破绽输出，药剂效率略低 | 首领预兆附注、武器纹样 |
| 丰收 | 留根采样、清理路障、带回货物 | 多得少量普通采集物，直接战斗略慢 | 地理图志、营帐布置物 |

建议样板数值以约 ±5%–10% 为上限，经四职业战斗预算再确定；不改变唯一首通掉落、剧情物或契约利润。誓约任务每张地图有一个有形目标，完成一趟换得一个纹样/材料，失败不扣永久进度。存档保存当前誓约、已完成目标和已领事务；切换只影响后续出行，不能反复切换刷一次性采集。

### 6.2 地区信任：让三座城对玩家的行动有记忆

建立昭元巡界厅、沉渊港港务厅、霜关驿巡界岗三条**可同时提升**的信任记录。通关前后做支线、解决委托、按期交货会留下记录；原有 s20、霜关轮岗、s36 选择提供对话背景，不把一个分支写成另一阵营的永久仇恨。每地设“认识→信任→托付”三档，界面显示下一档由什么行动触发。

收益是地图提示、地区短故事、普通商品的小幅服务便利与营帐外观。基础店铺、交通和主线入口始终可用；重复同一委托刷信任设每个 `posting_id` 一次上限。首批只接三名代表人物（闻叔/沈澜/宁砚）和各一段后续事件，三个城市都有实景反馈后再扩其他 NPC。

### 6.3 保价与延期交割：给商路增加可预判的风险

沿用现货与已有船运订单，在 s20 后由港务厅推出有限的三城商路合约。签约页同时显示货物数、当前参照价、需要交的保证金、结算的**游戏内日期/事件**、保价费用、最大可能损失（不超过该单保证金）和到期缺货时的补救路线。日期复用现有经济状态中的 `day`，不由现实系统日期决定。每次最多两张未结单；不产生负余额、不借债、不让契约成为主线必须的钱源。

一张合约的例子：玩家替霜关驿保两箱铁料，先交可承受的保证金，选“低利润保价”或“高利润自担一次路阻”；途中可到旧盐道/赤砂商路排除路障或正常购买补货；到期领取按**固定存档种子、已发生地区事件与合同签发时规则**计算的结果。可有一次付费延期，过期也先给补救/自动上限结算，不吞玩家全部货物。价格和供货路受 s20/s28 已有选择影响，但另一条路不会永久锁死。对账必须能说清收益从何来。

经济验收包括同日反复倒卖、跨城传送、读档/回档、背包满、重复领款、系统时间回拨、订单并发和写盘中断；结算账本只允许一个 `contract_id` 生效一次。先模拟大量可重复订单，确认不会变成无限金币路径，再放进玩家界面。

### 6.4 图志、坐骑与生活活动形成探索链

图志分“地理、怪物、伙伴、人物手记”四卷。初见只开位置和剪影；调查/战斗增加招式预兆、可能来源与地貌线索；完成地区旁事留下路线或人物注记。怪物掉落列表显示“可能来源”而非保证掉落，未见怪不剧透首领身份；已存的宠物图鉴和世界页按原 ID 迁移，不清空收藏。

坐骑六种已经能购买和升阶。先做**首骑与另一只坐骑**两种完整地图外观/步态和一项非必需地形特性，再扩其余四种：例如雪地辨路缩短一次绕行、潮滩辨浅水提示安全踏点、矿道载货减少商路补给消耗。地图必须有步行替代路；数值优势有限，坐骑不可跨图穿门或绕过机关。骑乘的四向脚点、遮挡、接触阴影及坐骑动作要在 480×800 和长屏实际播放检查。

钓鱼已有时机条、每日竿数与烹饪。新增内容只给地区线索和图鉴深度：港口潮线对应鱼种，霜关冷水对应鱼种；鱼王可用环境提示识别，失手可以再来，普通鱼继续用于宠物粮/少量商路补给。岩龟等伙伴增加一次“闻踪、提示危险、找安全路”的地图互动，冷却与切宠规则明确；不会因未抽到稀有宠物而缺线索。

八主题历练先解决**跨进程续局**：保存 `run_id`、种子、当前层/节点、词条、血量、背包快照和未领取结算，重进只可继续或安全放弃，不能重掷好节点。随后每主题加至少一个有辨识度的事件或地貌决策，地图图形与词条文字能辨出森林、潮汐、霜雪等差异；不把八历练主题直接称为八座真实碑。历练奖励侧重构筑材料/外观，主线特有物仍只走主线。

## 八、工程与状态约束

- 保留 `lorin_wilds`、旧副本世界 ID、`s01`–`s36`、原支线 ID 与已有任务/奖励协议；新房间、委托、图志页、合约使用稳定新 ID。不能直接改老档已领取奖励或旧奖励迁移基准。
- 多阶段任务至少记录 `accepted / current_step / used_entity_ids / completed / claimed / branch_flags`；同一交互实体只计一次。怪物、经济、生活、图志读取同一事件 ID；别为每个任务在 `G.gd` 堆硬编码 `if qid`。
- 奖励和道具消费使用同一个事务提交。失败时背包、钱包、状态旗和场景实体一起回滚；场景重建只读存档状态，不能靠截图脚本或会话内缓存维持“已修好”的假象。
- 地图互动新增 `inspect / align / switch / escort / repair` 等目标类型前，先明确 `QuestService` 与 `MapScene` 的生产调用、导航提示、触控面积、失败重试与存档字段。当前服务只覆盖 `defeat / collect / observe / deliver / boss` 等目标，单纯写 JSON 不会产生新机关。
- 每个新任务显示可完成的地图与目标，不在图鉴里提前揭底；分支奖励等值的地方必须在 UI 告知“影响回应和场景，不影响主线”。
- 新副本、誓约和合约先做一条纵切后才批量扩表。每条纵切从旧档接入、真实输入完成、强制中断、第二进程继续、重复结算和 480×800 实际截图同时验收。
