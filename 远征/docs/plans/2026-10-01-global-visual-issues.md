# 全界面视觉问题清单 · 2026-10-01

范围：启动、标题、登录、创角、序章、营帐、养成与功能面板、城内交互、主世界、历练、战斗及长屏适配。

目标：画面舒服、文字清楚、信息有主次、素材统一。原游戏用来参考实体比例、地面层次与交互辨识度；《远征》可以保留自己的题材和界面设计。

## 本次证据与边界

- 查看 [最新截图目录](</D:/new bee/远征/shots/all_scenes_20261001/README.md>) 的六张分类总览，并按原尺寸复查登录、标题、创角、序章、营帐、装备、地区图、天赋、召唤、伙伴帮助、商路、地图、建筑、战斗及长屏代表画面。
- 对照本地原游戏的登录、探索和战斗参考截图；参考截图中的模拟器按键和系统栏不作为设计目标。
- 核对当前字体配置、建筑阴影绘制及截图方式。这里只记录视觉审查结果，本次没有修改运行代码或重新拍摄全部场景。
- 长屏图片来自独立 SubViewport，截图说明明确提示不能替代真机验收。因此灰底是已观察到的截图缺陷，是否在正常窗口／手机出现仍需验证。
- 下列问题以截图为依据，不将旧文档的“功能通过”当作美术完成证据。

## P0：优先解决阅读和遮挡

| 编号 | 具体问题与证据 | 修改方向 |
| --- | --- | --- |
| V01 | **辅助文字太小、太淡。** `settings`、`equip`、`bag` 中浅棕说明和材料数量贴着淡黄色底；战斗中能量、蓄力提示在纹理地面上不够醒目。当前最小字号为 13，辅助字号为 16。 | 在 480 宽逻辑视口制定正文、辅助、数值三档；正文优先 18–20，重要辅助至少 15–16。暖白／浅纸底配深色正文，世界悬浮文字配稳定深色底或轻描边。 |
| V02 | **字体与字重使用缺少规则。** 标题装饰字体、粗按钮、细说明、发光或描边的世界文字并存，某些小字拥挤，整体阅读节奏不一致。 | 固定一款中文正文字体；装饰字体用于大标题。统一字重、数字字形、描边厚度、行距与字距，并以实际尺寸检查多笔画汉字。 |
| V03 | **说明堆在操作页。** 设置、装备、伙伴、导师、商路大量解释文字和按钮同时出现，难以先找到当前状态与下一步。 | 每页先显示“当前状态 → 变化／代价 → 主操作”。详细规则收入帮助或详情，常驻说明保留一两句，不丢失必要信息。 |
| V04 | **弹窗阅读区与叠层不完整。** `companion_help` 末行露出半行，滚动区和确定按钮挤在一起；长屏 `equip` 后方“养成”标题仍露出，两个页面争主次。 | 用容器约束内容高度、底部按钮独立，滚动区上下留边。弹窗打开时明确隐藏或压暗下层内容；长文采用清楚的滚动或分页。 |
| V05 | **地区图连线穿过地名。** `worlds` 的横线从“枫林古道”“失声碑窟”“断碑坡”文字中穿过，滚动条又占据图面边缘。 | 连线放在节点下层，从节点边缘接出；名称使用不透明底板。提供地区背景、当前位置、出口与解锁状态的清楚区分。 |
| V06 | **HUD 与场景标牌争位置。** 霜关截图右上小地图、出口牌和蓝色标识挤在一起；城镇两条横向任务条遮住上方景物，边缘还会出现没有主体的半截店牌。 | 建立顶部信息区、小地图区、世界标牌区和底部操作区。店牌随可见建筑整体显示或隐藏，出口指引避开 HUD，常态只突出一条当前目标。 |

## P1：整套界面的主要观感

| 编号 | 具体问题与证据 | 修改方向 |
| --- | --- | --- |
| V07 | **启动流程美术主题跳跃。** `load` 为角色与废墟，`title` 为蓝色星涡，`login` 为暖色营地，`createrole` 又换成紫色背景。 | 让加载、标题、登录、创角共享主视觉、色板和装饰元素。可以使用不同构图，但要有连续的品牌形象。 |
| V08 | **标题页主次与构图偏弱。** `title` 右侧四个同类细框菜单像漂浮在背景上，“开始游戏”与其他选项的差别有限。 | 为主要动作设计稳定位置、清楚的按钮体量与反馈；设置和退出使用次级层级，背景留出干净的操作区。 |
| V09 | **登录页内容分散。** 账号、密码、头像选择、两种登录方式、使用说明同时挤在同一纸板里。 | 分成主要进入流程和可选头像设置；缩短说明，压低版本和保存方式等附属信息。保留既有登录与存档逻辑。 |
| V10 | **创角页人物展示混搭。** 低亮度大立绘、明显放大的像素角色和亮黄圆台同时叠放，焦点不清楚。 | 建立明确的职业展示区：一个主视觉配简明职业定位，姓名和职业选择对齐，详细背景另行展开。 |
| V11 | **序章断行与篇幅不自然。** `prologue` 的引号出现单独断行，上半部连续文字，下半部大片空纸；文字、页码和操作间距缺少联系。 | 调整可用行宽与中文标点换行，按阅读段落分页；让正文、页码和继续按钮形成稳定阅读区，保持舒适行距。 |
| V12 | **营帐导航拥挤、主操作分离。** `home` 右侧八个圆图标及标签密集堆叠，中央大量空间留给角色，返回世界按钮贴近底边。 | 重新分配角色展示、当前目标、常用入口和主要操作的面积。入口按用途组织，图标与标签共同对齐，保留足够点击间距。 |
| V13 | **功能面板缺乏场景背景。** 背包、装备、养成、演武场等经常是一块纸板浮在暗棕色空底上。 | 为独立页面提供轻量、统一的场景或材质背景；浮层保留经过压暗的当前场景，让面板有明确归属。 |
| V14 | **面板装饰重复，层次扁平。** 大量页面复用黄纸、四角花纹、金框和木匾；正文、选项、详情和确认按钮的视觉重量接近。 | 统一组件，但区分页面标题、内容卡、选择项、详情和主按钮。减少重复边框，把留白、对齐和色块用于组织内容。 |
| V15 | **按钮状态辨识不够稳定。** 未选项、禁用项、普通操作都使用相近黄褐色；装备“强化／宝石／精炼”选中状态不够突出。 | 统一主操作、次操作、当前页签、禁用、危险动作和选中状态；配合边框、图标或标记，不只改变一点颜色。 |
| V16 | **图标美术与语义混杂。** 营帐、货币、装备、召唤等图标同时使用不同高光、描边、主体占比和分辨率；部分背包装备图标很小且发黑。 | 高频图标先统一画布、轮廓、色板和主体占比，并配清晰标签；缺少合适图标时再制作或选择风格匹配的开源素材。 |
| V17 | **建筑下的大椭圆阴影很突兀。** `town_north`、`frost_art_north_left` 可见建筑外侧整片椭圆，雪地尤其明显；当前建筑绘制会额外补一层统一椭圆接影。 | 按建筑底座形状和光向做贴地阴影，降低外扩与不必要的黑度；逐张核对贴图自身阴影，避免叠加后形成双重阴影。 |
| V18 | **道路和设施仍有大块程序几何外观。** 矿道轨道、赤砂道路、木桥与路牌大量使用大块直线、矩形和圆影，和精细建筑、人物不协调。 | 保留地图、碰撞及状态逻辑，用地砖、边缘、转角、轨道、桥板与路牌素材替换主要可见表面。 |
| V19 | **地图精细程度跳跃。** 港口和霜关有较完整地貌；古道、碑窟、矿道等仍是重复地面、大色块和少量散件。 | 统一地表纹理密度与材质，补远近层次、墙边、坡面和关键地标；按实际可走区域组织景物。 |
| V20 | **城镇空间关系偏机械。** 房屋和人物沿道路排列，建筑经常截在屏幕边缘；门口、NPC和店牌没有形成清楚的交互组合。 | 在保证通行的前提下组织入口、台阶、院落和NPC站位；调整镜头与店牌显示，使关键交互区域能被看见。 |
| V21 | **角色、NPC、怪物的比例与精细度未统一。** 主角金红高对比，部分NPC更细长，普通怪、伙伴与背景使用不同纹理密度；营帐角色放大后像素块很明显。 | 制定每类实体在实际画面的可见高度、脚点、轮廓和材质规则；地图与战斗共享同一实体的外观特征，展示页使用合适的专用资源。 |
| V22 | **战斗画面焦点偏散。** 主世界战斗地面大面积空白，角色与操作区相距远；技能名、能量、蓄力、敌我名签同时依赖悬浮文字，场上信息优先级不清楚。 | 调整敌我站位与镜头，划定目标信息、行动提示和底部操作三个区域。能量、技能可用性和确认反馈应集中在操作附近。 |
| V23 | **战斗状态颜色不够可读。** 紫色怪名、红色蓄力和伤害字在绿地、暗砖、雪地的效果差异明显；低血整屏红色又会影响阅读。 | 对亮地、暗地、雪地分别核对文字底板与描边；让危险预兆、受击数值和状态文字各有稳定表现，低血效果保留信息清晰度。 |
| V24 | **长屏截图背景覆盖不完整，待验证。** `long_480x1067/bag`、`equip`、`battle` 下部出现大块灰色，而部分地图和营帐能填满长屏。 | 先核对离屏根节点、遮罩及背景尺寸，再拍正常窗口和手机。确认来源后修复；不能据此直接断言手机必然灰底。 |

## P2：进一步提高完成度

| 编号 | 具体问题与证据 | 修改方向 |
| --- | --- | --- |
| V25 | **列表布局与内容量不匹配。** 商路商品行的价格、库存和购买操作分散；访客、任务及部分列表内容挤在上部，底部空白很大。 | 同类项目采用一致行高和对齐规则；数量少时让详情或插图合理利用余下空间，数量多时使用清楚的滚动列表。 |
| V26 | **天赋树密而缺少分组。** `talent` 三列节点重复使用近似图标，名字、连线和等级靠得近，阅读需要逐个扫小字。 | 强化分支名称与节点状态，增加组间距，选中节点后统一显示效果、升级变化和投入操作。 |
| V27 | **历练路线和地区地图缺少差异化视觉。** 多种主题路线仍是相同纸面与节点排列，地区图也偏线框示意。 | 给主题增加适量地图纹理与地标，保持节点可读；明确当前位置、可选道路、已完成和锁定状态。 |
| V28 | **长屏内容空间利用不一致。** 有的面板居中后顶部空很大，有的仍使用固定短屏高度；后方内容露出方式也不同。 | 建立固定边距、内容最大宽度、合理高度和底部操作规则；短屏、长屏采用一致阅读顺序，复杂页通过滚动适配。 |
| V29 | **NPC对话与帮助过于说明书化。** 导师、伙伴与定路弹窗常把规则、剧情和条件连续写在一起。 | 对话保留角色口吻和当前决定；条件、奖励和效果用简明信息项呈现，长背景内容可另读。 |
| V30 | **装饰和反馈缺少统一尺度。** 标题匾额、圆形入口、黑色技能提示、红点和边框各有自己的粗细与形状。 | 补齐统一的按钮、页签、信息条、提示、红点、确认与关闭规范；按重要程度控制装饰强度。 |

## 建议实施顺序

1. **先统一字体与阅读规则。** 小字、颜色、行距、描边、规则文案一起调整；先覆盖设置、装备、伙伴帮助和战斗提示。
2. **建立三个代表页面。** 标题／登录、营帐／背包、城镇／战斗各做一组实际运行样板，用同一套色板、组件与字体。
3. **处理全局布局。** 面板层次、导航、地区图、HUD、弹窗及背景覆盖。
4. **修正场景美术。** 建筑阴影、道路与设施、实体比例和地表材质。
5. **扩展到其余页面与地区。** 每批用相同尺寸截图核对，并进行对应的功能回归。

## 素材使用原则

- 先确定目标画面，再决定制作新素材还是使用开源素材。单张素材需要放进实际界面和地图检查。
- 开源资源需记录来源与许可证；字体也需记录允许使用和分发的条件。原游戏图片用于参考，不能按“开源素材”处理。
- 优先补主视觉背景、统一UI图标、地砖与边缘、建筑接影和展示人物等能改善整套画面的资源。
- 新素材接入现有资源与场景结构，保留任务、存档、碰撞、地图出口及主世界／历练行为的既有约定。

## 验收要求

- 480×800 基准尺寸下直接读字，不依赖放大截图；同时核对正常窗口及实际长屏输出。
- 中文不截半行，标点不形成异常断行，长名不溢出；重要状态和代价易读。
- 每页有一个明确主操作，标题、正文、辅助说明和禁用状态清楚区分。
- 浮层层次明确，背景铺满可见区域，世界标牌避开HUD，长列表能清楚滚动。
- 建筑阴影贴合底座与地面，光向一致；同一实体在地图和战斗中可辨认。
- 保存修改前后同条件截图；功能检查与美术验收分别记录。
