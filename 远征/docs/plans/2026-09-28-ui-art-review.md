# P00–P04 前端 UI 与图片风格复查（2026-09-28）

依据当前 Godot 4.7.2、480×800 实际渲染，不用历史宣传图代替现状。画面见 `tools/_logs/preview_lorin_wilds.png`、`preview_maple_road.png`、`preview_broken_slope.png`、`preview_stele_cavern.png`、`preview_stele_cavern_battle.png`、`review_login_ui.png`、`review_home_ui.png`、`review_battle_skills_ui.png`、`review_bag.png` 和 `shots/p04_20260928/equip_panel.png`。代码和 P01 同屏规范见 `docs/plans/2026-09-28-style-spec.md`。

## 判断

**有明显问题。** 当前 UI 已能操作，重要入口基本可找到；视觉上仍像几套界面拼在一起。P01 做到了字号、道路宽度、地区 tint、脚点与安全边距等底线，却没有完成“主世界、战斗、营帐、养成同一款游戏”的美术统一。P04 新背包功能可用，但截图还不像可发布的最终面板。原方案中的“重绘主城地表、角色／怪物／NPC、战斗细节、全局界面”仍是实质工作，不能因为 29 项功能回归全绿就判为完成。

## 已在这次复查里直接改的小问题

1. 营帐右侧八个 60px 圆形图标每隔 62px 摆放，下方标签被下一枚图标盖住，截图里除最后的“设置”外几乎看不到入口名。改为 48px 圆盘、64px 间距，八个文字标签全部可见，命中区仍为 64×64。
2. 主世界技能弹页原每行 28px，详述文字在浅色草地上过灰，弹页还透出底下的四指令。改为 44px 行高、亮色详情和近实底背景；弹页展开时隐藏底层四指令，返回后恢复。
3. 施法提示原位于战斗角色身上，和敌我名签、技能效果争同一区域；移到角色与操作区之间，默认加深色描边。

这三项是**布局和对比度修正**，不等于整套 UI 美术已经统一。

## 仍需成批处理的问题

| 优先级 | 画面与证据 | 玩家感受 | 实施方向 |
|---|---|---|---|
| P1 | 营帐 `image/background/home.png` 是 971×1619 的暖褐高细节插画；边城 `lorin_wilds_grass_v2.png` 是 1086×1448 的明亮草地；碑窟首领源图为 1210×1300，缩到百像素上下。同屏里这些图的轮廓硬度、纹理密度、光照与边缘锐度不同。 | 从登录／营帐进入主世界像切换了美术项目；首领与普通怪不像同一个制作规格。 | 先定一张**像素尺寸、色板、光向、描边厚度、阴影与材质噪声**的样板，再按地表→角色/NPC/怪→战斗特效→UI 图标批量替换。高分辨率源图可作草稿，但游戏内成品须按目标尺寸逐帧检查，不能仅缩放。 |

## 建议的重绘顺序与交付门槛

1. **先做一张真实纵切样板**：边城主街、主角四职业之一、两名 NPC、一只普通怪、同图战斗、营帐与背包共享色板和轮廓规则。做前后截图，不先批量出图。
2. **锁定资源规格**：每个资源写原生像素尺寸、最终屏幕高度、脚点、方向帧、阴影、调色板和来源；由 Godot 实机截图判断，而不是只看透明 PNG。
3. **按玩家视线路线扩展**：登录→出生主城→古道→碑窟→战斗→回城工坊／背包，先统一高频画面，再做其余地区和次级养成页。
4. **验收不只看“有图”**：同屏文字不压实体、图标带标签、互动对象优先级清楚、亮草地与暗地砖都可读、地图和战斗里的同一敌人一眼认得出；四职业和至少两种敌体型均通过截图矩阵。

视觉重绘属于 [P00–P04 审查问题清单](2026-09-28-p00-p04-review-issues.md) 的 R-08；其余整段玩法与存档风险仍按该清单分别处理。
