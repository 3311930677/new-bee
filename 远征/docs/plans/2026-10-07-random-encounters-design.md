# 《远征》随机奇遇与特殊事件扩展方案

日期：2026-10-07。状态：**详细制作规格，新增玩法尚未实装**。本轮先完成设计，再依照末尾批次实施。

依据：当前 `special_events.json`、`SpecialEventService`、`RunEvents`、主世界18张地图、现有委托/邮路/图志，以及[货币来源与数值复核](../2026-10-06-currency-balance-review.md)。本方案承接用户已确认的简洁像素人物、常规金币克制、传说宠物保持通关和寻访获取的方向。

## 1. 制作目标与当前缺口

当前三条奇遇已完整落地：错送喜帖、挑主宝箱、雪关夜炊。它们按主线开放固定地点，走调查、二选一、可选战斗、复命领奖，金币分别480/800/1200。已有结局和领取记录保留。

缺口在于：玩家重走同一条路时，地点、现场事实、处理动作和后果基本固定；八主题历练事件也主要采用回血/伤血换资源的共同规则。只增加同结构故事，重复体验仍容易被猜到。

本次希望实现：一趟路可能遇见不同的人和麻烦；观察能帮助判断真实情况；处理方式改变过程和留下的场景；曾经帮过的人会再次出现。随机性来自出现、情境、行动和后续组合，奖励规则保持清楚。

### 内容规模

| 内容 | 新增制作量 | 最低内容标准 |
|---|---:|---|
| 主世界奇遇 | 16个故事模板，分四地区 | 每个至少2种现场情境、2种实际处理路线、3种有效结尾 |
| 既有三条奇遇 | 3条保留，并各设计后续回应 | 原存档、固定入口、原报酬和原结尾均保留 |
| 历练事件 | 八主题各1个机制不同的样板 | 先做森林/雪原，再扩剩余六主题 |
| 首发内容总量 | 主世界19个故事入口/模板 | 新16个提供至少32种现场情境、48个结尾节点 |

以上为待制作数量。兼容性限制下的分支组合单独验收，不将所有变量做笛卡尔乘法后宣称几十倍内容；延期、离开和仅换名字的文案不计有效结尾。

一次短偶遇目标1—3分钟，地区故事4—8分钟，罕见连环故事8—15分钟。这些是节奏目标，后续用真实游玩记录修正。

## 2. 三种奇遇的定位

| 类型 | 16个模板中的数量 | 体验 | 重玩用途 |
|---|---:|---|---|
| 路边小事 | 8 | 有趣的人、误会、小推理、物件操作 | 换情境、补图志、少量补给 |
| 地区故事 | 4 | 两段地图行动，角色动机与关系变化 | 不同处理过程、人物回访 |
| 罕见连环奇遇 | 4 | 三环线索，意外发展，独特的场景留物 | 新线索和结尾收藏，首次奖励一次 |

主线普通配置可以独立通关。奇遇不成为开地图、获取必需装备或领取传说宠物的钥匙。第四幕故事只围绕归路碑与三城生活展开，不解释八碑总谜、渊的最终本质或王城首座，不追加必做s37。

## 3. 什么会随机，什么由玩家决定

### 3.1 五层变化

1. **出现层**：本趟是否出现、选哪个地区池、谁先出面、在哪个合格停靠点发现。
2. **事实层**：在模板预写的现场情境里选一种，例如借条确有重复记账，或只是同一笔债的三张副联。
3. **行动层**：玩家选择调查、对照、摆放、追踪、谈判、借物、护送或战斗；至少一条不强制战斗的路线。
4. **发展层**：前一处理方式决定接下来的人物、目标实体和补救办法；后续随机变化只从与已知事实兼容的池中选择。
5. **回应层**：结尾、人物台词、地图陈设和图志注记保留此次经过，满足条件时开放后续短事件。

现场事实与后续合法组合在**出现前一次生成并保存**。玩家选择后按保存的事实推进，不临时抽签改写对错；给出的证据必须足以支持判断。文本只复用称呼等非关键部分，动机、关键反转和结尾由作者预写。

### 3.2 选择信息

确认前说明金币/道具消耗、战斗强度、是否会中断运输以及可补救的风险。剧情反转可以保留惊喜。付出较少但绕路、付小额费用但省一段行动等差异要可读；成功不取决于不可见的“选项成功率”。

离开提示不等于接取或放弃。已接事件不随经济日或现实日期变化消失；调查错误给理由和新的证据，不吞线索物。战斗撤退/失败保留已知事实，并可进入求援或补救路线。

## 4. 触发、频率与防重复

### 4.1 使用有效旅次

旅次从玩家离开安全城镇沿道路出行开始，跨地图和跨进程延续。驿路传送不创建新旅次、不增加发现次数；已开始的旅次可以在传送后继续，但传送本身不给触发机会。

一个旅次达到以下条件，获得一次随机奇遇抽取机会：

- 实际沿道路到过至少2张不同的合格地图；
- 完成至少3项不同的有效地图行动，其中至少1项为调查、采集、机关、实际战斗胜利或现场交付；
- 只认生产调用的事件ID，同一实体、同一遭遇结果、同一拾取物只记一次；本系统自身事件不反过来生成下一次抽取机会；
- 当前处于安全的地图行走状态，主线演出、战斗、运输交付和其他弹层期间不插入。

反复进出城门、打开面板、推摇杆、原地待机、快速切图、休息换日和重复上报都不增加机会。旅次返回城镇结案；有未完成奇遇时只结束旅次计数，不结束奇遇本身。

### 4.2 初始调度值

| 规则 | 初始设计值 |
|---|---|
| 每合格旅次生成数量 | 最多1个新奇遇实例 |
| 基础出现概率 | 35% |
| 连续未遇后的概率 | 第一趟未遇后50%，第二趟未遇后65%，第三趟未遇后下一次必出 |
| 类型权重 | 小事65、地区故事30、罕见5，过滤不满足前置的模板后归一化 |
| 罕见故事保障 | 已有合格罕见模板时，连续12次有效机会未遇，第13次给予确定追寻线索 |
| 新系统同时进行中 | 最多2件；旧三条不并入此上限 |
| 近期避重复 | 最近3个模板降低权重，同模板至少间隔3个完成旅次 |
| 单地图同时可见的新随机奇遇 | 最多1件，完成陈设另算 |

“有效机会”只在真正执行过一次调度且成功保存时计数。无合格池、已达进行中上限或保存失败均不增加未遇/罕见保障计数。罕见保障优先未完成的罕见故事；池已收集完时不制造大额首奖。

调度种子由存档固定种子、地区和旅次序号推导；随机流与战斗、掉落、寻访分开。抽到的实例、位置、事实、后续组合和奖励类型一起保存，重进加载原实例。

### 4.3 发现与地图位置

每张可参与地图预设至少3个合格位置，标注路旁、驿亭、岸边、背风处等标签。调度只选可走、可见、可接近的点；不得落在水体、实体门后、首领接触区、传送口或主线交互范围内。

首次发现采用附近的小动作、物件和一句短提示；默认不弹整屏对话、不在未发现时把所有地点挂上全图罗盘。玩家接近约220个世界像素且同一道路可达后出现提示，主动点击/确认才接取。发现后可手动追踪；主线与手动追踪不互相抢走焦点。

旧三条保留固定入口。新随机池满时可以让城里NPC提供泛地区传闻，方便玩家继续找事做；传闻不立即重掷本旅次事件。

## 6. 第一批四个纵切的详细规格

先完成下列四个，再制作剩余12个。它们覆盖不同地区与实际操作，避免早期工程只适配一种“调查→战斗”的故事。

### 6.1 三张相同的借条：有证据的真假判断

- 入口：在断碑坡路旁遇到争执，主动询问接取；s06后可进入池。
- 开场情境在生成时确定：A为同债副联，B为误把已结账的副联再次收款。墨色、收讫印、货签日期分别支持对应情境。
- 阶段一：看至少两项证据，未检查时可先问人但不给最终断言；三项均可复看。
- 阶段二：选择先找担保人、直接当场对账，或先把借条交给巡界人暂存。使用不同实体和回城地点。
- 正确还原：A结为公开澄清，B结为退还误收款；退的是NPC之间的小额款，不从玩家钱包制造利润。
- 急于指认且判断错误：人会反驳，给新证据；玩家可以道歉后协助补签，形成“补账和解”结尾。过程发生改变，主线与店铺保持可用。
- 首奖240金＋伙伴粮2或强化石1二选一；同存档同模板只发一次。
- 留物：旧借条夹或新对账夹；NPC以后根据结尾说一句回应，人物手记记录证据与处理过程。

### 6.2 涨潮前的空席：可操作的物件小场景

- 入口：港口老鹭的空桌；s13后随机出现，出现点从三处安全岸位挑选。
- 情境A为纪念未归者，B为欢迎返航者；杯口向内/外、旧船牌和热菜构成证据，不让悲喜纯靠事后抽签决定。
- 阶段一：主动看桌上两件物品或先问老鹭。
- 阶段二：根据港口水线，在三个已验证可站立的桌位中选摆放点；桌子实体真正移动，不以一句“摆好了”代替操作。
- 处理：留原空席、先询问再移席、先搬桌再补位；分别导致保留纪念、等到返航人、认错后补席等兼容结尾。
- 错摆到临浪位：老鹭提醒并要求换位，不扣永久物品、不让玩家等现实涨潮。
- 首奖240金＋伙伴粮2或生活图志注记；注记没有永久战力。
- 后续：桌位保留；完成迎船结尾后未来旅次可遇到船员带来的短消息，首次与复现奖励共用模板首奖标记。

### 6.3 替身守岗：场景选择、护送和可选战斗

- 入口：霜林栈道的空甲与歪岗灯；s28后开放。
- 情境A为替患病同伴保岗，B为借假脚印逃岗。脚印方向、甲内药包、轮岗簿碎页提供不同证据。
- 可选路线：陪人回驿请援、当场重排三盏岗灯、追踪假脚印后揭穿。请援要真实走到驿站交互；不允许接取后直接“返回”完成护送。
- 一条路线遭遇闻声兽影，可选战斗；有明确预兆和可撤退规则。失败后能把已查线索带回求援，进入补值结尾。
- 三种结尾：共同轮岗、承认躲岗后补值、求援保住岗火。地图中的灯位与轮岗人物根据结尾重建，奖励相同。
- 首奖600金＋精炼石1或伙伴粮3；变体复现不再给600金。
- 条件回应：此前s28选商货/守关补给只改变人物一句解释和物资外观，任一路都能完成。

### 6.4 借影留名：罕见连环奇遇

- 入口：s36后的渊口外环，出现一位脚下影子与站位不合的旅人。人物保持普通小轮廓，不冒充其他真人玩家。
- 两种事实：布幕测照明，或用影线替危险旧标；锁定后各提供两种符合事实的中段。
- 环一：观察灯向与布边，旋转两盏临时灯，影子应在场景里真实改变。
- 环二：沿明影或暗影走到两个不同的观察点；根据上环记录出现测灯匠、匿名守路者或需要求援的支点。
- 环三：选择请他留名、尊重匿名但核对路标、先回共鸣廊寻援；至少两个地图目标、三个有效结尾。
- 可选战斗只处理局部渊影，不以击败该敌人解释世界总谜；机关/援助路线可以替代硬打。
- 首奖1600金＋静态图志页＋精炼石2或资质果1；资质果提示可能洗低。不给传说/传世宠物、不另加稀有抽取概率。
- 完成后外环留下署名/无名/补修路标之一，图志记录此次情境与处理；重进同一实例保持同灯向、同事实与同战斗配置。

## 8. 奖励与大额目标的边界

1. 首次金币按目录定额，同模板的所有变体与所有结尾共享首奖，tx采用模板ID。
2. 复现新情境首次完成只补图志或小材料，**重复奇遇不再产金币、魂晶、荣誉或远征币**。每完成旅次最多两份普通培养材料，按商店回收价折算合计不超过100金，余下进度可保留而不追加物资。
3. 完全重复的情境只给回顾与人物回应，不靠无尽领奖维持参与动机。奖励限额按事件签发时规则快照保存，拒绝换变体、撤退或回档后重算首奖。
4. 花费金币的处理路线每次最多40金，材料消耗最多一份普通材料；有免费行动替代。较大的运输/商业条款继续走已有商约，不在奇遇里隐性扣上千金币。
5. 新图志收藏或纪念称号采用外观/记录价值，不堆永久百分比属性。不同结尾的主奖等值，普通职业与普通伙伴都可完成。
6. 传说宠物保持高阶历练通关/魂晶寻访；传世鹿120胜领取；传世武器9万金、20胜条件保持。奇遇补材料与阶段预算，不绕过大额目标。

新16模板全首通最多8920金，叠加原主线5950、支线6995、原三奇遇2480，任务表内累计24345金。此数为所有相关内容都完成的上限，不包括战利和出售，也不是每个角色必须取得的预算；仍需扣强化、导师、补给和培养支出。

## 9. 人物回访与持续世界

每个模板有一处小范围留物或人物回应，状态从保存结尾重建。不同结尾相互排斥的留物只显示对应一处；可同时完成的故事不覆盖同一地点、不给彼此堵路。

旧三条各追加一个后续短回应：老赵第一次上台后的递词请求、陆七喂鸟箱的失物消息、岑雪夜炊后新兵带来的菜谱。前置读取原记录，不追加原480/800/1200首奖。回应每次只出现一个，手记可按人物与地区查阅。

新故事可使用现有地区信任和主线选择作对白背景。信任高只增加提示/某条省事路线，不永久锁掉其他完成方式；稀有伙伴仅提供额外观察提示，没有它也能找到证据。

## 10. 数据与存档设计

### 10.1 文件与职责

- `data/roaming_events.json`：16个模板、事实变体、阶段图、兼容条件、结尾、奖励和后续回应。
- `data/encounter_spawn_sites.json`：已验过的地图位置、标签、前置门/地图旗和避让半径。
- `data/encounter_schedule.json`：地区池、出现概率、未遇保障、避重复和奖励限额。
- `EncounterDirector`：合格旅次、有效行为ID、调度、生成快照与发现状态。
- `RoamingEventService`：具体实例的步骤、选择、成本、战斗、补救、结尾和奖账。
- `SpecialEventService`：旧三条兼容入口；新系统不将旧记录换成临时随机ID。
- `MapScene`：实际发现、实体生成、操作和场景变化；面板只展示与提交操作，不能直接修改奖账。

### 10.2 模板结构示意

示意列出了字段职责，不是可运行的完整任务。实际阶段图必须包含允许转换、目标实体、证据要求、补救与兼容事实，禁止把状态名称写入JSON就当玩法完成。

### 10.3 v7→v8

新增 `prog.roaming_events`，包含稳定种子、旅次序号/有效行动、调度计数、活动实例、近期模板、首奖/变体记录和归档。一次实例至少记录：

`instance_id / template_id / revision / trip_id / seed / region / spawn_site / fact_variant / followup_plan / phase / evidence_ids / branch_history / consumed_entity_ids / pending_battle / ending / reward_snapshot / claim_tx`。

迁移只补空新容器。原三条的 `special_events.records`、旧装备、旧钱包、旧主线与领过的奖账逐字段保留。活动实例保存**内容快照**，模板后续改文案/地图位置时仍能继续旧版本；旧落点失效时提供同阶段的安全替代点，不丢进度也不重掷事实。

出现前先保存；存档失败则不在地图上生成。奖励与消耗、分支、旅次限额、地图旗和去重账本同次提交。发奖成功而实体重建失败时只重建状态，不补第二份奖励。收存档数据时严格校验ID、版本、阶段、选择与票据，坏数据保留备份并拒绝覆盖。

战斗使用当前装备/职业/伙伴，开战前冻结完整配置、种子与本实例票据。主世界奇遇继续独立遭遇及两瓶临时药剂规则，避免不可预见地消耗行旅药剂；历练事件战斗遵守本局持续生命/药剂规则，必须在进入前提示。

## 11. 交互和像素美术

- 面板保留纸面、清楚字体、故事区滚动和底部固定操作；一次最多三个选项，不并排塞小字。
- 复杂证据用“看一件→获得一条记录→回选择”呈现；迷你地图只展示已发现且手动追踪的目标，未见内容保留剪影/传闻。
- 地图动作优先复用已有角色与道具；新NPC小轮廓、一到两名同屏，简单衣服和点状五官，少量主色，最多两级常规明暗。不生成复杂盔甲、密集挂件、真实面孔或伪像素的细纹插画。
- 卡面以128×128逻辑像素构图为目标，角色约16—24像素高；优先少物件、明确动作。在现有160像素图窗内居中显示128像素画面并留边，不做1.25倍拉伸；其他放大使用整数倍最近邻，原生像素块与文字渲染分开。
- 生图先做第一批四张卡面和必要道具；逐张查看角色数量、方形像素、颜色、轮廓与在160像素图窗中的辨识度，不合格就针对性重画。后续可复用道具与人物，不为每个随机组合生成整套美术。
- 480×800、480×1067均检查；触控、返回键、焦点和GM覆盖不能穿透。读对话时世界移动与其他事件触发暂停。

## 13. 验收与退出条件

### 调度与随机分布

- 同种子、同旅次、同事实产生相同快照；更换种子能覆盖两个事实、三个结尾的合法组合。
- 至少10000个**合格机会**样本检查出现率、类型条件权重、未遇保证和罕见追寻保证。概率区间预先按抽样误差制定，不能先看结果再挑阈值。
- 切图、休息、重进、读档、传送和重复回调不增加机会、不重掷已生成事件；无合格池和进行中上限不累计虚假保障。
- 导演随机流不改变战斗/掉落/寻访随机流；同一旧历练种子布局和待结算保持。

### 内容与实际操作

- 每模板两种情境都有证据与可行路线，至少三个实际结尾；错误、求援和补救能从场景动作走到结尾。
- 实体位置交互范围内可站立、从入口实际可到达；灯、桌位、人物位置确实随操作改变，重新进图保持。
- 四职业、普通伙伴与无稀有伙伴都可完成首批；自愿战斗可撤退，求援后仍能收尾。
- 主线36步、原36条支线、店铺、交通、结局和18张主世界地图入口按实际表核对；不新增强制钥匙。19个故事入口/模板不计作地图数量。

### 奖励与恢复

- 新模板首奖总上限8920；换变体、换结尾、重复NPC、跨进程确认、满包或中断不能增加首奖次数。
- 重复故事金币与其他三币为0；材料按旅次最多两份且回收价值不超过100金。未领取状态持久保留，超额不会发两次。
- 旧三条保持原记录和2480奖励口径；v7夹具迁移后钱包、装备、主线、角色与旧奇遇完全相同。
- 保存失败覆盖生成、接取、付费、机关、战斗结算、补救、复命和领奖，内存与磁盘均恢复可重试状态。
- 活动实例在第二进程恢复，内容版本变化也能继续；不是只在同进程缓存里“恢复”。

### 交付证据

新增检查按导演、状态机、地图输入、跨进程、旧档和经济边界组织；当前75项作为基线，runner预期数随真正增加的用例表更新。提供每条样板接取至结局的操作记录、短屏/长屏画面与保存失败日志；截图不能代替玩法验证。既有退出资源诊断issue #43继续单列。

## 14. 首批落地前的待定数值

35%出现率、三次未遇后保障、13次罕见追寻、220像素发现范围、材料旅次上限为首轮可调整设计值。先按这些值完成样板并测样，再根据真实短旅程的长度和事件打断感调整；不通过额外增加常规金币弥补剧情吸引力不足。
