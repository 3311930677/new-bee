# 《远征》玩法缺口补齐方案（单机优先）

提案日期：2026-10-06。
依据：`docs/2026-10-05-整体玩法与数值审计.md`（现状基准）、`docs/原版玩法全景.md` §11（原版实录）、`docs/plans/2026-10-02-gap-audit-vs-target.md`（G-01~G-24 编号体系）、2026-10-06 实机录屏逐秒拆解与远征现状对照。

定位：补齐**不需要联机就能做**的玩法缺口，按「玩家收益 ÷ 改动风险」排成三个交付包。联机层（聊天/好友/组队/公会/婚姻/真人 PVP）不进本方案，走审计 §12 已有联机路线。

2026-10-06 评审后执行修订：用户确认增加类似原版的特殊事件情节，并要求生图保持真像素风、人物简洁。**先交付包 P「人间奇遇」**，让接取、调查、处理方式、意外遭遇、复命选谢礼形成可玩的故事；仓库作为后续配套。A/B/C 的原始规格留作待实施项，以下取舍覆盖原排期：耐久后置，活动优先内容变体；新装备保留基础三孔，第四孔作为可选后期目标；速度宝石同时评估普攻频率与回能收益。原始「41→44」检查计数作废，开工基线为72项，奇遇交付后为74项。

## 包 P：人间奇遇（本轮交付）

2026-10-07 后续随机内容的详细规格见[随机奇遇与特殊事件扩展方案](2026-10-07-random-encounters-design.md)：规划新16模板、调度与变体、四条首批纵切，以及八主题历练事件深化。该扩展当前为设计状态，原三条交付状态保留。

| 奇遇 | 开放条件与入口 | 处理方式 | 后果与成长用途 |
|---|---|---|---|
| 一封错送的喜帖 | s12 后，昭元边城喜帖 | 查戏票后问清落款，或替信使从野狼处追回红绳 | 老赵被戏班请去演亲家；金币480，伙伴粮3或攻击宝石Ⅰ1二选一；边城留下戏帖 |
| 会挑主人的宝箱 | s20 后，沉渊港宝箱 | 查爪印与白羽，用任务提供的鱼干引出潮鸥，或赶走盐甲蟹 | 陆七的宝箱变成喂鸟箱；金币800，伙伴粮5或精炼石2二选一；港口留下喂鸟箱 |
| 雪关夜炊 | s28 后，霜关驿夜炊灯 | 追查面粉脚印，帮岑雪端汤，或先赶走兽影 | 宁砚的生辰夜炊写入轮岗簿；金币1200，资质果1或精炼石3二选一；驿站留下夜炊灯 |

- 每条只领一次；两种处理方式的奖励相同，人物回应不同。资质果可能洗低，选择前明确提示。
- 奇遇战斗是可撤退的独立遭遇，满生命入场，带两瓶临时药剂；不改变行旅生命和药剂，不额外掉落材料、不代替主线击败目标。使用当前职业、装备、授业分支与伙伴，开战时冻结完整配置及固定种子；中途退出后继续同一开场，战败或撤退后可整备重试。
- 奖励真实进入现有背包道具，金币、已选谢礼、结局、去重账本同次提交；写盘失败全部回滚。新增存档版本 **v7**，v6 逐版迁入空奇遇记录，旧主线、物品、装备与金币保留。
- 当前阶段驱动地图入口、目标导航和完成陈设；完成后的分支与谢礼进入行旅图志「人物手记」。长文可滚动，返回键和返回按钮可关闭。
- 新插图用内置 image_gen 生成，三张分别保存至 `image/special_events/`；人物限一到两名、简单服装和点状五官，运行时使用最近邻采样。提示词见该目录 `prompts.json`。
- 交付状态与检查证据见[人间奇遇交付记录](../2026-10-06-special-events-delivery.md)。后续三环悬赏与新的装备/伙伴成长节点仍待单独制作，未计为本轮已完成。

## 1. 包 A：仓廪（装备交付链补全）

### A1. 独立仓库

**目标**：为满包（60 格上限）提供长期解法，跨地图共享。

- 入口：三城物资铺开通仓库页签（不加新 NPC，复用既有商铺界面骨架）。
- 容量：初始 60 格，可扩容，每 +20 格一档，金币收费逐档递增（首档建议 2,000 金，档差 +1,500）。
- 存取规则：仅整件存取，不开放远程操作；装备锁定状态随条目保留；任务物品禁止存入（沿用背包锁定逻辑）。
- 数据：存档新增 `stash` 数组，条目结构与背包装备同构（id/强化/宝石孔/耐久等全字段）；扩容档位存 `stash_capacity`。
- UI：背包面板改双页签（背包/仓库），遵守 G-13 收敛的「选一件 → 看差值 → 决定操作」单操作线，不新增并排小字块。

### A2. 装备打孔

**目标**：把「固定 3 孔」改为成长线，新增一个中期消耗出口。

- 修订规则：装备保留初始 3 孔，可在工坊打孔扩展至第4孔；取消把新装备降到1孔再随机补回的前期负担。以下原第2/3孔概率规格停止执行，第4孔消耗与保底需在该包实施前重新定稿。
- 消耗：新道具「穿石锥」+ 金币。穿石锥来源：物资铺出售（建议 240 金）+ 历练精英节点掉落。
- 成功率：第 2 孔 90%、第 3 孔 65%、第 4 孔 40%；失败不损已有孔，每次失败 +15 个百分点（沿用强化的失败积累手感，保持经济语言一致），成功后清零。
- 数据：`equip.json` 条目新增 `sockets` 字段（已打孔数）。旧存档读取时**默认补 3 孔**，不亏待既有玩家。
- UI：工坊宝石块内加「打孔」操作，与镶嵌同页，不另开面板。

### A3. 5 属性宝石

**目标**：宝石从攻/防/血三类扩到五类，覆盖暴击与速度两个已有面板属性。

- 新增：暴击宝石、速度宝石，各 5 级，数值曲线与三类宝石同密（低阶小幅、高阶陡增；具体数值在实现时对照审计 §5 表定稿）。
- 合成：沿用「三颗同级 +300 金合成高一级」树，五类统一。
- 产出源：新两属性宝石**不进普通商店**，只进历练奖励表与荣誉兑换（荣誉兑换现有三阶攻/血宝石，同步补齐档位），形成金币↔荣誉双出口。
- 数据：宝石定义表扩两列；背包/仓库条目复用现有宝石结构。

### A 包验收

- 新增 `VerifyStash`（存取/扩容/迁移）、`VerifySockets`（打孔概率与失败积累）、`VerifyGems5`（五类合成与兑换），runner 用例 41 → 44。
- `VerifySave`（迁移链 +1 版本）、`VerifyEconomy`、`VerifyPanels` 必须全绿。
- 存档迁移测试必须覆盖「旧档装备无 sockets 字段 → 默认 3 孔」路径。

## 2. 包 B：回响（金币回收 + 通关后内容）

### B1. 耐久修理（轻量版，b2 方案）

**目标**：为满级后的金币新增一个稳定回收口，同时不给战斗增加挫败感。

> 设计取舍：曾评估标准版（战斗掉耐久、归零属性减半），因改动 `VerifyBattle` 全链路且回归风险大，且与「主线压力偏轻、体验优先」基调冲突，**选定轻量版**。若后续联机阶段需要更强金币回收，再评估升级为标准版。

- 规则：耐久只影响**修理费与出售价**，不惩罚战斗属性，玩家战斗无感。
- 数值：每件装备耐久 100 起，每场战斗结算 -1（撤退不计）；低于 30 时出售价按比例折损；铁匠/物资铺修理按「强化等级 × 单价」收费。
- 数据：装备条目新增 `durability`；旧档读取默认满耐久。
- UI：工坊加「修理」入口；背包条目差值区显示耐久与预计修理费。

### B2. 剧情回顾（往事回廊）

**目标**：补齐原版「剧情回顾」缺口（全库 grep 确认现无此功能），给通关后玩家回看主线。

- 入口：图志面板新增一页「往事回廊」。
- 内容：按四幕分章收录已触发的关键对话与演出文本（数据直接从 `story_quests.json` 现有文本派生，**零新文案成本**），每章显示完成度百分比。
- 数据：回顾解锁状态由主线进度直接推导（已完成步骤即解锁），不新增存档字段；只新增一个派生索引表（构建时生成或读取时惰性构建均可）。
- UI：复用图志单卡轮播骨架，标题字距沿用「宠 物 图 鉴」样式。

### B 包验收

- 新增 `VerifyDurability`（耐久累计/折价/修理扣费）；`VerifyLore` 扩展回顾页断言。
- `VerifySave` 迁移链再 +1 版本；`VerifyEconomy` 覆盖修理费回收。

## 3. 包 C：热闹（空壳入口落地）

### C1. 限时活动内容

**目标**：让活动中心从「暂无正在进行的活动」变成有内容可玩。参考 `2026-10-05-activity-config.md` 的字段约定。

- 首批 3 个模板（均走**经济日**驱动，不碰现实时间，规避审计 §6.3 记录的 UTC/本地日期键混用风险）：
  1. **周末双倍**：历练远征币奖励 ×2（按经济日周期轮换）；
  2. **集市日**：当日贸易出售价上浮 15%；
  3. **演武挑战周**：段位分胜利加成临时上调。
- 注意：现有 activities 结构是「公告与说明」，**奖励领取与活动计数未接入**——本项必须实现真实加成逻辑（在对应结算入口按活动开关乘算），不可只写公告。这是 activity-config 文档明示的红线。
- 数据：`activities.json.events` 填充；结算侧新增活动开关查询函数。

### C2. 本机排行榜

**目标**：演武与历练的本地成绩记录，提供长线追逐目标。

- 记录项：最高连胜、最快主题通关（分主题）、单场最大伤害、累计远征币。
- 存储：`user://` 纯本地文件，不做任何真实性校验；联网后由服务器接管（与审计 §6.1 保底计数同口径）。
- UI：演武场入口旁加「本机记录」页，**明确标注「本机记录」**，避免与未来真人排行混淆。

### C 包验收

- 新增 `VerifyActivities`（活动开关对结算的实际乘算，非仅展示）；`VerifyArena` 扩展本机记录断言。

## 5. 风险与回归策略

- **每包一个存档版本迁移**，禁止跨版本跳写；迁移失败必须回滚到待领区机制而不是丢弃数据。
- 回归基线：开工前跑一次全量 runner（注意 `-Expected` 与用例表一致，历史计数不可比）；每包交付时全绿 + 新用例通过。
- 旧档兼容三原则：仓库为空、装备默认满耐久、装备默认 3 孔——三个默认值保证旧玩家零损失。
- UI 改动全部走既有切角+硬影规范与单操作线原则，不引入新的视觉语言。

## 6. 交付顺序与里程碑

1. **M0（包 P）**：三城奇遇 → 六条分支 → 地图后果/图志 → 旧档与真实操作验收。
2. **M1（包 A）**：仓库 → 5 属性宝石 → 可选第四孔；职业机制天赋另行评估。
3. **M2（内容深化）**：三环悬赏样板 → 装备或伙伴成长节点 → 往事回廊。
4. **M3（包 C 修订）**：固定种子历练/条件挑战活动 → 按职业与条件分开的本机记录；双倍收益仅作附加福利。耐久后置。
5. 每个里程碑交付时更新本文档状态列，并在 `docs/` 追加对应交付记录。
