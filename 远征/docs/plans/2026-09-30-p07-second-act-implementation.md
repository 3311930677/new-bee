# P07 第一批：第二幕「水下的账」可玩纵切

本文件细化[总方案](2026-09-24-yuanzheng-master-plan.md)的 S5 和[交接卡](2026-09-27-next-agent-implementation-handoff.md)的 P07。P06 已有三站四货、订单与 v6 存档；第二幕沿用同一现货表、WorldSession、QuestService 和 RewardLedger，不另开平行世界或替代主城。

## 1. 交付范围与顺序

| 包 | 运行时交付 | 过门条件 |
| --- | --- | --- |
| P07-A 城镇复用 | `CityScene` 按 `city_id` 读取建筑、NPC、出生点、服务入口；昭元边城维持原数据与旧档坐标，沉渊港有码头主街、两侧店铺/人、仓库/工坊/船务/宠物等真正可走可用入口 | 两城独立进出、原城建造与委托回归；无空白图标页 |
| P07-B 地图与故事前段 | 枫林古道东侧通旧盐道，旧盐道通沉渊港；双向到达点和安全路；主线 `s13–s16` 完成接事、查账、抵港、和港务对话 | 从第一幕复命后实际步行到港，切图读档保持坐标，怪物只游荡接触 |
| P07-C 地图与故事后段 | 港东潮痕滩、水闸副本；`s17–s20` 完成调查、接战、首领、港内交付；潮滩可选首领盐鳞王 | 四职业可返城复命；失败、逃跑、重进和领奖幂等 |
| P07-D 养成与生活 | 首枚可孵化宠物蛋、普通鱼三钓点、船运订单与港口价格事件、首段港务人物关系；装备孔/宝石沿 P04 实例加字段 | 有来源、消耗、地图呈现和战斗反馈；不参与新系统仍能通主线 |
| P07-E 音画与验收 | 港口、盐道、滩涂、水闸各有独特地貌/路网/NPC/敌影；水闸首领可辨预兆；480×800 与长屏截图、四职业完整流程 | 不是换色背景；全量回归、旧档迁移、场景路线、Android 触控检查 |

每包必须留下可运行纵切和测试；只新增数据名或地图菜单不算交付。先完成 A+B 并从第一幕真实复命接入，再制作 C/D，最后 E 验收。

## 2. 地区连通与状态

```text
昭元边城 ↔ 枫林古道 ↔ 旧盐道 ↔ 沉渊港 ↔ 潮痕滩 ↔ 水闸
                    （第一幕 s12 后开放）           （s18 线索后开放）
```

- 地图稳定 ID：`old_salt_road`、`shenyuan_port`、`tideflat`、`tidal_gate`。所有出口有反向出口与独立到达点；旧玩家留在昭元边城/碑窟的坐标不重写。
- 旧盐道识别点为断桥盐车，港口为双层栈桥和潮位牌，潮滩为随潮露出的盐纹，水闸为闸门与退潮通道。每图至少一名可记住的人或固定事件，不在安全港口主街刷怪。
- 第一幕 `s12` 已完成而 `story.step == ""` 的存档，应只补入 `s13`；已记录的 `done[]`、装备、四币、P06 行情和地图位置保持原值。此内容扩展可用幂等归一化，不允许重放 `s12` 奖励。
- 现有第一幕稳定 ID `s01–s12` 不改。第二幕 `s13–s20`、第三幕 `s21–s28`、第四幕 `s29–s36`。总方案的“32 步”已更正为 36 步，避免删改已发布的第一幕存档键。

## 3. 第二幕八步的玩家行为

| 步骤 | 玩家目标与地点 | 真正的互动/战斗 | 结算与世界变化 |
| --- | --- | --- | --- |
| s13 | 昭元边城找行脚商人问盐账 | 对话；与现货入口并存 | 获旧盐道线索，不强制先跑商 |
| s14 | 通过枫林古道到旧盐道 | 访问事件、盐车痕迹可看 | 开旧盐道图鉴、前往港口方向 |
| s15 | 在断桥盐车拿回缺页 | 固定实体采集；战斗可选 | 单次事务发账页，读档不再刷 |
| s16 | 抵达沉渊港交给港务人 | 新城市 NPC 对话 | 港口生活/船运第一层开放 |
| s17 | 潮痕滩调查涨潮货堆 | 探索、可观察潮位线 | 判断货失踪与闸门有关 |
| s18 | 击败潮滩守卫并取闸门线索 | 明雷同图战斗，首见固定线索 | 开水闸入口；死亡不丢主线唯一线索 |
| s19 | 水闸击败潮蚀司祭 | 两阶段预兆/破绽机制，首胜幂等 | 固定首通素材与水闸世界旗 |
| s20 | 回港交账并作供货选择 | 两个等值经济选择，预览影响后确认 | 港口价格事件、台词和栈桥外观变化；不锁后续主线 |

盐鳞王放在潮痕滩可选路径，有独立明雷和首胜奖励；不是 s18/s19 的硬门槛。船运订单使用 P06 实物、时限和事务接口，亏损可由稳定工作恢复。

## 4. 工程边界

1. 把 `CityScene` 目前写死的单城配置、NPC ID、建筑位置和复用面板入口按 `city_id` 参数拆成数据驱动层，先用昭元边城旧表跑原 31 项回归，再导入沉渊港表。旧 `G.city` 的昭元城建状态保留；新港状态另有稳定键。不要让进入港口重置旧主城。
2. `TableCache` 新图与 NPC 引用校验：出口双向、到达点、怪物表、掉落表、主线目标、NPC 立绘/动作。图片必须运行时接入，不以文件存在代替。
3. `QuestService` 仍按步骤 ID 接世界事件，新增固定采集和选择事件时复用一次结算；战斗只提供结果，剧情、图鉴和经济价格读同一旗。扩表前补旧 `s12→s13` 存档测试。
4. 港口现货是 `EconomyService` 新 `site`，其日价仍由 `seed/day/site/good/事件` 决定。新船运订单锁净报酬，禁止同城买卖套利和读档重复结算。
5. 宠物蛋是有来源的背包道具，孵化在港口兽栏或随行面板完成；获得、重复转换、成长和协战有单独服务与事务 ID。钓鱼只给普通材料/图鉴/订单，不掉主线唯一物。

## 5. 必备验收记录

- 昭元旧档（`s12` 已完成）升级后：四币、装备 UID、坐骑、宠物、六支线、P06 行情/运单原样保留；`s13` 可开始，`s12` 奖励不重发。
- 新档四职业从登录到第一幕复命，再步行经古道/盐道到港、潮滩/水闸、回港；每图死亡/逃跑/程序重启后坐标与任务不倒退。
- 沉渊港和昭元边城各一张 480×800 与 480×1067 图；新野外两张、两场首领战、背包/宠物/行情/钓鱼各一张，检查字体、触控与像素比例。
- 旧 31 项全量回归持续通过；随着新场景加 `VerifySecondCity`、`VerifySecondAct`、`VerifyFishing` 等，调整准确用例数并记录每项自己的成功标记。
