### R-04 P0：正常游戏保存仍是直接覆盖写，断电／进程终止可能损坏唯一存档

- 证据：`src/autoload/G.gd::save_game()` 直接 `FileAccess.open(SAVE_PATH, WRITE)`，随后写完整 JSON；`SaveData.write_text_atomic()` 只由导入路径调用。其 Windows 分支先删除目标再重命名 `.tmp`，删除与重命名之间仍有无主档窗口；正常保存也没有滚动备份。
- 影响：P02/P03 文档宣称的“切图或结算中断后可恢复”目前只在内存字典模拟中成立；文件写到一半被终止时，下次启动可能把档判为非法并锁住。29 项回归没有杀进程中断写盘或磁盘故障注入。
- 实施：统一 `G.save_game()` 与导入写盘到一个安全存储接口；先完整写临时文件并回读／校验，保留上一份有效档，替换失败时恢复。启动时识别主档／临时档／上一份的有效版本并明确选择，不让“主档缺失”静默变成新档。写盘失败需返回错误，结算 UI 不得显示“已领取”。
- 验收：在临时写入、旧档备份、替换、新档校验四个点注入失败与进程中止；每次重启至少有上一份有效档，钱包、账本 ID、装备 UID、主线步骤相互一致；真实玩家存档哈希不变。

### R-05 P0：存档 v5 只校验容器外形，装备引用与 UID 一致性未验

- 证据：`SaveData.validate()` 检查 `inventory.instances/pending` 是数组、`next_uid` 是数值、`equip.*` 为非负整数，却未检查实例字段、UID 全局唯一、在身 UID 是否存在、槽是否匹配、`next_uid > 最大 UID`。`_ensure_v5()` 遇到数值装备指针直接跳过；`Inventory.new_instance()` 直接使用 `next_uid`。
- 影响：形如 `instances:[{uid:7,...}], next_uid:7, equip:{sword:7}` 的 v5 档可能通过校验；下一件掉落再次使用 UID 7，换装、回收和背包计数会指向错误实例。缺字段的实例也可能在 UI 或战斗数值路径被当作空装备。
- 实施：在迁移前后分别做结构校验；当前版本的损坏容器不得先被 `_normalize()` 替换成空数组。检查实例必需字段、允许的槽/模板/稀有度、UID 正整数且跨 `instances+pending` 唯一、装备指针确实指向同槽拥有池实例、`next_uid` 大于所有历史 UID。对可确定修复的 `next_uid` 先备份再提升；无法判断的丢失引用锁档并给出恢复入口。
- 验收：重复 UID、悬空指针、跨槽指针、错误模板、`next_uid` 回退、`pending` 与拥有池撞号分别有夹具；无一例静默删物或复用 UID。

### R-06 P1：P01/P03 的“可走可战”仍缺整条真实操作链

- 证据：`tools/PreviewMainWorld.gd::_walk_to_farthest_exit()` 每张图独立创建场景，强制怪物 `chasing_contact=true` 以屏蔽遭遇，遇阻还用 `_nudge()` 辅助绕行；古道记录 `stuck=10`。P01 文档也注明“跨图连续返城未验”。P03 验证覆盖场景断言与状态机字典，但没有同一新档的进城→接怪→胜／败／逃→切图→碑窟→返城→重启恢复。
- 影响：单图 `WALK_OK` 与单场战斗通过，不能证明主线全流程没有出口误触、卡位、状态残留或连续转场后错图刷新。
- 实施：加一条不冻结怪物、不调用 `_nudge()` 的 480×800 输入回放；记录每图入口、接战、结算、出口与重载后的实际状态。导航卡住时输出碰撞对象与坐标，修地图／碰撞，不把工具绕行记作通过。至少覆盖骑士与另一职业，以及普通怪／剧情首领。
- 验收：一份新档走完 `s01–s12` 并返城；中途真正触发胜、败、逃、满包掉落、任务物交付，再退出进程重开；每一步能继续，奖励只到账一次。

### R-07 P1：奖励账本忽略装备发放回调的失败结果

- 证据：`RewardLedger.apply()` 对 `host.inv_grant_equip(spec, false)` 的返回值不检查，随后仍把事务 ID 写入 `ledger.applied`。`G.inv_grant_equip()` 在装备模板未知时返回 `{ok:false}`。
- 影响：数据表漏项或版本不匹配时，账本会记“已发放”，但玩家没有得到装备；重复结算也无法补领。
- 实施：应用前预校验所有 `equip:` 奖励的模板、稀有度与数量；发放回调返回失败时不得登记事务 ID，也不得留下已扣成本／已发的其他奖励。可先在副本状态中执行再整体提交，或让事务计划阶段只产生经过校验的变更。
- 验收：夹具用不存在的模板、合法模板、混合金币／道具／装备及满包，断言失败零副作用、成功只应用一次。

- 验收：四张主世界图与同图战斗在一套可复用色板和字体层级下通过 480×800 同屏审核，资源来源表与替换清单齐全。
