# 《远征》界面精修方案：字体、排版与材质统一

> 本版保留为第一轮记录，视觉方向已被 `2026-10-03-ui-art-direction-v2.md` 取代。用户指出本版方框重复、配色单一，V2 改为页面构图、物件入口、按用途设计控件和场景色彩。旧排版板不作为后续美术验收标准。

状态：设计提案，尚未改动游戏界面或字体资源。以当前源码、字体内部名称，以及营帐、登录、背包、技能书、归路任务和第四幕战斗截图为依据。后续实施沿用现有页面入口、操作和存档协议。

## 1. 推荐方向

采用“像素行旅 RPG”的界面语言：安静的深青底、暖纸内容、精细硬边、小面积旧铜装饰。图形表达装备、地图、人物和行旅工具，页面具有明确阅读顺序。主要操作、资源数值与装饰分别分配不同的视觉权重。

精致感主要来自排版、字重、对齐、信息取舍与素材之间的协调。木纹、纸纹和角饰只用于说明材质；装饰不应覆盖整张页面，也不应与重要操作争夺注意力。

## 2. 当前问题与依据

| 可观察问题 | 当前依据 | 改进方向 |
|---|---|---|
| 大标题与页面内容分离 | 多页都在大块纸面上方悬挂独立木匾；背包、登录尤其明显 | 将页面标题整合到页头，木牌保留给城镇告示、门牌等真实木质载体 |
| 很多操作同样突出 | 背包“装备/锁定/卖出/返回”都使用金色实心按钮 | 主操作、次操作、返回、危险操作四种语义；同一任务区集中一个主操作，等值分支使用并列选择组 |
| 留白缺少内容组织 | 背包列表和详情、技能名与珠子之间有较大固定空白 | 用列表、属性表、效果说明、固定操作区组织；长屏增加可见内容，避免把纸面空白等比拉长 |
| 缺少自然阅读顺序 | 营帐入口、技能页的标题、级别、说明、数值大量居中 | 正文/列表左对齐、属性数值右对齐；标题和主操作才使用有限居中 |
| 图标与游戏主体有落差 | UIIcons 为线性 SVG 导航图，人物与物品是像素素材 | 导航图标形成同一套小像素符号；物品、技能继续用实际游戏资产并校正占框比例 |
| 战斗信息争夺角色区域 | 最新首领阶段横幅经过战场中央，名签与召唤物较密集 | 预兆/阶段移到顶部固定区域；命中反馈短时出现在目标附近，角色中段保持清楚 |
| 字体层级不够克制 | 常规 400、粗体 700、宋体 600；字号 15/17/18/24/28/56；若干页面复用金字标题和硬色块 | 正文、UI标题、数值、剧情文字各有明确用途，减少装饰字的覆盖范围 |
| 渲染配置分散 | font .import 和 G._tune_font_rendering 的设置不同；运行时覆盖为灰阶抗锯齿、正文字体无 hinting、oversampling=2；项目默认最近邻 | 用真实窗口做字体渲染对照，集中配置；像素图与动态文字分别验收 |

已读取 sfnt 内部名称，确认 NotoSansSC-Regular/Bold 文件确实为 Noto Sans SC，字重 400/700；NotoSerifCJKsc-SemiBold 为 Noto Serif CJK SC，字重 600。没有证据说明字体文件本身由 AI 生成。“AI感”在此是对重复模板、装饰方式和风格拼接的感受。

## 3. 字体方案

推荐两类字体承担不同职责：

- **操作、列表、属性、资源：Noto Sans SC / 思源黑体**。Regular 负责正文，Medium 候选负责页头和按钮，Bold 限于关键数值。当前只有 Regular/Bold，Medium 需在字体样板阶段从官方来源补入并核对字形，不能用描边模拟粗体。
- **对白、书信、短叙事：霞鹜文楷屏幕阅读版候选**。给人物说话与行旅记录增加自然书写感；数值表、操作按钮仍采用黑体。此字体尚未接入，需要用长句、繁复汉字和小屏截图确认可读性。
- 《远征》两字的品牌字标单独检查笔画与轮廓。常规页面标题采用 UI 字体；宋体木匾不再作为所有页面的统一标题模板。

| 文本职责 | 建议规格，480×800逻辑尺寸 | 排版 |
|---|---|---|
| 页标题 | 黑体 Medium，24px | 左对齐，与内容栏对齐 |
| 区块标题/物品名 | 黑体 Medium，19–20px | 左对齐；物品名不整行染稀有色 |
| 正文/按钮 | 黑体 Regular/Medium，18px | 正文行高约26px；按钮自然字距 |
| 辅助信息/状态 | 黑体 Regular，16px | 只用于短状态，不承担主要说明 |
| 关键资源/对比数值 | 黑体 Medium/Bold，20–22px | 等宽数字能力先检测；不具备时用定宽列对齐 |
| 对白/书信 | 文楷候选，19px | 行高约28px，左对齐；玩家能即时显示整段 |
| 战斗伤害 | 黑体 Bold或单独绘制的数字字形，24–32px | 整数定位、短时停留；不延伸成第三套全中文字体 |

现有“进度 1/1 · 可交付”之类信息缩短为“可交付”，详细进度留在目标区域。去掉为了显得古风而手动插入的字间空格；全局数字、标点、单位与中文基线统一。字体缺字回退必须显式配置并核对角色名字。

渲染样板使用灰阶抗锯齿，比较 None/Light hinting；测试 1×、1.25×、2×及实际窗口缩放，确认细字不糊、多笔画字不粘连。单独比较文字的纹理过滤，不改变整张地图的最近邻策略。像素数字若采用动态像素字体，必须按原生设计尺寸的整数倍使用并关闭亚像素定位。Godot 的参数会因字体、尺寸和缩放而产生不同结果，不能根据注释直接认定某个组合已解决问题。[Godot字体文档](https://docs.godotengine.org/en/stable/tutorials/ui/gui_using_fonts.html)

字体来源与许可随发行包保留：[Noto Sans CJK官方许可](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)、[霞鹜文楷屏幕阅读版](https://github.com/lxgw/LxgwWenKai-Screen)。本方案不安装或替换字体。

## 4. 色彩、材质与组件

| 用途 | 样板色 | 使用原则 |
|---|---|---|
| 深色底/状态栏 | `#1C292C` | 背景退后，资源/状态清楚 |
| 内容纸面 | `#EEE7D7` | 细纹仅作低对比底材，文字区域保持安静 |
| 主文字 | `#303832` | 常规正文、物品名 |
| 次文字 | `#60695F` | 短状态与说明，不用过浅灰字 |
| 主操作/选中 | `#355F59` | 浅米字配深青底；选中也有边条/符号，不只靠颜色 |
| 铜色强调 | `#AE8B4F` | 金币、稀有标识、局部角饰，减少大面积金色实心块 |
| 收益/治疗 | `#3D7457` | 明确的数值变化 |
| 危险/不足 | `#A45243` | 卖出等危险操作、资源不足；同时有文字说明 |

这些是样板起点，浅底/深底的对比都需实测。禁止统一改成一套颜色后就宣称完成精修。

先做八种共用组件：页头、面板、页签、列表行、属性对比、操作按钮组、提示/对话、状态条。外边距 24px，内容内边距 20–24px，间距采用 4/8/12/16/24px。边框一般 1px，少量关键外轮廓 2px；硬边与像素角统一尺度。装饰集中在角和分隔处，内部不重复套多层框。

按钮反馈用色阶、1px下压和短音效；避免把按钮连同文字缩放到0.97造成字形抖动。触控区域保持至少44px高；鼠标悬停、按下、选中、禁用、焦点各有明确状态。禁用按钮显示原因，不能只变灰。

导航图标先统一绘制24px母版，必要时做32px版本；在最终显示尺寸逐个调整轮廓和空白，不机械缩放。物品图标仍走原资源ID，统一透明边距、主体占框比例和像素密度。中英文标点、emoji、线性SVG、像素画的混搭逐页收口。

## 5. 各界面的具体改法

| 页面 | 精修内容 |
|---|---|
| 主世界HUD | 头像、等级、生命合为紧凑状态块；任务只保留名称和下一目标，详情点击展开；小地图与药剂/疾行入口有固定留白，姓名牌缩短并控制遮挡 |
| 营帐 | 保留现有入口与主角；“继续旅程”成为主操作；养成、行囊、世界等入口分组，降低所有入口一样大的木框感；资源栏规整数值与单位 |
| 背包/装备 | 保留现有列表和选中逻辑；列表增加图标、名称、等级和状态，属性按列对齐；装备对比用清楚的加减值；装备为主操作，锁定为次操作，卖出独立并保留确认 |
| 技能/养成 | 页头显示职业与资源；技能图标、技能名、等级、效果组成一个阅读区；升级前后展示具体变化；等级珠改紧凑刻度或进度；其他技能的名称可直接定位，减少无名称圆点导航 |
| NPC对话/任务 | 人物名字与对白层级分开；正文自然左对齐；奖励用小图标与数量；主任务标题、当前目标和交付状态分区；分支放在对白下方，不叠重复正文 |
| 战斗 | 我方左、敌方右，沿用冲刺/命中/回位；首领血条与阶段预兆占顶部固定区；人物中段留给动作与特效；底部四个指令使用统一尺寸，技能详情单独展开；非当前目标的名签降低存在感 |
| 商店/加工/兑换 | 同一资源栏、列表和比较组件；花费与获得分列；强化结果只强调实际变化；不要每一项价格都变成一枚大金按钮 |
| 图鉴/地区/任务列表 | 分区导航有文字名称；条目有状态；空态、未解锁和已完成都用相同组件说明；长列表可滚动，保留原位置 |
| 登录/设置 | 压缩独立悬浮木匾；登录身份与头像选择分组；设置用规整分区、开关与说明，减少大卡片轮播；返回位置全局一致 |
| 结算/奖励 | 战斗结果、核心战利品和继续操作三层；奖励序列短且能跳过；复用物品图标与属性布局 |

## 6. 实施批次与代码落点

**第一批：字体和共用组件。** 建立字体对照板、色板、8种组件与状态。沿现有 `G.gd` 标签/按钮/纸面工厂接入；可将样式定义拆到 `src/ui/`，保留原函数签名与页面调用。收益最大、影响最广；逐项替换和截图检查，避免全局替换后遗漏固定宽高。

**第二批：四个代表页。** 背包、NPC对话、主世界HUD、战斗。它们覆盖密集数据、长文、叠场景和动作信息四种情况。用同一套组件得到稳定样板后，再迁移更多页面。背包和对话优先，战斗动作协议沿用现有实现。

**第三批：全菜单迁移。** 营帐、技能、装备、宠物、坐骑、天赋、商店、加工、任务、图鉴、地区、登录和设置。`PageDeck` 的现有交互按具体页面保留或换成有名称导航，不能只让所有卡片换皮。

**第四批：美术细节和完整验收。** 导航图标、物品占框、边框材质、字标、状态动效、短音效；补长屏、小窗口、真实输入和Android检查。地图人物/建筑之间的风格差异另按场景美术计划推进，保持已约定的主角重绘暂缓。

主要落点：`src/autoload/G.gd`、`src/ui/UIIcons.gd`、`src/ui/GameHome.gd`、`src/ui/BagPanel.gd`、`src/ui/SkillBookPanel.gd`、`src/ui/PageDeck.gd`、`src/city/CityScene.gd`、`src/explore/MapScene.gd` 与 `src/battle/BattleScene.gd`。本方案不更改战斗公式、奖励、NPC入口和存档字段。

## 7. 验收标准

- 480×800与480×1067都检查，缩放到实际窗口后仍可读；长屏用于更多内容和更好的间隔，不任意放大文字。
- 第一眼能找到页面名称、当前选中项和主要操作；所有页面的返回、页签与资源栏位置有共同规律。
- 同一屏不出现多个竞争的标题/按钮样式；中文自然字距，主要说明不压缩到小于16px。
- 多笔画字、数字、标点、长物品名、长角色名与缺字回退有专门样例；有无遮挡、无截字的原尺寸截图。
- 主世界姓名牌、任务条、小地图不遮挡关键人物；战斗阶段提示不盖住双方站位与接近命中动作。
- 空背包、满背包、无材料、满级、已锁定、已装备、待领取、存档受限等状态都清楚，且不依赖单一颜色。
- 升级、换装、交付、翻页、返回与读档用真实输入验证；既有回归继续通过。程序通过与视觉通过分别记录。
