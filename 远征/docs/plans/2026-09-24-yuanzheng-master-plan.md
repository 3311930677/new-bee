## 0. 总目标与不可改变的产品约束

**目标是一款可以独立玩完的像素奇幻养成 RPG**：玩家从自己命名的角色出发，在改造后的原主城接任务，沿连通地区寻找目标，与地图明雷接触后进入指令战斗，带着掉落物回城换装、加工、培养技能与宠物，并逐步改变世界状态。它保留原游戏“在地图上生活、跨区找人、养成角色和伙伴、做买卖、挑战首领”的乐趣，同时以《远征》自己的昭元／界碑／渊叙事、四职业、历练构筑、地区事件和更透明的经济规则形成新作品。

1. **改造现有主城，不另开一个江湖。** `lorin_wilds` 保留为兼容旧档的内部地图 ID；玩家看到的是“昭元边城”。目前白色道路作为主街重新绘制，店铺和职能 NPC 沿路左右两侧布置；主街保持可走、可辨，不用怪物堵路。
2. **主世界是默认游玩空间。** 登录或读档进入最近安全的世界位置；`GameHome` 收成营帐／人物与系统菜单。八主题历练、词条构筑、演武、据点、图鉴、召唤等成为世界内可发现的补充玩法，不再是推进主线的必选入口。
3. **保留已成型的四职业与现有投入。** 破军、穿杨、霜语、晨星和已有技能、宠物、坐骑、装备投入继续有效。旧档迁移不吞资源；改造时先写迁移规则，再改存储结构。
4. **只借鉴经观察确认的结构，不照搬原作内容。** 视频可见地区等级节点、可走城镇、明雷、独立指令战斗、任务定位、宠物参战、宝石加工和经济菜单。怪物刷法、掉落、技能倍率、市场结算等未从解包代码证实；本文给出的规则都是《远征》的设计值。用户口述的法王、女神、股票等作为设计线索，名称、概率和消耗重新设计。
5. **单机没有真钱与强制日常。** 完整主线可通过任务、探索、普通掉落完成；抽取、贸易、历练、生活活动提供选择和长期目标。现实时间不决定主线开放，战败不毁存档或掉已装备物品。

## 2. 玩家路径与世界结构

### 2.1 进入、出生、地图与移动

- **登录和命名**：账号名用于登录，角色昵称用于头顶、对话和存档角色卡。首次创角要求输入并确认昵称；旧档保留 `player_name`，为空时只提示补填一次。现在 `G.display_name()` 对非游客优先返回账号名，这一处须改为角色昵称优先，账号只在登录页展示。职业、性别选择有相应头像、地图与战斗外观预览；缺图的组合明确标注待补并由统一原型图替代，不能伪称独立外观。
- **出生点**：新档落在昭元边城主街南段的安全空地，面对接应 NPC，镜头能看见路、路两侧店铺和北向城门。旧档从保存的 map ID／位置恢复；非法坐标、改版后被建筑占据的坐标、战斗中断位置回落最近安全点。地图脚点而非贴图中心定义碰撞和名签位置。
- **地图图谱**：`world_regions` 定地区等级段、章节和连线；`world_maps` 定可走地图、双向出口、落地点、安全点、碰撞、NPC、明雷点、采集点、事件、背景和音乐。走出口触发短过场；离开和返回保持任务事件、资源与短期怪物状态。跨区地区图明确“当前位置／可达／未解锁／建议等级／任务方向”，与历练随机路线使用不同界面和数据。
- **移动与指引**：触控虚拟方向或点击目的地均可用；地图中的目标箭头只在追踪任务时出现，落地点靠近时收起。右上小地图只显示已到过的出口、已发现的 NPC 和当前追踪目标。可折叠目标不超过两行；正常探索下中部不摆长文字。
- **主城格局**：浅色石／土路是南北主街，主街全长保持连续通行。建筑分置两侧，招牌、货架和 NPC 站位避开路中心；门口有可见互动区。市政／接应、导师、商店、锻造、宝石、马厩、宠物、仓库、布告栏、历练入口都迁到这张地图。危险怪只在边缘、城门外哨所或受剧情污染的封锁角落出现；普通生活主街无随机战斗。
- **骑乘与随行**：城中可骑乘但速度设上限，不穿过人群或建筑；窄门与副本入口自动下马。宠物在玩家后方跟随，拥挤处可简化为脚边徽记；不让随行物挡交互按钮。

### 2.3 任务与地区事件精确规则

- 主线状态为 `locked → available → active → objectives_done → rewarded`；奖励领取只可提交一次。任务目标类型至少覆盖 `talk / visit / defeat_instance_or_species / collect / deliver / craft / trade / boss / choose`。击杀由战斗结果事件计数，不在画面返回时另算一次；NPC 对话和物品交付由事务式奖励接口执行。
- 同时追踪 1 条主线和 1 条支线／委托。可接任务不抢占追踪。任务点在本地图小地图上标记，跨地图则标地区图方向；未知区域显示线索而非全图自动寻路。
- 世界旗有三类：永久剧情（桥修复、路障打开、NPC 换位）、地区短期（夜市开放、怪群警戒）、可重玩（采集刷新、每日委托）。永久旗进入档案；视觉、NPC 台词、服务库存和地图阻挡须由同一旗驱动。
- 委托从 `data/quests.json` 的日常结构迁出适配层，目标可涉及战斗、采集、送货、生活活动。12 个模板轮换，一次最多接 2 个；已接委托不因现实跨日消失。目标奖励上限由幕数控制，不可刷取主线唯一材料。
- 任务内容在表内写 `id / prerequisites / objective[] / target_ids / map_id / dialogue_id / flags_on_complete / rewards / repeat_policy`；内容校验器检查引用 ID、循环依赖、不可达出口、缺失 NPC 和重复一次性奖励。

## 3. 明雷、战斗与失败恢复

### 3.1 地图明雷与接敌

- **怪物只游荡、不追人。** 每个刷点有唯一 `spawn_id`、怪物池、等级区间、活动半径、占用上限、重生条件和剧情限制。普通怪离开锚点建议不超过 2 格；精英不走入主街或安全区。视野靠近显示“等级＋名字＋危险标记”，名签按距离淡出；超出玩家可视区可降频更新。
- 角色和怪物碰撞／点击交互进入预警短窗，距离达到配置接触半径后触发一次战斗。若玩家正在对话、过场、打开覆盖菜单或刚返回战斗，接战被抑制；返回后有约 2 秒安全期。对首领可用点击挑战牌确认。怪物不因看见玩家而改变行走方向。
- 进入战斗前生成 `encounter_id`，锁住该实例和世界位置。胜利才消耗怪物并登记其 `respawn_at`；逃跑在原点附近生成安全位并给该怪短冷却；战败返回最近营地并扣一次可明确说明的补给。世界怪单只进入首版战斗；首领阶段可召唤随从，历练保留原多怪编成。
- **建议初始调参**：普通怪重生 60–120 秒、半径 40–80 地图像素、接触半径约 32–42 像素、单图同时可见 4–7 只。当前主城配置的 30 秒、6 点和半径 42 仅是原型值；按实机路宽、刷点密度和平均战斗时长调整。所有刷点不可封堵出口、任务 NPC 或出生安全区。

### 3.2 独立指令战斗

沿用 `BattleSim` 的确定性模拟，世界战斗由 `EncounterContext` 带入敌方实例 ID／等级、地区主题、任务来源、宠物和返回坐标。进入后敌方在左，人物和参战宠物在右；战斗背景取地区地表与光色，主城蓝调与野外绿调是第一批样板。切入、开战、胜利、战败、逃跑、返回原图构成明确状态机，任何中途关闭都能从保存的状态安全恢复。

| 指令 | 单机具体行为 | 必须显示 |
|---|---|---|
| 攻 | 对选中的敌人普通攻击，恢复少量技能资源；目标死亡自动选择存活目标 | 当前目标、预估命中类别、攻击与受击反馈 |
| 技 | 打开最多 5 个已装备技能；技能可选目标时先选目标再确认 | 技能等级、消耗、冷却、范围、核心效果、资源不足原因 |
| 物 | 使用战斗背包的药品和解控品；相同回合／时窗限制由表驱动 | 剩余数量、效果、是否占用行动 |
| 逃 | 普通战斗可尝试脱离；剧情首领提示不可逃或撤回入口 | 成功条件、失败后果与回图位置 |

默认是可暂停观察的手动指令战斗：敌人行动预告清楚，玩家有足够时间选择，不用原视频的 30 秒硬压力作为普遍规则。普通战斗可开托管／倍速；首领的关键预兆必须留给手动应对。战斗只有一个结算源：`BattleSim` 生成 `result_id`，奖励、任务、经验、掉落都按它幂等提交；`BattleScene` 仅播放事件和发送玩家指令。地图返回保留摄像机、角色朝向、刚才 NPC／怪物的状态。

普通怪至少 6 个战术原型：近战压迫、蓄力重击、远程投射、持续伤害、护盾支援、召唤／分裂；在四幕中组合为约 30 个外观和战斗配置。首领每场 2–3 个阶段或明确技能循环，预兆图形与文字双提示。元素只做 3 条可读相互作用（例如寒霜减速、火焰点燃、守护抵消一次控制），避免先铺四套看不见的抗性。伤害上限、减伤上限、速度阈值、技能冷却、药品频率统一进 `combat_balance` 表；四职业均可用普通任务装备独自通关。

## 4. 四职业与角色成长

现有等级上限 60 作为本轮单机战役上限；建议按幕分段 1–12／13–25／26–42／43–60。任务首通提供主线所需经验的主体，战斗提供练技能与掉落；不靠重复刷同一怪数十次补等级。属性面板同时显示基础值、装备值、最终值和用途说明；力量、生命、速度、命中、减伤等若新增必须给公式和上限，杜绝藏关键收益。

| 职业／现有五技 | 主打体验 | 两条专精与单机保底 |
|---|---|---|
| **破军**：裂山、破阵、回风斩、战吼、断罪 | 贴身破防与承伤 | “镇守”偏护盾／反击，“裂阵”偏破甲／群伤；首领单人通关有足够防护和输出 |
| **穿杨**：连珠、贯甲、夺魄、遁影、倾泻 | 远距单体与位置／节奏 | “猎印”偏追击弱点，“游击”偏撤步／控制；速度收益有软上限，不以口述的 280 点作为门槛 |
| **霜语**：霜刃、霜环、天陨、秘盾、湮灭 | 范围、冻结与爆发 | “霜链”偏控场，“星术”偏蓄能爆发；低投入也有秘盾和稳定基础伤害 |
| **晨星**：圣愈、普照、净化、祝祷、破晓 | 支援与持续作战 | “庇护”偏治疗／解控，“晨辉”偏光属性输出；单机时敌人设计不能强迫只当奶妈 |

- 职业基础技能按等级与导师任务解锁；技能在有效命中、有效治疗或有效防护时获得熟练度，单场／单目标有限额，空放不刷。达到熟练节点可选一个可见的行为变体，消耗技能点而非仅提高数值。每个职业至少在 I 幕完成一次“新技能 → 实战练熟 → 导师选择变体”。
- 技能槽首版为 5 个现有技能，分支只改变技能作用和动画强调，不同时生产四职业数十个新按钮。重置专精可在导师处花普通金币并确认，不锁死初次选错的角色。历练取得的技能书改为突破材料或提前体验券，不取代正常解锁。
- 装备需求按等级和职业主属性配置；不同职业的首通奖励提供等价值可用装。等级提升、穿装、骑乘、宠物切换都即时刷新人物页和世界外观；进度条在主世界左上以 Lv／血量／经验呈现，蓝量／技能资源只在战斗或展开状态显示。

## 5. 背包、装备、锻造与宝石

### 5.1 物品与掉落

现有 `items` 是材料数量表，`equip.json` 是固定槽位强化配置。新增背包实例 `inventory.instances[]`，每件装备含 `uid / template_id / source_id / level / rarity / rolled_affixes / enhance / sockets / gems / refine / locked`；材料继续可叠放。槽位先保持武器、护甲、饰品三个类别及职业对应武器，第二幕后才按需要增加副件。背包首发 60 格，可通过仓库和任务扩容；任务关键物品走单独分类且不占格。满包时普通掉落进本次战利品待领取箱并给明确提示，不静默消失。

来源分工：普通怪给基础装备与通用材料，精英给词条候选和宝石原石，首领首次给定向装备或图纸，重打给升级材料，主线给不会落后于推荐等级的保底件，工坊将材料变成指定部位。每种掉落在图鉴或敌人详情写“可能来源”，首通保底和随机池分别显示。装备比较展示穿上前后的生命、攻防、速度与关键技能影响，重要词条有文字解释；换装能在地图武器、背饰或颜色上至少有一项可见变化。

### 5.2 工坊的明确规则

| 服务 | 输入、输出和风险 | 与旧档关系 |
|---|---|---|
| 制作／修理 | 图纸、材料、金币换指定物品；修理只恢复耐久，不制造破产循环 | 现有装备不因新耐久系统失效，迁移后为满耐久 |
| 强化 | 每次显示下一阶属性、材料、费用、成功率、失败后果；低阶 100% 成功，中高阶使用公开的失败积累或保护符 | 旧强化等级等值挂到迁移物品；不暗做“垫装”概率 |
| 打孔／镶嵌 | 消耗明确材料开孔；宝石可取下，取下费用低于重新获取成本 | 旧槽位宝石转入对应初始装备，不丢属性 |
| 宝石合成 | 2／3／5 颗选择可保留原作“投入更多换成功机会”的乐趣，但所有概率和失败返还在确认前显示；首章先用确定性 3 合 1，第二幕后试公开保底 | 当前 `equip.json` 宝石配置先接到真实库存；不照抄录屏 36% 等数值 |
| 精炼／词条 | 选择保留 1 条词条，预览其他条目的可能池和资源成本；设置最大花费确认 | 旧精炼投入按等值继承或补偿，绝不直接清零 |

强化、合成与卖出统一使用“预览 → 确认 → 单次扣除和产出 → 写档”事务。可锁定装备，稀有／已强化件出售和分解二次确认。商店可以随机出现好装备，但同阶段至少有任务或制作的稳定替代品。

## 6. 宠物、坐骑与守碑誓约

### 6.1 宠物是可见伙伴

初始岩龟由 I 幕剧情获得；野外蛋通过生态地点、精英掉落和支线取得；孵化展示物种池、特性可能范围和固定的完成条件。8 只现有宠物先全部得到地图跟随、战斗站位、至少一招可识别动作和图鉴来源。宠物只有一只出战，其他在营地／巢屋；切换不消耗稀有资源，战斗中换宠有行动成本。成长维度为等级、亲密／协战熟练、两项特性与一次进阶，避免连续叠十几条细小属性。

特性首批为护卫（分担一次重击）、追击（角色触发条件后追加攻击）、元素响应（对应元素技能加强或净化）。每只宠物至少一个明确战术角色；普通宠通过孵化和剧情能满足主线。高级伙伴的碎片来自指定首领、长线委托和历练交换，有可查的目标数量和保底；寻访只加快收藏，不拥有唯一高强战力。重复宠转换为该物种成长材料，不直接消失。宠物蛋、碎片兑换借鉴用户提供的原版趣味结构，名称与概率均原创。

### 6.2 坐骑与长期祝福

现有 6 坐骑与两阶数据保留，但升级收益拆成地图速度、特定地形便利和少量战斗准备收益。I 幕至少完成一只完整四向骑乘表现；II 幕扩大到两只；III 幕六只完成。骑乘进出建筑、与 NPC 互动、接战、窄路、宠物跟随都要实测。坐骑不能靠速度穿墙或跳过脚本触发。

用户提到的“女神”长期养成不直接移植，单机后半段设计原创**守碑誓约**：玩家从庇护（失败恢复）、征伐（首领破招）、丰收（采集／贸易）三种契约中启用一种，随地区事件升级，切换须在城镇且费用可承担。誓约材料主要来自主线副本、支线和历练，数值上限以职业／宠物玩法为先；只有在 III 幕内容完成、资源曲线和 UI 验证后才接入，不能成为早期另一个付费式养成面板。

## 7. 单机经济、交易与生活

### 7.1 三层收入与价格系统

金币是日常流通货币；远征币归历练，魂晶归稀有伙伴进阶，荣誉归演武。新增商品用物品，不新增“期货券”“股票币”等冗余货币。金币来源分成稳定收入（任务、打工、战斗）、情报交易（地区差价和订单）、后期风险合约；单条路线不应长期碾压其他路线。

- **现货**：第一幕 4 种商品“谷物、盐、药草、铁料”，三处城／驿有基础价、买卖价差、库存与运输成本。每日游戏内结算一次，但玩家可通过任务、睡营地或旅程推进；不是现实零点。UI 显示现价、近 5 次价格、已知影响因素、携带量和扣除费用后的净收益。地区事件例如“旧盐道修通”改变供给，并在公告、NPC 对话及行情解释中同步体现。
- **稳定工作／订单**：商会搬运、修路、采药和送信是可重复短任务，保证亏掉一次买卖后仍可恢复基础补给。订单绑定有限需求和目的地；提交按目标数量结算，不能在同一城无成本买回、卖回无限赚。任务奖励和经验低于同等级首次主线目标。
- **延期交割合约**：III 幕开放，允许根据公开的 2–3 个游戏内时段预期签小额买入／卖出合约。开仓支付保证金，合约在指定游戏日按可复现价格结算；最大亏损限定为已交保证金，无负余额；同时持仓数和总额上限写入表。价格由种子、地区库存、已发生事件计算，读档后同状态重现。市场不是现实股票，不接服务器行情。首章只交付现货，合约上线前须完成可模拟千次的经济测试和界面风险说明。
- 反套利验收：所有订单扣除物品与资金一次；游戏内时间推进触发一次价格结算；同日反复倒卖、跨城传送、读档、背包满、离线重启均不能复制物品或无限获利。价格参数可调，公式和影响因子对玩家可解释。

### 7.2 生活活动与人际关系

- **钓鱼**：II 幕首开 3 处钓点，小游戏围绕观察水波、按住／松开控制落点和短时收线；普通鱼用于烹饪或订单，少量鱼王有图鉴与外观奖励。一次尝试控制在 30–60 秒；钓鱼不产出主线唯一物。
- **奇遇**：每张野外图至少 1 个固定线索加 1 个按存档种子变化的短事件。触发由地点、任务旗和一次性 ID 控制；奖励可为小故事、地图捷径、材料、NPC 关系或战斗，不用不可见纯概率卡结局。
- **NPC 关系**：先做 3 名贯穿多幕的人物，每人 3 段关系事件；礼物只是辅助，对话选择和协助任务提供主要进度。婚姻主题可在联机或后续叙事资料充分时另立功能；本期先把“建立关系、后续有人回应”做实。
- **赌场／投机娱乐**：若在终局加入，只用金币、设每日游戏内额度、不能成为最有效成长路径；在单机首发范围之外，不因口述原版存在就自动排期。

## 9. 美术重绘与界面规范

### 9.1 风格样板先于批量生产

统一目标为“清晰的像素奇幻地图＋较克制的木金／石蓝界面”。保留《远征》的界碑纹样和金色识别，原视频只提供布局和体验参照。先制作 **一张 480×800 同屏样板**：改造后的主街与左右店铺、四向主角、一名 NPC、岩龟、一只明雷、左上 HUD、任务提示、背包／对话浮层。再做同一角色的城战与野战两张战斗样板。样板在手机实机和 `shots/` 同视口对照通过后，才批量扩展。

资产规格作为样板期的待确认约束：地图以现有 48 px 格为逻辑基准；角色走动帧继续遵守 `WalkActor.gd` 的 128×128 帧结构和脚点，显示尺寸按地图比例统一；人物／NPC／怪物轮廓、阴影、受光方向和像素边缘一致。左右行走必须是侧身，不露出并排两只脚。导入用 nearest 过滤，禁止在同屏混放缩小的整张绘画背景与清晰小像素人。所有资产记来源、尺寸、帧顺序、锚点、使用图层和审核截图。

### 9.3 480×800 可读性与验收

地图默认只常驻左上角紧凑等级／血量／经验、右上地图、极少量底部动作；姓名等级贴主角头上但随相机缩放保持可读，NPC 名与功能图标按距离和遮挡优先级出现。世界名签建议 12–14 px，正文 15–17 px，按钮 16–18 px，标题 20–24 px；现有 `G.gd` 的 30／56 px 标题只给全屏章节页，不用在地图上。小字必须有足够对比和描边，触控热区建议至少 44×44 逻辑像素；遇到拥挤时隐藏次要标签，不把所有字号整体缩到看不清。角色、怪物、出口、任务方向在 480×800 实机一眼可辨。每次大批图像入库都产出主城、野外、战斗、背包四张同分辨率截图，进行叠层和颜色检查。

## 10. 工程落地、数据边界与旧档迁移

### 10.1 模块边界与数据

`G.gd` 当前同时持有角色、钱包、道具、成长和大量流程；新工作不得继续把具体任务、行情、地图 UI 堆进这个全局脚本。拆分为可独立测试的服务与表现：

```text
WorldSession（当前地图、脚点、出入口、安全点、怪物实例）
  ├─ WorldMapView / CityServiceLayer（地面、建筑、NPC、任务指引）
  ├─ EncounterDirector → BattleSim → BattleScene（唯一战斗结果）
  └─ WorldEvents（永久旗与短期事件）
PlayerProfile（名字、职业、等级、技能）
InventoryService（物品实例、仓库、装备事务）
QuestService（主线、支线、委托，消费统一世界事件）
EconomyService（价格、订单、合约，按游戏内时间结算）
CompanionService（宠物、坐骑、誓约）
SaveRepository（校验、迁移、备份、原子写盘）
```

现有 `BattleSim`、`RouteScene` 和历练模式仍可调用同一人物／物品配置，但各模式拥有自己的场景状态。`MapScene.gd` 中 `_mode == main_world/expedition` 的分支按切片逐步外提，不能一口气切断旧玩法。表建议分为 `world_regions.json`、`world_maps.json`（由现 `main_world_maps.json` 演进）、`world_spawns.json`、`story_quests.json`、`side_quests.json`、`dialogues.json`、`item_templates.json`、`loot_tables.json`、`craft_recipes.json`、`market_goods.json`、`market_events.json`、`encounters.json` 和 `art_manifest.json`；旧 `quests.json` 继续承接委托，旧 `maps.json`／`nodes.json` 继续承接历练。所有引用稳定 ID，不在进度里存中文显示名。

统一事件形状为 `{event_id, type, source_id, map_id, actor_id, payload, game_tick}`。任务、图鉴、地区变化和经济事件从同一事件读取；一次性事件 ID 写入已处理集合。奖励使用 `{transaction_id, costs, grants, world_flags}` 原子提交：背包已满、读档重试、战斗结果重复上报均只结算一次。随机过程持久化种子和计数器，经济尤其不能因加载而重抽。

### 10.2 旧档迁移与回退

1. 先收集 v1／v2／v3 与当前真实进度的匿名样本，冻结备份和截图。给 `SaveData.gd` 增加 `v3 → v4`，后续每次结构改动逐版迁移；迁移是纯函数、幂等，可对同一旧档重复运行得相同结果。
2. `account` 和 `player_name` 分开：昵称从旧 `player_name` 取，空值让玩家补填；账号不再覆盖头顶。`prog.main_world.map_id = lorin_wilds` 映射昭元边城，坐标按地图布局版本检查通路；旧地图不存在时进入边城安全点。
3. 旧装备的槽位强化／宝石／精炼转成对应三件初始装备实例；不能无损映射的投入转材料补偿并记迁移报告。材料数量、四币、已得宠物、六坐骑状态、图鉴、历练通关、建筑、委托均保留。新剧情不能因旧角色等级高而直接全跳过；提供“从第一幕游玩但等级缩放”或等值章节追赶，具体以旧档测试定。
4. 开始迁移前备份，结构校验通过后原子写盘；失败锁写并提供恢复原档入口。导入未来版本拒绝覆盖。保留最后 3 份自动备份及可手动导出档。
5. 迁移验收要比较迁移前后钱包、投入价值、收藏、建筑、任务状态；角色坐标不落障碍或刷怪点；当前历练中的局按原规则读完或安全折算，不静默删除。

### 10.3 可测试性与性能

内容构建检查所有任务前置、地图双向出口、安全点、刷怪与交互碰撞、掉落和商品 ID。自动回归覆盖新档首章、战斗胜／败／逃、奖励幂等、买卖与持仓、背包满、旧档迁移、历练旧流程。手测覆盖 480×800 安卓触控、连续跨图、骑乘／跟随、回城与读档。性能目标为目标安卓设备探索和普通战斗稳定至少 30 fps，场景切换与进包不卡死；目标机型和基准数据在样板阶段记录，不能凭编辑器帧率宣称达标。

## 12. 联机目标、开放顺序和不变的单机承诺

联机是已经完整可玩的单机世界的扩展，优先增加“相遇与合作”，再开放交易和竞争。单机档本地离线可继续游玩、可看到完整剧情结局；网络故障只影响联机功能。联机战斗、社交和市场不倒逼重写单机进度或改成持续在线游戏。

建议上线顺序：**L0 账号／在线角色与本地导入预览 → L1 城镇同屏与好友 → L2 双人／四人合作副本 → L3 受控交易与地区市场 → L4 帮派／团队活动 → L5 自愿竞技 → L6 公开版与持续运营**。每一步先小规模测试，前一步的存档、作弊和经济安全没有证明前不开放下一步。

## 13. 联机玩法逐模块设计

| 模块 | 玩家流程与规则 | 与单机内容的关系 |
|---|---|---|
| 账号与角色 | 玩家注册／登录后独立创建在线角色；本地角色可带入职业、外观选择和昵称建议，导入页逐项说明。线上角色由服务器权威保存 | 本地档原封可留；本地金币、装备、宠物战力和材料不进入在线库存或市场 |
| 城镇同屏 | 先在昭元边城与沉渊港显示同频道玩家，附近名片、表情、好友和组队邀请；拥挤时优先隐藏其他人的坐骑／宠物标签，限制同屏实体 | 单机 NPC、建筑和主线交互保持可用；别的玩家不能挡店门或任务点 |
| 合作探索／副本 | 2 人或 4 人自愿组队，队长选副本难度；每人独立任务判定和掉落，首通主线也可单人完成。掉线后允许重连，超时让 AI 接管或继续单人缩放 | 用现有四职业互补、宠物协战与 4 副本机制；主线战斗数值随人数受控，不简单倍增血量 |
| 共同首领 | 周期性地区事件给多队共享目标，按个人参与与完成目标领有上限的奖励，不抢最后一击 | 可回访地图但不把所有刷点改为多人争怪 |
| 玩家交易／寄售 | 仅可交易明确白名单的装备和商品；任务物、首通奖励、绑定强化件禁止交易。寄售有挂单费、有效期、价格上下限与日志 | 单机商品价格机制可作为 NPC 基础价，玩家市场独立统计；先模拟再开放跨玩家货币流动 |
| 帮派／社交 | 建立帮派、帮派据点外观、共同建设与协作任务；不把核心伤害加成锁到帮派等级 | 单机据点状态保留为个人家园；帮派层是额外场所 |
| 竞技／PK | 演武场正式交付 1v1、2v2、3v3，三种模式均有好友切磋与独立排位，并做等效战力段和观战回放。野外默认安全，若将来试自由 PK，必须另开双方同意的区域和无装备掉落模式 | 不复制原作全图袭击与随机掉神装；不妨碍单机式探索和找 NPC |
| 宏观行情 | 玩家订单影响服务器市场只在有限区间内变化，NPC 保底买卖和反操纵熔断保持材料可得 | 单机行情依旧按本地游戏日和世界事件运行，不能让服务器价格回写离线档 |

## 14. 联机技术与运营边界

- 服务器对在线角色等级、物品、金币、战斗结果、任务旗、市场订单和交易是权威来源。客户端上传意图和输入，不上传“我获得了某装备／击败了首领”的自报结果。战斗沿用确定性的 `BattleSim` 规则定义，但在线由服务端执行或验证，版本号与回放日志可追溯。
- 内容表用稳定 ID 和版本哈希；线上客户端／服务端版本不一致时拒绝写入并提示更新。本地单机存档和线上角色有不同命名空间、库存和经济台账，避免复制档、改系统时间或离线回档把物资注入联机。
- 联机角色状态分为私有进度、队伍副本、频道公共地图与市场。公共图只同步位置、动作、外观与必要表情；其他玩家的隐私数据与完整背包不广播。兴趣区域和实体数量上限控制 480×800 小屏密度。
- 交易实行双边原子提交、幂等订单 ID、货币与物品台账、可审计日志；失败可回滚，发货和收款不能只成功一边。市场、礼物、帮派仓库在防复制和异常交易测试通过前不开放。
- 网络断线后单机可继续，但在线组队副本只从服务端检查点重连；不能把离线期间的战利品在重连时合并进在线角色。服务停运或长期维护时玩家的离线战役依然完整。
- 运营设置基本举报、屏蔽、聊天节流和名字审核；联机是本地单机发布验收后的独立项目，不在单机 S1–S7 偷塞在线依赖或公共经济门槛。

### 联机验收顺序

| 阶段 | 必须证明的结果 |
|---|---|
| L0 | 本地档导入预览与在线角色分离，昵称冲突和可带入的外观／身份项目透明；重复导入不会生成第二份线上资源 |
| L1 | 城镇移动可见、好友与组队邀请可用；人多时 NPC 与路仍能看清、碰到，离线照常玩 |
| L2 | 合作副本在掉线／重连／成员退出后仍可结算，各人任务与掉落准确，单人首通路径不受损 |
| L3 | 交易／寄售没有复制、丢单、负余额或物品洗白；有审计和异常关闭开关 |
| L4–L5 | 帮派活动与自愿竞技可独立停用；1v1、2v2、3v3 各能匹配、结算和独立记分，不影响世界主线、角色养成和单机档 |

## 15. 以后如何按本方案实施

每个开发任务必须标明本方案的章节、阶段、玩家可见结果、涉及表与场景、旧档处理、截图／回归验收。若发现新参考资料，可更新“依据与设计值”记录；不能仅凭一张图或口述数值覆盖已完成的单机规则。任何新增系统先回答：它在哪张地图由谁提供、玩家做什么、得到什么、与既有系统如何交换资源、旧档怎么迁移、如何证明它没有把主线变成菜单操作。若回答不清楚，先做纵向原型而不批量生产资产。

首次执行任务应是 **S0 同屏风格样板和 S1 的昭元边城纵切**：以现有 `lorin_wilds` 为唯一主城，改正出生与昵称，重排白路左右建筑及 NPC，移动堵路怪点，再接一张野外、一个任务、一个怪和一次可返回的战斗。这个切片是整套单机重构的第一条可玩的验证链。
