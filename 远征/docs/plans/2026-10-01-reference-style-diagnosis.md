# 参考游戏画面风格偏差诊断（2026-10-01）

结论：偏差存在，且是整套视觉语言与制作流程的问题。当前布局能运行、功能回归通过，不能证明画面风格符合参考。本文是诊断记录，未把现有美术或 S0/S7 判为完成。

## 问题与根因

| 优先级 | 参考画面可观察特征 | 当前偏差 | 实现根因 |
|---|---|---|---|
| P0 | 地表、人物、小建筑有相近的色阶、轮廓硬度和阴影语言 | 主角偏大头短身、强金属高光；NPC 较修长；建筑是高细节等距楼；雪地与设施又是另一套简化画法。同屏像多批资源拼接 | 多批素材按功能入库，没有以原生像素密度、轮廓、色板和光向统一审核；各自缩放只能调整大小 |
| P0 | 地表以较大色块组织，纹理服务于人物和建筑；边界有地貌过渡 | 草地、雪地纹理碎，视觉噪声高；矿轨、木栈道、灯和部分房屋边界平直，人物像贴在程序图形上 | `ThirdActGround._draw()` 直接绘制长矩形、等距重复横线与纯色多边形；`PortGround` 同类。主城另走整张草地图缩放，与48px地砖并存 |
| P1 | 人物与NPC在一套比例关系中，头身、脚点、阴影和地图物件能一起读 | 主角、NPC、普通怪的体型与细节密度跳跃；较大的建筑/怪物容易压过主角；阴影形状和浓度不一致 | 主角配置0.54倍、NPC0.72倍、建筑0.75倍，再叠相机1.15倍；各源图的可见内容与原生像素不同。倍率不相同本身不是错误，但缺少统一最终屏幕比例的依据 |
| P1 | 战斗切入同地区色调的专用地表，留出对阵和指令空间 | 直接继承探索地图的轨道/道路/设施构图，再摆敌我和预兆；探索道路横穿战斗主体 | `classic_inline` 下 `BattleScene._build_background()` 直接返回。复用了地图，而未制作独立的战斗构图 |
| P1 | 原UI也是纸色/木金，但主要是硬边框、角饰、简洁列表与高对比选中行 | 当前圆角卡片、软投影、胶囊金按钮、半透明条和圆图标混用，像现代触屏面板；只用相近颜色无法匹配风格 | `G.parchment_box/gold_button/ghost_button` 大量使用 `StyleBoxFlat` 的圆角和软阴影，战斗又采用另一套方角样式 |
| P1 | 世界画面之间的亮度、材质和角色位置有连续性 | 明亮草地/雪地切到深褐绘画营帐，角色变成巨大展示立绘，视觉体验断裂 | `image/background/home.png` 及整备页展示与主世界没有共同样板；同一套按钮跨画面使用不能解决背景语言不同 |

最近邻过滤已经开启；它只改变采样方式，不能把高分辨率插画、简化几何图形和不同规格精灵变成同一套像素美术。当前非整数缩放与相机缩放还使各素材的屏幕像素节奏难以统一；不宜仅把倍率改成整数就宣告修复。

## 为什么问题持续扩大

总方案 §9.1 原本要求先制作主街同屏样板及城战/野战样板，手机和同视口对照通过后再扩展。P01 实际主要校准了道路、碰撞、脚点、字号、名签、安全边距与地区 tint；大量样板值保留“现状不变”。这些是可用性底线，未建立可被后续资产复用的最终美术样板。

`2026-09-28-ui-art-review.md` 已明确指出多套风格拼接，后续记录又将逐张重绘归入 R-08 延后。继续生产第二、第三幕时，程序识别层承担了最终地图的视觉面积，偏差随内容规模扩大。此前“视觉样板完成”的表述需要收紧为“布局与可用性规范已落地，美术风格仍未验收”。

另一个方向差异：总方案 §9.1 写“原视频只提供布局和体验参照”，这不足以满足用户现在明确要求的画面风格接近。后续应以参考游戏的地表色块、精灵比例、轮廓/阴影、建筑透视与硬边UI作为风格基准，同时保留《远征》角色身份、世界内容和已有结构。

## 修正顺序

1. 先冻结一小段昭元边城样板：同一镜头下主角、一名NPC、一只怪、两栋建筑、草地/石路及最少HUD。对照参考确认头身、屏幕高度、地表噪声、光向、阴影和色板，再决定资源规格；128×128帧容器或48px逻辑格可保留，不强行作为原生美术像素尺寸。
2. 同时出一张同地区专用战斗样板和一个背包/对话浮层，让三种界面共享轮廓、颜色和字体层级。触控热区保留，不照搬数字键盘或聊天遮挡。
3. 将程序道路/设施保留为布局或状态逻辑，用合格地砖、边缘、转角、木板、房屋与设施像素资源替换视觉层；保留碰撞、出口、剧情旗和存档ID。
4. 按主城→第一幕野外/战斗→港口→第三幕扩展。每批做同屏对照，实际渲染通过后再铺开。

当前装备保底、存档与任务工作不因此作废；它们的功能证据与美术验收分开保留。本次未修改游戏运行代码或批量替换素材。
