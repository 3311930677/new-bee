# 《远征》UI 方向复盘与第二轮规则

依据：用户提供的七张游戏截图，以及第一轮营帐、养成、技能书的实际引擎截图。本文修正第一轮的视觉方向。第二轮已落实营帐、养成、技能书，并接入路牌及 28 种世界/剧情设施设计；实景与验证记录见 [第二轮交付记录](2026-10-05-craft-ui-delivery.md)。

## 1. 第一轮为什么仍不好看

第一轮改善了可读性、导航和状态反馈，但把精致过度收窄为统一、规整、少装饰。结果是功能更清楚，游戏的角色吸引力、场景气氛和成长欲望反而没有得到强化。

- 营帐：小角色站在暗淡背景中；整备台、活动按钮、出发按钮自上而下占据主要位置。场景没有明确的灯光焦点和用于构图的前景，入口图标的细节弱于角色。玩家首先看见几条功能区，而不是一个值得停留的营地。
- 养成：纸面几乎覆盖全屏，角色只剩摘要里的小头像。六行信息的视觉重量相近，缺少装备、同伴、成长路线的可视展示，接近设置列表。
- 技能书：大色块、文字说明、系数对比占主导；简易几何招式图不足以表达招式威力。升级收益虽清楚，玩家仍难以想象这个技能在战斗中的表现。
- 材质：角色、背景、原生器物图标和按钮的细节密度不匹配；细线、规整边距和字体统一无法弥补这种落差。
- 验收：功能回归证明页面能正常使用，不能证明画面已经精致。需要单独看实际画面的构图、素材完成度和风格一致性。

## 2. 七张参考图可借鉴的部分

| 参考 | 可见的设计选择 | 对《远征》的启发 |
| --- | --- | --- |
| 图 1、2、6：角色大厅 | 角色是大主体，资源与功能沿边缘组织；背景与人物共同构图；出战动作具有突出形状与颜色 | 给角色和营地展示空间，把高频导航移到稳定边缘位置，强化出发动作 |
| 图 3：角色养成 | 装备槽围绕角色分布，底部暗区承载属性；圆弧和装饰实际参与人物构图 | 让装备、角色和成长信息在同一视野中发生关联，避免养成总览只有六行目录 |
| 图 4：卡牌收藏 | 相同组件反复使用；卡面是主要内容；稀有度边框有意义；选中卡突出并就地展开动作 | 宫格适合收藏比较；卡面、品质、选中态和操作层级必须精心设计 |
| 图 5：对战大厅 | 中央竞技场是具有体积与灯光的展示物；边缘快捷入口、底部主动作形成层级 | 像素营地也可以以真实场景物件为中心，入口不能只靠一排抽象小图标 |
| 图 7：技能/卡牌详情 | 角色动作突破面板边缘，实战演示占据大块空间，属性和升级动作次之 | 招式效果需要可视展示，说明、等级和成本围绕效果组织 |

这些截图风格不同。它们可共同借鉴的部分是主体、层级、素材完成度和一致的组件语言；不应同时拼入科幻斜板、卡通厚按钮与复古金边。仅凭静态截图也不能判断动画和交互质量。

## 3. 替换第一轮中的过度限制

- 不再一概限制宫格、圆角、多色、装饰或框的层数。按页面任务选择结构：收藏允许宫格，品质允许多色，详情允许明确的前后层次。
- 不再强制所有正文左对齐、所有内容使用同一层纸材。对齐服务于内容关系，材质服务于页面身份。
- 账册可以作为任务或记录页的局部表达，不能成为营帐、角色成长和技能展示的通用模板。
- 金属边、宝石、徽章和光效可以使用，但需要形成统一的形状、光源、细节和状态规则。
- 具名技能导航有必要；分页点也可以保留在真正存在多页演示的区域。不能仅因看起来常见就禁用某种组件。
- 保留现有可点击面积、返回行为、真实余额、升级收益、禁用反馈和存档保护规则。

## 4. 第二轮统一方向

精致像素奇幻 RPG。角色与世界是核心展示，控件采用与像素素材相容的清晰轮廓和受控层次。使用有限的金属、皮革和职业能量色，材质通过少量准确高光、暗面和边缘表现。

每页先回答三个问题：玩家首先看什么、随后判断什么、最终按哪里。标题不能自动成为视觉中心，页面也不能因留出空白就被判定为有设计感。

### 素材规则

- 保留现有战斗角色和动画。现有小尺寸精灵不可直接模糊放大到参考立绘的尺度。
- 大主体有两种可行形式：为展示单独制作的高质量像素肖像；或围绕现有角色构图的完整像素营地场景。两者先做实际尺寸样张，按观感选择。
- 同组图标统一画布、物体占比、轮廓粗细、光源和细节密度。原生几何图示可以做布局占位，不能充当最终高质量技能或入口美术。
- 场景、角色、图标、按钮一起审视。任何一组素材明显更粗糙，都需要补齐，不能只改字体和色值。
- 保持像素清晰度，使用适合素材的缩放方式；前景、主体、背景的清晰度差异必须有明确的景深或视觉层级目的。

### 页面规则

| 页面 | 展示主体 | 主要结构 | 主动作 |
| --- | --- | --- | --- |
| 营帐 | 角色与营地场景 | 顶部紧凑资源；边缘少量快捷入口；底部稳定导航；任务显示当前目标 | 继续旅程：强化轮廓、亮度和与场景的联系 |
| 养成 | 当前角色及其装备/成长 | 角色展示与装备、天赋、技能的摘要关联；宠物、坐骑、称号为次级分类；保留进入各子页的路径 | 依当前分类显示明确的整备或提升入口，避免六种入口同等突出 |
| 技能书 | 当前招式的动作或效果 | 紧凑技能选择；大块招式展示；等级、收益与成本在操作附近 | 升级：收益可读，成功后有清晰反馈 |

招式展示优先复用实际战斗效果；必要时制作专用演示。伤害系数仍需保留，但不能独自承担技能的吸引力。预览不得影响真实战斗、消耗玩家资源或改动存档。

## 5. 落地顺序与视觉验收

1. 先完成营帐一屏的构图样张，使用实际分辨率、实际文字和达到目标完成度的关键素材。不能把粗略线框或漂亮但无法落地的概念图当成成品预览。
2. 对照本次参考检查：主体是否鲜明；主动作是否一眼可见；入口是否形成主次；材质和图标是否一致；画面是否仍像纵向功能清单。
3. 样张形成明确方向后，落实营帐的真实引擎版本；再使用同一套组件与美术规则制作养成、技能书。不要一口气将全部页面换成另一套通用模板。
4. 逐页检查 480×800、480×1067 与四职业。关注头像/主体、文字密度、资源长度、窄屏操作和背景可读性；功能检查与视觉检查分别记录。

本轮完成的标准是实际游戏画面具有明确主体、可辨主次和统一素材质量。测试通过、边距统一、色值统一只能作为基础条件。
