## 先定取舍

**先做有辨识度的关卡和可解释的商路，再试轻量异步联网；玩家互买互卖暂不列入首发。** 《远征》的独特卖点应是“走过一条危险的路，留下后来人能使用的路”。纯粹增加刷怪房、每日收菜或拍卖行，容易让这个主题被资源循环盖住。联机交易有吸引力，但它的真正前置工作是可信账号、可信物品和服务器结算，不是一张买卖界面。

| 候选 | 玩家能得到什么 | 对当前版本的适配 | 决定 |
|---|---|---|---|
| 三座旧副本改造成三种机关冒险 | 主线高潮不再只是进门打首领 | 已有地图入口、首领和任务 ID，返工最少 | **优先做**，沿用既定三房方案 |
| 通关后“失联邮路”可重玩关卡 | 10 分钟左右完成一次调查、护路、送达和世界反馈 | 能复用三城 NPC、地图、委托和船运 | **优先做一条纵切** |
| 单机商路事件与订单 | s20/s28 的供货选择影响路线和收益 | 已有 5 市场、4 货物、两条船运及游戏日 | **第二批**，先把现货交易变成有行动的委托 |
| 异步“同行路标/共筑驿站” | 看见其他玩家也在维护道路，仍可单人玩 | 无实时战斗同步，服务端范围可控 | **有稳定玩家群后试验** |
| 玩家自由寄售与互买 | 有社交经济与长期流通 | 本地存档里的金币、装备、掉落无法让服务器直接信任 | **条件性后续工程**，先通过安全和运营门槛 |

## 一、关卡要有选择、反证和后果

旧副本扩建和新关卡统一采用“**读懂环境 → 做一个有代价但可补救的选择 → 战斗验证 → 回城看到结果**”。谜题信息必须在地图上可复看，色觉或听觉障碍可用文字/符号等价提示；失败退回安全点，不能靠一次不可重复操作卡主线。战斗仍保持角色左侧接近打击、怪物右侧和清楚的预兆，机关提供破绽而非强制属性门槛。

| 关卡 | 特色玩法与具体场面 | 选择和重玩价值 | 与现有内容的关系 |
|---|---|---|---|
| **失声碑窟：借声辨路** | 三处裂缝传来相似但不同的回声；玩家拿青姨拓片比对缺口与节拍，旋转两枚碑座让旧声回到碑面。错位会出现可读反证和一场守影遭遇。 | 先稳定碑座可让首领的蓄力预兆更清楚；首通后可挑战“少看一张拓片”，奖励图志注记/外观材料。 | 扩建 `stele_cavern`，保留 s09–s10、碑灵和原碑片奖励。 |
| **退潮水闸：两道水线** | 玩家先看水痕和港务记录，再在两闸之间决定开放栈桥或保护货箱；水位变化当场改可走区域，所有状态由游戏进度驱动。 | 可绕路救回未优先处理的一边；重玩尝试同时保住两箱货，获得港口陈设，不多发潮核。 | 扩建 `tidal_gate`，呼应 s16–s20 和两条供货路线。 |
| **裂谷矿脉：让路的矿车** | 玩家先从翻车记录判断风向，转两座风轮和道岔，让矿车避开烟道并带矿工从安全侧撤离。错线生成烟雾/敌群，可回开关修正。 | 铁料与药包谁先行会改变驿站一句话与停靠位置，另一批最终抵达；重玩可选无补给点挑战。 | 扩建 `rift_mine_vault`，保留 s24–s25、原械卫和首通凭证。 |

三房改造的细规格、撤退与存档规则沿用[后续玩法第三节](2026-10-03-next-gameplay-design.md#三先补三座旧副本同为三房机关各不相同)。这三座算**当前主线打磨**，不要再统计成三张全新世界地图。

### 新的通关后样板：“失联邮路”

接在 s36 和现有“三城的回信”之后，由霜关驿的归路邮箱接单；它是一条反复游玩的**路况关卡**，不是追加 s37。玩家带一袋写给某个具体人的信、少量补给与一张不完整路图出发。每局约 8–12 分钟是策划目标，须由真实游玩校准。

1. **开局见人。** 信封只说明收件人住哪片区域和为何迟迟没收到信；不泄露后面的危险。玩家在“快走的谷道 / 稳妥的旧驿路”中选一条，界面明确显示预计危险与补给差异。
2. **中段辨路。** 路标可能被风雪、潮水或兽迹遮住。玩家可观察两处地形、请伙伴闻踪、或到驿亭花少量货物换消息；始终有不依赖宠物、坐骑或交易的观察法。
3. **一次紧张遭遇。** 有时是战斗护送，有时是稳住桥板或安置受伤信使；随机种子只换遇到的事件组合，不把完整任务交给概率。
4. **送达与回响。** 玩家亲手把信给人，读一小段回应；回城邮箱多一封可回看的回信，图志记下“这条路后来怎么样”。首次完成三种地区变体各有固定故事，之后重玩以普通材料、地区信任和不同路况为主。

纵切先只做**昭元古道→沉渊港的一条固定路线、两种路况、两种非战斗解法**。通过后扩“沉渊港→霜关”和“霜关→昭元”两个变体。每局保存 `posting_id / route_seed / current_segment / observed_clues / choice / delivery_state / reward_tx`；中断后能原样继续或主动放弃。签收和领奖各只一次，重复点击、满包、写盘失败不能复制信件或材料。按旧档已完成 s36 与现有邮路 flag 解锁，不覆盖已发的六条托付奖励。

为了让它不沦为最赚钱的刷图点：第一次见到每名收件人的故事是固定且可回看；之后每游戏日最多领一次常规报酬，可继续无奖励重玩练路线。收益控制在同期普通世界委托与数场野外战之间，经四职业实测锁数值。无现实日期清空进行中关卡。

## 二、把交易变成“路和人的选择”

现有 `data/economy.json` 已有谷、盐、药草、铁料四种货、五个市场、六种工作和两条船运；`G.economy_trade()` 使用本地 `RewardLedger` 与本地写盘，价格随经济游戏日和 s11/s20/s28 事件变化。因此第一步应在原交易面板上加**有来源的货运委托和可选路障处理**，保留原买卖入口，而非重做一套“玩家商店”。

**样板订单：霜关缺药。** 港口药草便宜，但赤砂商路前段有风沙。玩家接单前能看到购货价、运费、截止的游戏日、预计净报酬与最大损失。可以买药草走较短的危险路；也可以先做“驿亭修篷”小关卡，让运输更稳、利润较少。s20 的港口选择影响采购价，s28 的霜关选择影响收货台词和短期需求；任何组合都可按正常价格完成订单。抵达时驿站药架有货、矿工对白改变，账本能说明每笔金币和货物的来去。

第二张样板订单做**断碑坡修桥铁料**，让玩家看到重量和坐骑载货差异，但步行有替代路。两张跑通后再扩“期限内送到 / 延期补货 / 放弃退保证金的一部分”等合约；与[原保价/延期设计](2026-10-03-next-gameplay-design.md#63-保价与延期交割给商路增加可预判的风险)共用同一 `economy.day`，不看系统日历。不得让玩家通过同日倒买倒卖或反复接单无限刷金；必须覆盖跨城传送、读档、重复领款和写盘故障。

交易界面先做三件小改动：每个价格旁写“为什么变了”；买卖确认页给总成本、背包重量与收货余量；订单页直接关联到地图上的货物、路障和收件人。这样即使永远不上线，商路也会比纯数字套利更有趣。

## 三、联网先试“有人同行”，不急着把经济上云

### 第一种在线功能：同行路标

玩家完成一段真实的地图路程后，在安全驿点可留**预设印章**，例如“北侧兽影”“南桥可绕”“这里有补给”。每个印章绑定地图 ID、可验证的路口、版本和有效期；其他玩家只会看到少量当前有效路标。没有自由文字、图片、私信、玩家定位或战斗加成。断网时继续显示 NPC 记下的固定路标，单机主线和关卡照常运行。

路标不是标准答案：其他玩家提示标“行旅传闻”，任务必需线索仍由世界实体和图志提供；玩家可关闭路标、反馈误导或屏蔽来源。首轮只在“失联邮路”固定路线试，不全图铺开。成功标准是玩家真的用它来理解路况，而不是只增加点击量。

### 第二种在线功能：共筑驿站

玩家各自完成一项短程邮路或维修任务，可以把一次“守路记录”提交到同一驿站。累计值只点亮公共风灯、横幅和口述册等**共同场景外观**；个人奖励只由个人完成事实发放，贡献被拒或网络断开也不影响任务报酬。每账号/周期贡献有上限，服务器可撤回异常记录。不开聊天、不排榜、不过期清空玩家个人进度，也不让别人不参与就少拿强力装备。

技术边界：这种异步功能可用 Godot 客户端经 HTTPS 调用服务端 API；`HTTPRequest` 支持 HTTP(S)，Android 导出需启用网络权限。[Godot 官方 HTTPRequest 文档](https://docs.godotengine.org/en/stable/classes/class_httprequest.html) 实时同屏战斗是另一种工程；Godot 的多人 API 方便同步，但官方明确提醒它**不会自动让关键状态安全**，重要判定应由服务器掌握。[Godot 官方多人文档](https://docs.godotengine.org/en/4.7/tutorials/networking/high_level_multiplayer.html)

如果上线任何公开玩家信息或交互，要按发布平台的现行规则处理账号、举报和屏蔽。Google Play 对用户可见内容有持续管理、举报等要求，具体实现需随上线平台复核。[Google Play 用户生成内容政策](https://support.google.com/googleplay/android-developer/answer/9876937?hl=en)

## 四、玩家互买互卖的准入门槛

目前的金币、普通材料、装备实例和战斗掉落都以玩家本地档为准；单机账本能防止正常流程重复结算，**不能证明上传来的存档未被改过**。若服务器直接接受“我有 999 个铁料”和“我有 100 万金币”，市场会失去可信供应与价格。Godot 官方也提醒，持久多人游戏应把客户端输入视为不可信、关键库存与结算放在服务端。[Godot 官方多人安全设计](https://docs.godotengine.org/en/4.7/tutorials/networking/high_level_multiplayer.html)

因此只有满足下列条件才立项**限定物品的异步寄售**：

1. 有账号绑定、设备换机找回、停服/离线时的清楚提示；单机故事档继续独立使用。玩家明确知道哪些资产属本地，哪些属在线商会。
2. 可交易物与交易货币由服务器发行和持有，具备唯一批次 ID 与来源账本。旧本地档中的金币、四类现货、宠物、装备、首通剧情物**不能直接上架**；如未来确需迁移，必须先设计一次性可信迁移与审计，不能读取本地数量就发等量在线资产。
3. 第一版只上架预设 ID 的普通材料/外观图纸，固定价格区间、数量上限、上架期限和手续费；不开放拍卖、以物易物、抽取货币、现金兑换、自由标题或私信。主线材料和影响战斗公平的关键装备不可交易。
4. 上架时服务端把物品锁入托管；购买时在**同一数据库事务**中核库存、扣买方在线币、给买方物品、给卖方收入并关闭货单。取消/到期原路退货；每请求有幂等键和状态机，重复购买、双人同时抢同单、断线重试、付款成功回包丢失都只能产生一笔成交。服务端负责身份鉴权、限流和对账。[OWASP REST 安全建议](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)、[OWASP 竞争条件说明](https://community.owasp.org/pages/vulnerabilities/race_conditions)
5. 先在小范围封闭测试里证明双端账本对得上、异常交易可冻结/回滚、日志能追溯物品批次，且有人负责投诉与运营；再决定是否给全体玩家开市。

如果这些条件做不到，保留单机商路和轻量异步社交就是完整产品方案，**不需要**为了“有联网”牺牲单机可玩性。不能把 `RewardLedger` 的本地事务 ID 误当成跨设备的服务器可信凭证。

## 五、排期和可验收结果

| 批次 | 交付范围 | 做完才进入下一批的证据 |
|---|---|---|
| A：现有 M0/M1 内 | 先稳存档与奖励；失声碑窟三房纵切，退潮水闸、裂谷矿脉依次扩建 | 真实输入可解机关、首领、撤退、重进；四职业不会因解谜卡主线，原首通物只给一次 |
| B：M2 内 | “失联邮路”一条固定纵切、三城各一项世界委托、图志路况页 | 路线选择有可见风险与不同处理方法，8–12 分钟目标经玩家测试；第二进程恢复/签收/领奖去重 |
| C：M3 内 | 两张有地图事件的商路订单，价格成因、保证金/运费、地区对白；随后扩其他订单 | 所有路线可交付，最坏损失可提前看；模拟反复买卖不无限套利，断档不吞货 |
| D：单机内容稳定后 | 小范围同行路标，再评估共筑驿站 | 断网完整可玩；提示可关；服务端拒绝非法地图/过量提交；玩家反馈证明路标有用 |
| E：有持续运营能力后 | 只在准入门槛全过时试在线寄售 | 可信资产来源、双端原子结算、并发/断线/重试/回档演练、投诉处理与下架能力齐备 |

这份方案的最高优先级是**特色关卡纵切 + 失联邮路 + 具体货运**。它们即使没有服务器，也会让战斗、地图、经济和剧情真正连起来。联网是之后的增益层；玩家自由交易留在明确的准入门槛后，而不是现在给现有单机背包直接接一个交易按钮。
