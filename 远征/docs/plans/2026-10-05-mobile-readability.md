# 手机界面清晰度规则与本轮交付

## 设计规则

- 按 480 逻辑像素宽的真实游戏画面验收，另检查 800 与 1067 两种高度；素材原图漂亮不算通过。
- 常用操作只用一个主体轮廓、少量大色块和一处高光。图标实际可见主体约 36–42 像素，禁止细刻纹、碎光和依赖微小细节辨认的装饰。
- 像素角色保持像素采样；缩小的图标、文字各自采用适合的过滤。禁止把文字画进图片。
- 文字使用原生字体，不叠黑色双层阴影。正文使用黑体，书卷风字体只用于大标题；旅程主按钮已改为清晰的粗黑体。字号原则上正文 16–18，辅助信息不得小于 14。
- 战斗地面保持开放空间，角色周围优先清晰。远景负责环境身份，背景细节不得与角色、血条和菜单争抢注意力。
- 四个战斗操作固定在下缘，每个触控区 88×86，角色移动不带动按钮。菜单行高至少 44，显示真实能量与冷却。
- 交互状态由程序表达：冷却、能量不足、不可撤退和二次确认不依赖贴图上的小字。

## 本轮实现

1. 攻击 / 技能 / 道具 / 撤退：新四格图标图集，简洁深青底座、统一暗金边、大图标在上、文字在下。技能选择仍由原有解锁技能驱动，不新增虚假的技能或改变战斗数值。
2. 林地同图战斗：新林间空地背景，避开后排站位，匹配单敌与多敌布局。其它地区采用现有地区战斗背景，缺少素材时仍保留原地表回退。
3. 技能菜单：能量和冷却实时刷新；不足时说明原因并保留菜单，不再无声关闭。
4. 营帐文字：移除投影，文字采用平滑采样；继续旅程改用粗黑体，减少缩小后的细碎笔画。
5. 活动中心：营帐独立入口、空状态、配置列表、可滚动详情与返回行为。目前没有开放活动，也没有虚构奖励或领取操作。
6. 导出包含已被现有角色与地图引用的 style_review_20261005 中正式使用的素材，避免运行时依赖被旧排除规则漏掉。

## 验证

- 截图工具：tools/CapturePhoneUI.tscn；截图位于 shots/phone_ui_20261005，覆盖营帐、活动空状态、测试配置的列表和长详情、单敌/多敌战斗、技能与道具菜单。
- 测试活动只在截图/回归工具中注入。正式 data/activities.json 的 events 为空。
- 新增回归检查：实际活动入口/返回、活动时间边界、隐藏与重复配置、长详情、只读资源；战斗图标尺寸、能量不足反馈与实时能量读数。
- 测试与截图的用户目录完全隔离，未写真实玩家存档。

生成模式：内置 imagegen。图片只复制到项目，未使用外部脚本改画；实际图标取图集区域并由游戏缩放。完整提示与资产路径见 2026-10-05-mobile-art-manifest.json。
